### 参考资料与发布位置
+ 开始制作前，先阅读以下资料，并以其当前内容为准：
    + `#workspace/app/DESIGN.md`：站内页面的视觉语言、主题与布局基线
    + `#workspace/app/API.md`：可调用的Integration API、页面URL上下文约定与静态资源映射规则
+ `#workspace/app/API.md`、`#workspace/app/CANVAS.md`、`#workspace/app/DESIGN.md` 是受保护的只读参考资料。不得新增、修改、覆盖、移动或删除这三个文件；它们由 Integration 定期恢复为创建当前 Agent 时复制的发布版本。
+ 迷你应用及其资源必须放在当前Agent的`app/`目录中，站内静态访问地址为：
```text
#origin/mapping/#agentId/<相对路径>
```
+ 例如，`app/index.html` 对应：
```text
#origin/mapping/#agentId/index.html
```
+ 新建页面时，优先使用用户指定的文件名，未指定且`app/`为空时，可使用`index.html`
+ 修改已有页面前，先检查现有文件与资源引用，不要覆盖、移动或删除无关的用户文件
+ 每个迷你应用页面都必须在同目录创建并维护与HTML同名的`<页面名>_readme.md`。更新页面时必须同步更新README，不得静默删除或改写其中仍然有效的功能说明
+ 资源路径必须保持在`app/`内，使用相对路径，并避免`..`等会跳出静态根目录的写法
+ `app/`目录及相对资源路径限制仅适用于迷你应用自身的HTML、CSS、JavaScript和静态素材发布，不适用于用户选择的业务数据、CLI输入输出或待分析文件。读取业务数据时，不得将路径人为限制在`app/`或当前Agent workspace内，应允许使用当前运行进程具有操作系统访问权限的任意本机目录和文件路径
+ 向当前Agent workspace之外的路径写入、覆盖、删除或移动数据前，必须在迷你应用内明确展示操作类型、目标绝对路径、影响范围及覆盖或删除风险，并要求用户逐次确认后才能执行，确认后仍须防止重复提交。实际执行仍仅能使用API文档明确支持、且当前运行环境有权限的接口，不支持时必须报告受阻，不得宣称已写入

### 制作流程
+ 1.明确应用目标、核心交互、所需数据、目标文件路径，以及是否有参考页面或素材
+ 2.阅读DESIGN与API文档，若项目中已有目标页面，先理解其结构和资源
+ 3.先完成可用的核心流程，再补充视觉细节、状态反馈和动效
+ 4.对涉及Integration的功能，仅使用API文档明确提供的接口，优先通过API获取或提交数据，不额外启动服务
+ 5.当核心流程需要执行命令或代码，且API文档提供受支持的执行接口时，页面必须直接执行，并展示可视化结果、执行状态和错误信息。不得仅生成命令或代码文本要求用户手动执行。若没有受支持接口，必须明确报告执行能力受阻，不得将命令生成或复制页面作为执行型需求的交付。仍须遵守页面内确认、权限和副作用限制。
+ 6.可视化结果应优先展示生成文件或数据的预览、访问入口和关键结构化结果。无可预览产物时，展示退出状态、关键输出、可滚动的脱敏日志和可恢复操作。仅展示命令文本不构成结果展示
+ 7.直接打开完整迷你应用页面，并在与实际iframe相同的视口尺寸下验证首屏、核心交互、窄宽度布局、加载态、空态和错误态，不得以宿主页面或iframe作为验证对象
+ 8.编写或更新README。README是供其他用户复建同等功能的实施指南，不是开发过程记录。必须包含：应用目标、使用场景和边界。前置条件、所需权限、依赖和配置项。页面与资源文件清单及入口文件。核心用户流程、字段说明、输入来源、输出结果和副作用。已使用的API或CLI的请求方式、必要参数、响应处理和失败恢复。文件或目录选择、绝对路径和跨平台行为。深浅主题、响应式和无障碍约束。验证步骤、成功与失败预期、已知限制和风险。内容必须足以让不了解当前实现的用户在不读取原页面源码的情况下复建同等功能，但不得写入密钥、令牌、Cookie、个人路径或其他敏感信息
+ 9.最终返回页面的站内访问URL，并简述已实现的功能与验证结果

### 页面与交互要求
+ 没有参考页面时，采用紧凑、聚焦任务的布局：突出主要操作，避免无意义的大标题、空白和装饰区
+ 有参考页面或用户提供的设计稿时，高保真还原其可见层级、布局、字体比例、颜色、间距、状态和交互。只使用用户提供或明确允许使用的素材
+ 保持单一清晰的主操作，次要操作不应抢占视觉层级
+ 为加载中、无数据、错误和成功状态提供清晰反馈。失败信息应说明可恢复的下一步，例如"重试"
+ 表单控件必须有可见标签或等效的无障碍名称，支持键盘操作、焦点可见与合理的Tab顺序
+ 所有需要选择本机文件或目录的字段必须同时提供跨Windows/macOS的系统选择器和可编辑的路径文本框。文件、目录、多选与类型过滤须与字段语义一致。选择器应优先使用API文档明确支持的统一本机接口。标准浏览器文件控件可作为选择入口，但不得把受浏览器保护的`value`当作绝对路径。若后续API或CLI必须接收绝对路径，必须通过受支持的本机选择接口回填真实路径。不能可靠取得时，保留手填路径并明确说明能力限制。选择取消不是错误，且不得清空用户已填写的路径。除非用户明确要求上传，选择文件不得隐式上传、复制或写入Agent工作目录
+ 用户输入、API响应和URL参数均是不可信数据。展示文本时使用安全的DOM写入方式，不将未净化内容直接拼接为HTML
+ 涉及删除、发送、提交、覆盖或其他外部副作用的操作，必须在页面内显示影响范围并要求用户明确确认，提交期间禁用重复触发

### iframe、响应式与主题
+ 页面必须能在iframe中独立运行：不依赖父页面DOM，不假设固定视口高度，不在顶层页面使用破坏嵌入体验的全屏或跳转行为
+ 使用流式宽度、合理的最小/最大尺寸和可滚动内容区，兼容窄宽度与常见桌面侧栏宽度。
+ 页面应读取URL中可选的 `agentId`、`chatId`、`themeLabel` 参数，需要调用上下文相关API时使用前两者，缺失时提供安全降级，不伪造上下文
+ `themeLabel=深色模式` 时应用深色主题，`themeLabel=浅色模式`时应用浅色主题，未提供时优先遵循系统主题或提供稳定默认值
+ 颜色、圆角、边框、阴影和过渡优先与DESIGN文档保持一致，不要复制与当前设计基线冲突的旧主题样式

### API与数据处理
+ 先查阅`#workspace/app/API.md`，再决定接口、方法、参数和响应格式，不要猜测接口或依赖未记录的内部实现
+ 优先使用同源的Integration API（例如相对路径 `/api/files` 或当前 `location.origin`）；不得依据文档示例硬编码 `localhost`、`127.0.0.1` 或任何固定端口。处理网络失败、非成功状态码、超时和取消请求
+ 不在HTML、JavaScript、URL或本地存储中写入Token、Cookie、密码或其他凭据
+ 仅请求完成当前功能所需的数据，不要把完整API响应、iframe页面内容或大体积数据无目的地持久化到localStorage
+ 如需保存UI偏好，只保存最小且非敏感的状态，并按Agent/Chat上下文隔离，避免跨会话串扰

### 临时产物目录
+ 迷你应用在执行过程中生成的临时文件、中间文件、预览文件或未被用户明确指定保存位置的产出物，必须按类型写入当前Agent workspace中的默认目录：
    + 图片类：`#workspace/images`
    + 视频类：`#workspace/videos`
    + 音频类：`#workspace/audios`
    + 画布类：`#workspace/canvas`
    + 规划、代码、文档、日志、结构化数据及其他非媒体类：`#workspace/tmp`
+ `app/`仅用于迷你应用自身需要发布和通过站内静态地址访问的HTML、CSS、JavaScript、静态素材及其前端构建产物，不得将运行时临时产物写入`app/`，除非该文件本身是页面必须引用的发布资源
+ 生成的文件同时属于多种类型时，按其主要用途归类，无法判断时写入`#workspace/tmp`
+ 用户通过页面明确指定文件或目录保存位置时，优先遵从用户指定的位置，向当前Agent workspace之外写入时，仍须遵守页面内展示绝对路径、影响范围、风险并逐次确认的要求
+ 写入前应确保目标目录存在，目录不存在时，可创建该默认目录及必要的子目录。文件名应避免覆盖已有文件，优先使用任务标识、时间戳或随机后缀
+ 页面应在结果中展示实际产出文件的路径、类型和可访问的预览或下载入口，临时文件的保留与清理由具体功能决定，不得静默删除用户可能仍需使用的文件

### 动效与依赖
+ 简单状态过渡优先使用CSS，仅在动效确实改善理解或操作反馈时添加动画
+ 需要动画库时，优先级为：GSAP > Anime.js，需要3D时优先Three.js
+ 仅在资源已可用或能作为页面静态资源一并交付时引入依赖，不要为迷你应用单独启动后端、开发服务器或运行时安装流程
+ 尊重`prefers-reduced-motion`，并避免持续高帧率动画、自动播放音频和不必要的WebGL效果

### 更新备份
+ 每次新增或修改app内文件前，如Git可用，先检查相关文件的Git状态与差异。变更完成并验证后，只暂存本次变更的差异块并创建独立提交，以便回退。若无法区分已有改动，禁止提交并说明原因
+ 独立提交指一个已验证的完整功能或一次用户请求可回退的最小变更集，可包含该功能必要的多个app文件
+ 不得把无关的已有改动一并暂存或提交。Git不可用或无法提交时，必须说明原因并保留可审阅的差异
+ Git可执行文件路径（为空表示未安装）：`#git`

### 验证与完成标准
+ 浏览器验证准出门禁：当前任务已启用且可使用技能`__internal_browser`时，完成前必须按其规范创建或复用当前CDP session，并通过其封装的Playwright浏览器能力，直接导航至完整迷你应用页面的发布地址：`#origin/mapping/#agentId/<相对路径>`，在该页面作为顶层页面时验证核心用户流程。不得以宿主页面、站内预览容器或其中的`iframe`作为浏览器验证对象，也不得只验证iframe元素已加载。验证至少覆盖页面加载、主操作成功路径，以及本次变更涉及的关键交互、错误或重试路径；应以实际浏览器操作和可观察结果为准，不得仅凭代码审查、静态检查、截图或手工推断替代。未完成、失败或因运行环境受限而无法完成浏览器验证时，页面不得准出为"已完成"或"已验证"，最终反馈必须明确说明阻塞原因、未验证范围和下一步
+ 完成前至少验证：
    + HTML、CSS和JavaScript能正常加载，资源路径无404
    + 核心用户流程可完成，重复点击不会导致重复请求或重复提交
    + 在与常见iframe相同的窄宽度和桌面侧栏宽度视口下没有横向溢出、遮挡或不可达控件，此项应在直接打开的完整迷你应用页面中完成，不以嵌入宿主页面的iframe测试替代
    + 深浅主题、加载态、空态与错误态可读且可用
    + 涉及本机文件或目录时，验证选择器与手填路径两个入口、选择取消保留原值，以及带空格的绝对路径的展示与传递。在可用的Windows与macOS运行环境中复用同一套页面交互和接口，不以平台分支替代其中一端
    + 涉及API的操作已验证成功、失败和重试路径，且不会暴露敏感信息
    + README与当前页面、资源、接口和验证结果一致，且已包含复建同等功能所需的必要细节
+ 最终反馈包含：页面URL、文件路径、主要功能、验证结果，当技能`__internal_browser`已启用且可用时，还必须说明CDP/Playwright验证的核心流程与结果。任何尚未验证、失败或受运行环境限制的部分，均不得表述为已完成，必须明确列出
