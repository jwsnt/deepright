### 需求介绍
+ 修改居中输入框的待发送消息逻辑，将原本输入框置灰不可编辑和追加蓝色小圈图标的逻辑改为：
    + 如果有待发送消息则在居中数据框的小地球图标右上角增加一个小圆圈图标（和原来待发送消息的蓝色小圈图标一致，增加闪动效果）
        + 待发送消息需要有一个收起到蓝色小圈图标的动画，收起后居中输入框依旧处于可编辑状态
        + 可以持续多次追加，最多累计10条待发送消息
        + 当前消息正在执行时，如果居中输入框存在内容且待发送列表未满，则点击发送按钮时应将当前输入内容加入待发送列表，并清空居中输入框内容
        + 当前消息正在执行时，如果待发送列表已满，则居中输入框需要锁定为不可编辑状态，直到待发送列表数量减少
        + 当前消息正在执行时，居中输入框右侧按钮需要根据状态动态切换：
            + 如果居中输入框无内容，则保持取消按钮
            + 如果居中输入框有内容且待发送列表未满，则显示发送按钮，用于继续追加待发送消息
            + 如果居中输入框有内容但待发送列表已满，则保持取消按钮
    + 鼠标悬停在蓝色小圈图标时，向左上展开一个列表，列表内容为有序的待发送消息列表
        + 每条待发送消息在列表内展示最多10个字符，超过则用...替代
        + 每条待发送消息后有2个选项，编辑和删除按钮
            + 点击编辑则收起列表，并使用原来气泡编辑的浮层来编辑指定待发送消息
            + 点击删除则从列表中删除该待发送消息
        + 列表可以通过左侧拖拽手柄改变顺序
        + 列表拖拽完成后，插入到新位置的待发送消息需要在新位置闪动3秒，用于提示新的顺序位置
        + 鼠标离开蓝色小圈图标或列表浮层后，列表需要延迟2秒再自动收起，避免鼠标来不及移动到浮层
        + 列表浮层需要保持最高展示优先级，不能被沙盒按钮、最大化按钮或同区域其他浮层遮挡
    + 待发送消息队列按照最早插入最先执行的顺序处理
    + 每个待发送消息开始执行时，需要立即从列表中移除
        + 一旦从待发送列表取出开始执行，无论最终结果是成功、取消、异常或其他终止状态，都不能自动塞回待发送列表
        + 不允许存在任何自动回队或重复入队逻辑，避免出现循环执行
    + 列表宽度自适应，但最大宽度不能超过500px
+ 待发送列表是与AgentID+ChatID（会话ID）绑定的，切换会话时注意检查状态
    + 切换会话或切换Agent时，需要按当前AgentID+ChatID检查并展示对应的待发送列表状态
    + 当前消息正在执行时，如果点击取消，则应优先取消当前执行中的消息，而不是重复向待发送列表追加消息
