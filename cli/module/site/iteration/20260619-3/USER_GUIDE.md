# 迭代 20260619-2：待发送消息队列补强

## 功能说明

1. 当前会话仍在执行请求时，居中输入框可以继续录入下一条消息；点击发送后不会打断当前请求，而是把新消息加入当前 `Agent + Chat` 绑定的待发送队列
2. 待发送队列最多保留 `10` 条；达到上限后，居中输入框会临时锁定为不可编辑，直到队列数量下降
3. 当前请求执行中时，右侧主按钮会根据输入框状态在“取消当前请求”和“加入待发”之间自动切换
4. 待发送入口挂在输入框左侧小地球图标右上角的蓝色小圆点上；只要当前 `Agent + Chat` 还有待发送消息，这个小圆点就会持续显示并保持闪动
5. 鼠标悬停蓝色小圆点时，会向右上展开待发送列表；鼠标离开小圆点或列表后，浮层会再保留 `2` 秒才自动收起
6. 待发送列表支持 `编辑`、`删除` 和拖拽排序；拖拽需要从左侧六点手柄开始，拖拽完成后，新插入位置上的那条待发送消息会额外闪动 `3` 秒
7. 待发送列表严格按照最早插入最先执行的顺序消费；某条待发送消息一旦开始执行，就会立即从列表中永久移除
8. 无论某条待发送消息最终是成功、取消、异常还是其他终止状态，都不会自动回到待发送列表，避免出现重复执行或死循环

## 实现说明

- 待发送状态按 `AgentId::ChatId` 作用域隔离；切换会话或切换 Agent 后，只会读取当前作用域下的队列内容
- 列表浮层复用现有输入区渲染结构，但会提升到输入区同域最高展示层级，避免被沙盒按钮、全屏按钮或同区域浮层遮挡
- 编辑待发送消息时继续复用原有的居中消息编辑浮层；保存只更新队列内容，不会立即发送
- 拖拽排序已切换为指针事件驱动的手柄排序，不再依赖原生 HTML5 `drag/drop`，以保证在当前 WebView 环境下稳定生效
- 排序完成后的 `3` 秒闪动反馈只绑定到本次被移动的那条消息；队列再次刷新、切换会话或切换 Agent 时会自动按当前作用域重新校验并清理状态
