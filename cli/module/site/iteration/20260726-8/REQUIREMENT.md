### 需求介绍
+ 左侧虚拟文件系统的“新增”类型增加“图片”。
+ 创建图片时，名称未带后缀则自动补全 `.png`；已有 `.png` 后缀时保持原样（大小写不敏感）；已填写其它后缀时必须在创建浮层内提示错误，且不得打开编辑器或写入文件。
+ 点击“创建”后直接打开图片编辑预览，创建前不得在工作区生成空文件。
+ 新图片的可编辑 Canvas 固定为 `1024×1024` 原始像素，像素内容必须为透明背景；编辑浮层中的 Canvas 显示尺寸必须在不改变原始像素坐标的前提下随浮层可用宽高自适应，并允许滚动查看完整图片。
+ 工作区内既有的所有已识别图片类型继续使用同一图片预览编辑器；新建和既有图片均支持现有画笔、橡皮擦、文字、形状、取色、坐标和切图工具。
+ 图片编辑器的保存统一导出为 PNG，并统一另存到当前 Agent 工作区的 `images/` 目录：目录不存在时由保存链路创建；不得覆盖源图片或既有导出图片。
+ 保存目标文件名以创建时的图片名称或既有图片的基础名称为准，统一由服务端追加高精度时间戳后写入，例如 `images/海报_20260726_120000_123456789.png`。
+ 保存成功后刷新虚拟文件系统，并将服务端返回的系统绝对路径复制到系统剪贴板；复制失败不得影响已成功保存的图片，页面需明确提示复制失败。

### 技术约束
+ 新建图片仅在浏览器内初始化透明 Canvas，不调用“创建空文件”接口；保存时通过既有受限 `POST /api/edit?agentId=<agentId>&path=images/<name>.png&saveAsNew=true` 提交 PNG Base64。
+ 前端不得自行生成最终时间戳，必须使用服务端 `saveAsNew=true` 的最终命名结果与 `savedAs` 绝对路径，避免客户端时间与并发写入造成命名冲突。
+ 图片编辑画布的 CSS 尺寸可缩放，但 Canvas 的 `width`、`height` 及所有编辑、取色、坐标计算均以原始像素尺寸为准。
+ 图片预览/编辑画布右上角必须提供完整可见的悬浮视图控制组：包含纵向排列的“缩小”“放大”图标，以及上、下、左、右四个查看区域移动按钮；图标样式与无限画布的缩放按钮一致。缩放每次按 `1.2` 倍等比调整 Canvas 的显示宽度和高度，范围限制为 `25%` 至 `400%`，缩放状态必须解除编辑器的初始宽高自适应上限，到达边界时对应按钮禁用；方向按钮按当前可视区域的固定比例滚动编辑区，到达对应边缘时禁用。缩放与方向查看均仅改变 Canvas 的 CSS 显示或滚动位置，不能修改原始像素、绘制坐标和保存结果。
