### 需求介绍
+ 在 VFS 顶部“新增”菜单中增加“录屏”类型；确认后不创建空文件，而是打开居中的 Chrome 画面录制浮层。未选择 Agent 时必须保持既有错误提示，不得发起录制或写入请求。
+ 浮层复用 `demo/iframe-recorder/index.html` 的原生画面选择、实时预览、选区拖动/缩放、逐帧裁切、开始/停止录制和共享结束处理；必须通过 `getDisplayMedia` 让用户手动选择 Chrome 标签页、窗口或整个屏幕，不得使用 CDP、iframe、浏览器自动化或跨域嵌入。默认必须录制完整共享画面；仅当用户开启“选择录制范围”开关时才展示并启用蓝色拖拽选区，并以选区裁切输出。选区允许任意像素宽高，不能因奇数尺寸阻止、缩小、退出或中断录制；最终 MP4 自动在右侧或底部补齐至最近偶数尺寸，界面应展示补齐后的输出尺寸。
+ 浮层保留既有三步使用引导与录制功能；第二步标题为“选择录制目标”，并说明可选择标签页、窗口或整个屏幕。但不展示 `Tab Region Recorder` 标题、原有说明段落、右上角“无 CDP · 无 iframe”标记或任何 iframe 相关文案。用户取消共享、结束共享、权限拒绝和录制错误都必须回到可重新选择的状态，不得留下不可点击的遮罩。
+ 录制必须以 Chrome 实际交付的 `VideoFrame` 为单位裁切并保留时间戳；不得用页面 `requestAnimationFrame()`、后台页面绘制循环或固定 30 fps Canvas 流作为录制驱动。页面请求最高 60 fps，停止时必须先排空已进入逐帧管线的帧再完成封装。浏览器或源页面本身未交付的帧、DRM 保护内容和编码器无法实时处理的帧不承诺恢复。
+ Chrome 原生录制先产生 WebM；用户点击“保存 MP4”后，前端把该 Blob 仅作为临时二进制文件写入当前 Agent 工作区 `tmp/.screen-recording-<随机值>.webm`，再调用 Integration 的全量转码接口。临时上传、转码、刷新与关闭期间必须锁定重复操作并显示可理解的进度与失败信息。
+ 前端调用 `POST /api/video_record_convert` 时仅提交当前 Agent ID、临时 WebM 的工作区相对路径与安全的 `.mp4` 文件名。成功后刷新 VFS 的 `videos/`，提示并尽力复制返回的绝对路径；最终文件固定位于 `videos/<文件名>.mp4`。取消、关闭、上传失败、转码失败或请求中断时必须尽力删除临时 WebM，绝不把 WebM 作为最终用户文件保留。
+ MP4 名称沿用“新增”输入框：空名称使用时间戳默认名；无扩展名自动补 `.mp4`；其它扩展名和路径分隔符必须在前端拒绝。点击“创建”打开录制浮层前，前端必须以补全后的最终 `.mp4` 名称检查当前 Agent `videos/`；例如输入 `aaa` 必须检查 `videos/aaa.mp4`。同名时必须停留在创建浮层并显示冲突文件名，不得进入录制浮层。保存阶段若同名文件在录制期间新建或发生并发冲突，服务端必须在扩展名前追加时间戳，原子地保存为不重名 MP4 并返回实际路径；不得覆盖、报冲突或丢弃录制结果。保存成功前不得在 `videos/` 创建最终文件。
+ 打开录屏浮层前先调用同源 `GET /api/ffmpeg/check`。仅当 `ffmpeg` 与 `ffprobe` 可用时允许录制并保存；缺失依赖、配置错误或检查失败时必须显示服务端提供的可理解安装提示，页面不得自行探测本机可执行文件、执行安装命令或在浏览器中伪造 MP4。
