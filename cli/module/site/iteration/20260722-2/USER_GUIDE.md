# 迭代 20260722-2：设置中的模型配置测试

在“设置 → 模型与密钥”中，模型行的密钥右侧会在配置有未保存变更时淡入一个紧凑的烧瓶 Test 图标。它只在设置浮层中出现，位于客户化配置和删除图标之前；已保存且未修改的配置不会显示该图标。

## 使用方式

1. 选择服务商并填写密钥。
2. 展开客户化配置，确认“基础模型（`__model`）”有值。
3. 点击 Test 图标，等待结果提示。

“模型 URL”可以留空以使用服务商默认地址；填写时必须是 `http://` 或 `https://` 开头的完整 URL，且不能包含用户名或密码。反斜杠、空白、中文标点（如 `、`）和无效百分号编码均不允许。输入不正确时会标红，无法保存或测试，直至修正。

测试使用当前输入框里的值，不需要先点击保存，也不会保存本次测试的密钥、URL 或模型名称。保存成功后，若当前值就是已保存值，Test 图标会淡出隐藏；保存失败时仍会保留，以便继续测试或修改。

“添加模型”只会在还有未配置服务商时显示；所有服务商已配置后会自动隐藏，删除一行后如有可选服务商会再次出现。

## 结果与限制

- Test 图标的提示为“测试配置”。它只会在密钥非空且因密钥、URL 或任一模型字段发生变更时出现；密钥为空时不会显示。Seedream 不提供此入口；deepright 修改密钥后会显示且可测试。展开/收起配置、显示密钥或切换 Agent 不会显示它。图标已显示但服务商或 `__model` 缺失时会置灰，并说明原因。
- 测试进行时同一行会锁定为 loading 状态；再次点击只会取消本次测试，不会自动重试。
- 测试期间，密码区域会完全替换为不透明、闪动的“正在测试配置，请耐心等待。”提示；原密钥、小眼睛、复制和 CURL 等框内控件均不可见且不能编辑。结束后恢复。
- 服务端确认 SSE 收到有效数据并正常结束后，会在当前模型行内显示“配置成功”。
- HTTP、SSE、超时和流中断错误会在当前模型行内显示“配置错误：…”；服务商错误 JSON 会优先显示其 `content`（包括 `choices[].delta.content`），而非整段原始响应。401、403、404、429、503 与其他 5xx 会只显示统一的中文原因和处理建议；404 为“请检查模型 URL 和基础模型”，服务商仅在 `content` 中写入如 `(code=401)` 的状态码也同样适用。主动取消显示“测试已取消”。这些结果不再显示在虚拟文件系统提示中，因此不会被设置浮层遮挡。
- 测试不创建聊天、不改变当前会话、模型选择或 Agent，也不会写入浏览器本地会话数据。只有 Test 操作的服务端转发会携带 `metadata.test = true` 并传到最终服务；普通聊天不会携带该标记。
