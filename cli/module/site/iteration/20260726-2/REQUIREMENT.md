### 需求介绍
+ 左侧虚拟文件系统的“新建文件或目录”浮层新增“画布”类型。名称必须填写，并沿用现有名称合法性校验；创建画布时，若名称未以 `.canvas` 结尾，页面自动补充该后缀，已带后缀时不得重复追加。
+ 选择“画布”并点击“创建”后，页面立即打开独立的无限画布编辑浮层，而不是先创建空文件。新画布在首次点击“保存”前只能存在于浏览器临时状态；取消、关闭、点击遮罩或刷新页面均不得在 Agent 工作区留下文件。
+ 画布编辑浮层须包含无限画布的核心交互：鼠标/触控板缩放、自由平移、卡片或便签、独立文本、节点拖拽、框选、多选、连线、撤销、重做与小地图。默认在画布中央提供可删除的引导卡片；背景使用可辨识位置的点阵网格。
+ 卡片、文本及图片都是可选择和拖动的画布节点；图片必须同时支持本地上传、拖放到画布和粘贴图片。图片数据作为画布内容保存，重新打开同一 `.canvas` 文件后必须可以继续编辑。
+ 顶部标题允许修改画布标题；标题是画布 JSON 的内容/元数据，默认取文件名去除 `.canvas` 后的部分，保存标题不得修改实际文件名。
+ 点击“保存”后使用既定文件名创建或更新 `.canvas` 文件，保存成功后编辑浮层继续保持打开。首次保存或外部同名文件已存在时，必须提示是否覆盖；用户确认后才可写入。保存后的再次编辑也必须再次点击“保存”才更新文件列表中的内容。
+ 画布编辑器应提供明显的“关闭”与右上角关闭按钮。对新建但未保存的画布，无论是否编辑过，点击关闭、取消、遮罩或 `Esc` 都必须先弹出“放弃未保存内容”确认；已保存画布只有在存在尚未保存修改时才需要该确认。
+ 打开已有 `.canvas` 文件时，必须解析其保存的画布状态并进入同一编辑浮层；遇到不合法或旧版本内容时，以可编辑的空白画布和提示回退，不得使文件预览浮层崩溃。
+ 编辑器提供导出菜单：支持 PNG 与 PDF，并分别支持“整个画布”和“当前视口”两个范围。导出仅生成浏览器下载文件，不写回 Agent 工作区，也不支持 SVG。
+ 画布保存格式为版本化 JSON，至少包含 `version`、`title`、视口、节点（类型、坐标、内容/图片）和连线；前端不得将本机路径、`file://` 链接或未经编码的图片文件路径写入 `.canvas`。

### 编写代码
+ 在 `index.html` 的 VFS 新建类型、文件打开分流和既有居中 overlay 管理中最小范围实现画布编辑器；不引入第三方前端依赖。
+ 复用现有受限工作区接口保存和读取 `.canvas` 文件，图片只以 Data URL / JSON 内容在浏览器和工作区之间传输；导出使用浏览器能力，不新增服务端导出或本机文件读取能力。
+ 画布节点、连线、框选、缩放和平移必须在浅色和深色主题下可辨识；画布关闭确认、覆盖确认和键盘焦点须融入既有 overlay 互斥、`Esc` 与可访问性语义。
+ 最小范围更新。
