# 迭代 20260428-13：终止会话延迟取消与已取消补消息

## 功能说明

1. 在等待 SSE 响应期间点击终止图标时，仍会立即中断当前本地 SSE 连接或待发送消息
2. 终止后界面会进入 3 秒等待阶段，展示 `100x100px` 的淡红色转圈等待图标，随后再调用 `/api/cancel`
3. 如果已经收到 assistant 的 SSE 内容，则最后一条 assistant 消息内容会改为 `已取消`，并标记为 `完成`、更新时间
4. 如果还没有收到任何 SSE 内容，则会补一条样式一致的 assistant 消息，内容为 `已取消`，状态为 `完成`
5. 完成所有终止操作后，界面会恢复到待发送状态，并提示 `取消成功`
6. 取消后如果再点击重新加载，当前界面已经展示过的这一次请求内容不会被重复追加渲染

## 实现说明

- 本地终止和后端取消分阶段执行：先本地中断，再延迟 3 秒发起 `/api/cancel`
- 取消阶段的转圈等待图标沿用待发送样式，但颜色切换为淡红色
- `努力工作中` 浮层会保留到所有取消操作完成后，再统一收起
- `/api/cancel` 的成功判定放宽为 `status=0`，兼容连接已被关闭的场景
- 有 SSE 内容时，最后一条 assistant 消息内容会被覆盖为 `已取消`；无 SSE 内容时则补一条 `已取消` 消息，状态均展示为 `完成`
- 重新加载时会跳过当前已展示且已取消的这一轮本地消息，避免重复渲染
