### 需求介绍
+ 设置中的“模型与密钥”模型清单、客户化配置默认值和可编辑能力必须由运行时 `config/config.json` 的 `provider` 属性提供，不再在页面中维护固定模型或固定默认值。
    + 服务启动时读取一次 `config/config.json` 并缓存 `provider` 元数据；`GET /api/model_provider` 返回该缓存，页面不得再通过文件读取接口重复读取配置文件。
    + 修改 `config.json` 后，需重启应用才会生效；重新打开页面后会读取新启动实例的缓存。
    + 模型列表由 `provider` 的所有 key 构成，另加特殊模型 `deepright`；`deepright` 不读取 `provider` 配置，始终排在第一位。
    + 除 `deepright` 外，模型 key 按英文首字母升序排列。
    + `provider` 中移除的模型不在页面展示、不能新增选择，也不能用于会话或蜂群选择；其已保存密钥及客户化配置继续保留在服务端，未来重新加入 `provider` 后恢复展示。
+ `deepright` 可以正常配置和保存密钥，但没有客户化配置入口，全部模型 URL/模型字段均不可编辑。
+ 每个 `provider.<key>` 的默认值与能力规则如下：
    + `__url`：模型 URL 默认值。
    + `__model`：基础模型默认值。
    + `__model_fast`：快速响应模型默认值。
    + `__model_thinking`：深度思考模型默认值。
    + `__model_multi_input`：多模态输入模型默认值。
    + `__model_multi_output`：多模态输出模型默认值。
    + 某字段缺失、值不是字符串或为空字符串时，均视为该 provider 不支持该能力；对应输入框必须禁用，保存时不得写入该字段。
    + 有非空默认值的字段可由用户客户化覆盖；重置后恢复该默认值，清空操作保留为显式覆盖为空。
+ 只配置 `__model_multi_output`、未配置基础模型的 provider 视为仅多模态输出模型：可在“模型与密钥”中保存密钥和输出模型配置，但不可作为普通对话模型、备忘录模型、插件模型或蜂群模型选择。

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，尽量复用现有知识库展开态、右侧边栏标题 action 区、右侧栏布局同步和 chat 切换链路
    + 系统指令展开态必须与知识库展开态显式分流，避免共用同一个状态位导致语义串线
    + “系统指令是否展开”只能保存在页面运行时状态，不得写入 chat 持久化字段、`saveChats()`、`localStorage` 或 URL
    + chat 切换、右侧边栏收起、知识库进入展开态等场景下，都必须显式回收系统指令展开态，避免残留脏状态
    + 日志流式追加期间，展开态切换不得中断现有 CLI 子面板渲染、恢复和滚动沉底逻辑
    + 新按钮的 DOM 落位、显隐和 aria 文案必须稳定，禁止在不同状态下漂移到标题栏之外
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
