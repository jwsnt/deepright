### 需求介绍
+ 右侧 Sidebar 的独立 iframe 预览区需要新增一个“展开覆盖当前页面”的页内放大模式
    + 展开入口放在右侧 iframe 预览区左上角，位置与现有关闭网站浏览的小图标同域且同层级，不得漂移到其他区域
    + 展开入口的最终落点需要贴近右侧 iframe 预览左边界上方区域，视觉上位于现有关闭网站浏览小图标下方，也就是截图红框所标注的位置
    + 该入口使用“小图标”形式，尺寸、交互热区、视觉重量需与现有右侧 iframe 预览的小图标体系保持协调
    + 点击展开入口后，不进入浏览器原生全屏，不调用现有输入框左上角的浏览器全屏能力；本次仅实现站内页内覆盖展开
+ iframe 页内展开态的展示语义必须明确且唯一
    + 展开后，当前 iframe 预览需要脱离“仅占右侧栏”的布局限制，覆盖当前页面主要可视区域
    + 展开态下，iframe 需要尽量吃满当前页面可用视口，不得继续保留右侧栏宽度限制、边栏裁切或原右栏内部留白
    + 展开态容器需要以当前 HTML 可视区域为基准，上下左右各内缩 `50px` 呈现，不允许直接贴满浏览器边缘
    + 展开态浮层外的页面背景需要同步加入毛玻璃模糊与柔化遮罩，整体观感要接近“超大浮层覆盖当前页面”，而不是简单放大右栏
    + 展开态下页面上只保留右上角一个高亮的小图标作为“还原”入口；不得同时保留现有右侧关闭按钮、右侧边界悬浮关闭按钮或第二个重复的返回入口
    + 点击右上角还原小图标后，只恢复到“当前右侧 iframe 预览尺寸”，不关闭预览，不切回原右侧栏内容区
+ iframe 页内展开态只允许使用当前页面运行时状态，不得写入 chat 持久化状态
    + 现有 chat 级别持久化的 `rightSidebarUrlPreview` 语义保持不变，继续只负责“当前 chat 是否打开某个右侧 URL 预览、预览的是哪个 URL、标题/副标题为何”
    + 新增的“是否处于页内展开态”只能存放在页面运行时状态中，不得写入 chat、localStorage、URL query 或任何会跨刷新/跨会话保留的状态
    + 页面刷新、重新进入站点或切换到一个未处于展开态的新页面后，展开态默认消失，但当前 chat 若原本处于右侧 iframe 预览开启状态，仍只按原右侧预览态恢复
+ 展开态与现有右侧 iframe 预览状态的协作必须稳定
    + 只有在当前右侧 iframe 预览真实处于 active 状态且已有可展示 URL 时，才允许进入展开态
    + 若展开态期间当前 iframe 预览被主动关闭、加载失败、加载超时、切换 chat 后目标 chat 不再展示该 iframe、或右侧预览整体失效，必须自动退出展开态
    + 自动退出展开态后，不需要额外提示“已还原”；只需保证页面恢复到正确的右侧 iframe 预览态或原右侧布局
+ 展开态期间现有关闭网站浏览入口必须被禁用或隐藏，避免语义冲突
    + 右侧 iframe 预览常态下已有的关闭网站浏览按钮，在展开态下不得继续展示为可点击状态
    + 现有用于切回原右侧布局的悬浮按钮、右侧预览内部按钮、以及任何与“关闭网站浏览”同语义的入口，在展开态下都不得继续参与点击命中
    + 展开态下仅允许右上角“还原到右侧预览尺寸”的按钮可见且可点击
+ 展开态期间不得触发任何新手引导，且不得与现有引导流程串扰
    + 进入展开态后，现有 onboarding 系统不得新启动任何引导，包括但不限于右侧 iframe 预览引导、全屏引导、知识库引导、输入区引导等
    + 若某些引导原本依赖 iframe 成功加载、按钮显现、hover、首次点击等时机触发，展开态期间也必须直接拦截，不进入待启动状态
    + 本次需求默认不要求在退出展开态后补播展开态期间被拦截的引导；展开态期间命中的引导触发机会可直接跳过
    + 若进入展开态时页面上已经存在一个进行中的新手引导，不要求为该旧引导新增特殊播放效果；但展开态本身不能额外再触发新的引导步骤
+ 展开态需要支持键盘 `Esc` 还原
    + 当父页面仍持有键盘焦点时，用户按下 `Esc` 需要退出展开态，并恢复到右侧 iframe 预览尺寸
    + `Esc` 只负责退出本次页内展开态，不负责关闭右侧 iframe 预览，也不负责退出浏览器原生全屏
    + 需要兼容现有页面其他 `Esc` 监听逻辑，避免误伤已有弹层、浮层或浏览器全屏退出逻辑
    + 若焦点进入跨域 iframe 内部导致父页面无法稳定收到 `Esc`，页面仍必须始终保留右上角可点击的“还原”按钮作为兜底出口
+ 展开态的层级、遮挡与交互隔离必须显式受控
    + 展开态 iframe 容器需要覆盖当前页面主展示区，并确保普通页面元素不可误点
    + 展开态背景遮罩需要拦截普通页面点击，避免用户在浮层外误触到底层按钮、输入框或右侧关闭入口
    + 右上角还原按钮的层级必须高于展开态 iframe 本体，始终完整可见且不被 iframe、毛玻璃层、右侧栏、中心浮层残影或页面裁切遮挡
    + 展开态下不要求额外保留右侧栏标题、知识库、CLI 子面板、备忘录等普通内容的可操作性；它们可被展开层整体覆盖
    + 展开/还原过程若保留现有淡入淡出或毛玻璃动画，动画只能作用于覆盖层与按钮自身，不得引起页面整体 reflow、滚动跳动或右侧栏高度抬升
+ 展开态实现必须继续遵守现有 site 前端收口方式
    + 在 `../../index.html` 内按现有 HTML / CSS / JavaScript 组织实现，不引入新的构建流程或前端依赖
    + 代码尽量复用现有右侧 iframe 预览状态、浮动按钮、布局同步、overlay 刷新和失败回退链路，避免再造第二套 iframe 预览容器
    + 需要与现有 `scheduleLayoutSync`、overlay 域状态刷新、右侧 sidebar 折叠/展开、低功耗渲染降级机制兼容
    + 浏览器全屏能力与本次页内展开能力必须显式分流，避免复用同一状态位导致语义串线
