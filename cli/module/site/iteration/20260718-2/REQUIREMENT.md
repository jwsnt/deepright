### 需求介绍
+ 设置页的模型配置区域中，为新增或未保存成功的模型提供“复制已配置模型”能力，减少重复填写 API Key、URL 和各能力模型名称的操作。
+ 入口位置：当存在至少一条其他“保存成功”的模型配置时，在当前模型行的 API Key 输入框右侧操作区展示 Copy 小图标；小眼睛图标向左移动，为 Copy 图标预留位置。
    + Copy 图标仅在可复制来源存在时展示；没有其他保存成功的模型时不展示。
    + 当前正在编辑的模型不得作为复制来源，即使该模型此前已保存成功也必须从来源列表排除。
    + `deepright` 不参与复制：不能作为复制来源，当前新增模型为 `deepright` 时也不展示 Copy 图标。
+ 交互流程：
    + 点击 Copy 图标后，展示轻量下拉选择框，列出其他全部保存成功的模型配置，供用户选择复制来源。
    + 用户选择来源后，立即将来源的 API Key、URL 及模型能力配置写入当前正在编辑的模型；不新增或修改来源模型本身。
    + 复制完成后，自动展开当前模型的“个性化配置”区域，便于用户检查和继续调整复制结果。
+ 复制范围：
    + 基础模型配置。
    + 快速模型配置。
    + 思考模型配置。
    + 多模态输入模型配置。
    + 多模态输出模型配置。
    + API Key 与 URL 配置。
+ 能力兼容规则：
    + 当前模型支持、但复制来源不支持的能力：保留当前模型该能力的默认值，不使用来源的空值或不支持状态覆盖。
    + 当前模型不支持的能力：始终维持既有不可编辑状态；即使复制来源配置了该能力，也不得将其变为可编辑或写入为可用配置。
    + 当前模型和复制来源均支持的能力：复制来源的对应配置值。
    + 复制行为不得改变当前模型由模型类型/能力定义决定的支持范围和编辑权限。
+ 状态与数据约束：
    + “保存成功”以现有模型配置保存状态为准；只有该状态的模型才可出现在复制来源列表中。
    + 复制仅填充当前表单的编辑值，仍须由用户点击现有“保存”按钮后才持久化。
    + 复制后的 API Key 保持现有脱敏展示、显示/隐藏及安全处理逻辑，不得在列表或下拉框中明文暴露密钥。

    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，优先复用既有备忘录查询接口、明细缓存、`rsMetaCenterPreview`、overlay 域管理、`scheduleRefreshCronViews()`、现有本地存储统计和容量维护能力；不得复制形成第二套预览、压缩或统计体系

    + 不得信任前端传入的 Agent、状态、周期、时间、游标或排序；服务端完成归一化、范围校验、权限/存在性校验和参数绑定
    + 能用现有开源包和浏览器能力的就不要重复造轮子
