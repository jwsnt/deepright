# Site 迭代手册（20260525-1）

## 本次更新

- 修正会话区 SSE 流式响应的 Markdown 渲染时机，增量阶段不再长时间停留在原始 `#`、`*`、``` 等符号文本
- 流式消息在每次收到新的累计文本后，会立即进入与最终完成态一致的 Markdown/HTML 安全渲染链路
- 渲染前新增轻量文本归一化，会先清理 ANSI/OSC 控制序列、`\r` 回车、零宽字符等隐藏干扰内容，避免 `#### 正在加载技能 weather` 这类工具进度行因脏前缀失去标题语义
- 自动滚动改为“仅在用户仍停留底部附近时跟随”，主动上滑查看历史时不会被抢回底部
- 主动停止生成时，已收到内容会保留，assistant 状态改为 `已取消`
- 如果实时 Markdown 渲染仍异常降级，页面会保留当前文本可见，并在浏览器控制台输出统一前缀 `[stream-markdown] fallback to plain text`

## 当前行为

1. 每次 SSE 新增 `delta.content` 后，页面都会基于当前完整累计文本立即重渲染当前 assistant 气泡。
2. 标题、列表、引用、代码块、表格、链接、图片、安全 HTML 嵌入等结构会在流式过程中持续成型，而不是只在结束后一次性转换。
3. 对于未闭合代码块、未闭合表格、未闭合 HTML 片段等中间态，页面会先按当前可解析结果展示，结束后自然收敛到最终样式。
4. 如果增量文本里混入 ANSI 颜色控制符、回车覆盖字符、零宽前缀等隐藏内容，页面会先清理，再交给 Markdown 解析器，保证可见结构不被这些脏数据破坏。
5. 当滚动条仍停留在底部附近时，新增内容会自动跟随到底部；如果已经主动上滑，后续流式更新不会强制抢回视图。
6. 点击停止生成后，如果当前轮已经收到部分内容，这些内容会继续保留在气泡中，只把状态更新为 `已取消`。
7. 如果消息在实时 Markdown 渲染阶段被迫退回纯文本，页面不会清空内容；同时控制台会打印统一前缀的告警日志，便于继续定位异常输入。

## 验收建议

1. 发送以 `#### 正在加载技能 weather` 开头的流式响应，确认在 SSE 未结束前就已经按标题样式展示，而不是看到原始井号文本。
2. 发送包含列表、引用、未闭合代码块的流式响应，确认中间态持续可读，结束后收敛为最终正确样式。
3. 在流式过程中主动上滑，再继续等待增量内容，确认视图不会被强制拉回底部。
4. 在已经收到部分内容时点击停止生成，确认气泡内已有文本保留，右下角状态显示为 `已取消`。
5. 若再次遇到流式阶段显示原始 Markdown 的异常，打开浏览器控制台，检查是否出现 `[stream-markdown] fallback to plain text`，并结合对应内容继续排查。
