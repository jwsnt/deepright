### 需求介绍
+ 在待发送消息列表每个待发送消息的编辑按钮前增加插入小图标，点击后调用/api/message_insert/add为该消息插入上报，tid为当前时间戳
    + Integration接口需求：../../../integration/iteration/20260621-1/REQUIREMENT.md
    + 待发送消息列表需求：../20260619-2/REQUIREMENT.md
+ 待发送消息列表每个待发送消息继续保持3个操作按钮：插入、编辑、删除（从左到右），并保留现有拖动手柄：
    + 插入按钮用于将当前待发送消息加入插入上报；进入插入态后按钮切换为进行中小图标，并等待SSE确认报文
    + 编辑按钮在未进入插入态时保持现有编辑行为；已进入插入态但尚未通过 `cli/pub` 正确上报时，先调用/api/message_insert/del撤销插入态，再进入现有编辑流程
    + 删除按钮在未进入插入态时保持现有本地删除行为；已进入插入态但尚未通过 `cli/pub` 正确上报时，改为调用/api/message_insert/del取消加入插入消息，仅清除插入态而不删除本地消息
+ 插入成功后该待发送消息持续高亮，插入小图标切换为进行中小图标，并继续保留在当前Agent + Chat作用域的插入队列中，等待SSE确认：
    + 单个待发送消息作用域内最多同时跟踪5条插入中的消息
    + 页面上的插入状态、按钮状态和动画效果需要与当前Agent + Chat作用域绑定，切换会话或切换Agent时不要相互影响
    + 如果用户主动取消插入，则按现有删除接口清除插入态
    + 当这条插入消息已经通过 `cli/pub` 正确上报后，在它转为最终结果前，待发送列表中不再提供编辑/删除功能，只允许等待成功、异常或SSE结束兜底
    + 如果前端本地状态暂时还没感知到“已通过 `cli/pub` 上报”而误触发编辑/删除，服务端拒绝后必须立即提示并阻止后续操作，同时把当前待发送项刷新为只读等待态
+ 当页面收到SSE响应报文中 `metadata.__PROCESS__ = rag_insert` 且 `metadata.__TID__` 与待发送消息tid相同（插入后）时，需要立即：
    + 气泡样式与普通用户发送消息一致
    + 气泡位置在发起这次最初请求的SSE气泡之下、等待SSE响应的气泡之上；若当前尚未出现等待中的SSE响应气泡，则先追加到当前会话消息末尾
    + 该气泡首次出现时需要有明显的插入入场动画，并且动画只在首次插入到当前会话时播放一次，不能因后续重渲染、切换会话或恢复渲染而反复播放
    + 对应待发送消息要立刻从插入队列中移除，不再依赖 `/api/message_insert/status` 轮询
+ 已进入插入态的待发送消息再次点击编辑时，需要先调用/api/message_insert/del撤销当前插入态，再进入现有编辑流程：
    + 编辑保存后仅更新本地待发送消息内容，不自动重新进入插入态；如需再次插入，由用户重新点击插入小图标触发
+ 已进入插入态的待发送消息点击删除按钮时，不再直接删除本地待发送消息，而是调用/api/message_insert/del取消加入插入消息：
    + 取消成功后仅清除插入态和高亮态，待发送消息继续保留在本地待发送列表中
+ 如果待发送消息队列轮到该消息时该消息尚未被上游消费，则在自动发送前best-effort调用/api/message_insert/del撤销插入上报：
    + 无论接口返回是否异常，都继续自动发送，不因删除接口异常阻塞发送
