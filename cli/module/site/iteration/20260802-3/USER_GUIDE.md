# 视频提取主体

在当前 Agent 工作区根层悬停 `videos` 文件夹，点击放大镜“视频提取主体”；虚拟文件系统中的每个视频文件也提供同款放大镜，视频预览工具栏中相机左侧同样提供该入口。文件入口会直接带入所选视频。所有入口都先检查 FFmpeg 与 FFprobe，再仅将当前页面已选择的 Agent ID 发送给服务端；服务端用这个 Agent ID 解析工作目录，优先检查 `$workspace/rvm/inference.py` 与 `$workspace/rvm/weights/rvm_mobilenetv3.pth`，并依次回退到普通 `git clone` 产生的 `$workspace/rvm/RobustVideoMatting/` 和工作区根层同名目录。任务执行会沿用通过预检的脚本与权重组合；某个组合运行失败时会继续尝试下一组。不使用会话 UUID，也不会传递或反查 VFS 工作目录。任一依赖缺失时，点击“安装”会把对应的配置安装请求发送到当前 Chat，其中 `$workspace` 已替换为该 Agent 的实际工作目录，页面不会自行安装。

依赖可用后，浮层可从本机多选 `mp4`、`m4v`、`webm`、`ogv`、`mov`、`mkv`、`avi`、`mpg` 或 `mpeg` 视频，最多暂存 5 条。每个视频可选择“标准主体提取”（默认，适合大多数视频）、“精细边缘提取”（保留更多发丝和边缘细节，处理更慢）或“快速主体提取”（适合预览和较低细节要求）；底部会说明当前场景作用。点击“开始”或按 `Enter` 加入队列；`Esc` 或“关闭”只关闭浮层，不会取消已创建任务。

任务列表会标记每条任务的场景，可按状态筛选、每页查看 5 条、打开执行日志、取消、重新开始或删除失败与已取消记录。完成任务支持预览、复制单项输出；勾选多个完成任务后，可用“复制”一次复制所有输出绝对路径，“清空”只取消勾选。输出保存在 `videos/<原文件名>_subject.mov`，保留透明通道；同时生成同名 MP4 作为预览副本，预览副本会将透明区域填充为纯黑色。复制的仍是 MOV 路径，预览打开 MP4；VFS 不直接预览 MOV。任一同名配对文件已存在时，会同时添加相同时间戳且不会覆盖。任务优先使用 GPU（macOS 使用 MPS），不兼容时自动改用 CPU 重试。
