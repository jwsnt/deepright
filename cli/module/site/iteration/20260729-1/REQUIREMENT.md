### 需求介绍

+ 飞书插件的参数保持为既有 `param` 契约返回的 `appId`、`appSecret`、`mcp_url` 三项；不得重命名、替换或新增字段。飞书插件的识别必须继续使用运行时 `key=feishu`，不得以展示名 `name` 作为判断、提交、启动或查询标识。
+ 在飞书插件配置浮层点击“启动插件”或“重启插件”时，前端必须先读取三个输入的 `trim()` 后值并执行相同校验；校验失败时不得提交配置或发起启动／重启请求，并在现有提示机制中清晰说明失败原因。
+ 校验规则如下：
  + `appId` 与 `appSecret` 是同一凭证组。二者只要有任意一个非空，另一个也必须非空；仅填写其中一个时，提示“appId 和 appSecret 必须同时填写”。
  + 凭证组完整（`appId`、`appSecret` 均非空）时允许启动，`mcp_url` 可为空或非空。
  + 凭证组完全为空时，必须填写非空的 `mcp_url` 才允许启动；三个字段均为空时，提示“请填写 appId 和 appSecret，或 mcp_url”。
  + 仅填写 `mcp_url` 为合法配置，必须允许用户点击启动／重启，并按既有流程保存该字段和展示服务端返回的启动成功状态；前端不得因不存在飞书应用凭证而自行将其显示为启动失败。
+ 本次仅调整飞书插件启动前的参数校验，不改变其他插件的参数校验、配置保存、会话绑定、启动／关闭按钮、日志查看或 URL 文档图标行为。既有 `mcp_url` 回填、提交及 URL 图标仍只对 `key=feishu` 和字段 `mcp_url` 生效。

### 编写代码
+ 以现有 site 页面技术栈在 `../../index.html` 最小范围实现；不引入新的构建流程、第三方依赖或持久化状态。
+ 校验必须复用现有插件参数收集、toast 与启动／重启调用链，且只在运行时主键为 `feishu` 时启用。继续以字段 key 读取和写入 `appId`、`appSecret`、`mcp_url`；禁止根据标签文字或插件 `name` 推断字段和插件身份。
+ 保持服务端校验为最终准入条件：前端校验只用于阻止无效点击和给出即时反馈，不得伪造启动成功状态或绕过服务端返回的错误。
+ 覆盖前端自动化测试：完整凭证组（含／不含 `mcp_url`）可启动；仅 `mcp_url` 可启动且正常展示成功；仅 `appId`、仅 `appSecret`、三项为空均被阻止；非飞书插件和既有 `key`、`name` 语义不受影响。
