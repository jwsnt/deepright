### 需求介绍
+ 右侧边栏的`知识库WIKI`区域必须以当前激活的`Chat`为唯一作用域。其它后台`Chat`即使仍在接收SSE，也不得改变当前右侧区域、当前输入框上方的“努力工作中”提示或当前会话的停止按钮状态。
+ 当前激活`Chat`的SSE请求已经实际发出且尚未达到终态时，右侧区域必须从知识库切换为思考展示；终态包括正常完成、服务端异常、网络异常和用户取消。用户点击取消后，应立即按已取消终态恢复知识库与“努力工作中”提示，不能等待后续取消接口的确认等待。
+ 思考展示的数据必须与居中SSE响应内的思考小气泡共用同一份已捕获思考片段，不能单独请求、生成、改写或复制另一份思考内容。片段按捕获顺序展示，按逻辑分组去重后仍须允许后续增量合并到原片段；正文继续使用既有Markdown渲染和安全处理。
+ SSE已经开始但尚未产生思考片段时，右侧区域仅展示闪动的`...`等待态；首次片段到达后原地切换为片段列表。每次片段新增或合并后，片段列表必须自动滚动到末尾。
+ 思考展示期间，隐藏顶部知识库WIKI标题栏及全部操作入口，只保留内容区的“正在思考”状态提示；知识库正文、面包屑和文档加载结果均不得覆盖思考展示。
+ 当前激活`Chat`进入终态后，右侧区域必须立即恢复该`Chat`对应Agent的知识库标题、面包屑和已加载正文。SSE期间完成的知识库加载可更新缓存，但只能在恢复知识库展示后写入可见区域。
+ 切换`Chat`时，必须在切换当下依据目标`Chat`的实时SSE状态、恢复轮询状态及本地已记录的未结束请求状态决定右侧展示：目标`Chat`未结束即展示其思考等待态或思考片段；目标`Chat`已经结束、取消或异常即展示知识库。不得先沿用前一个`Chat`的思考内容，也不得被任意全局“存在流”的状态误导。
+ 刷新页面后，若本地记录表明当前`Chat`最后一轮请求尚未结束，页面必须在既有恢复轮询启动前后持续保持思考展示，并用恢复得到的同一批思考片段刷新列表；恢复到完成、取消或异常记录后立即切回知识库。没有未结束请求时，首次进入即展示知识库。
+ “努力工作中”提示必须使用与右侧思考展示相同的当前`Chat` SSE生命周期判定：预检阶段尚未实际发出SSE时不显示；已发出且未终态时显示；完成、异常或取消后隐藏。

### 编写代码
+ 最小范围更新，不新增第三方依赖。
+ 复用既有会话流状态、恢复轮询、思考片段持久化、Markdown渲染和知识库缓存；不得引入新的SSE连接、轮询接口或独立思考内容存储。
+ 知识库异步加载与思考展示并发时必须以当前`Chat`的展示状态为准，避免异步回调覆盖右侧内容。
