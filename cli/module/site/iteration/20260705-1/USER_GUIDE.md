# 20260705-1 用户手册

本次迭代补齐了两组体验：assistant 响应中的 URL / 路径会以可点击行内小气泡展示，同时 `/api/restore` 会同步恢复右侧 `CLI` 子任务历史。

## assistant 行内小气泡

- 这次气泡化仅覆盖 assistant 响应展示链路，包括实时 SSE 增量渲染和 SSE 结束后的历史恢复
- 可识别的文件路径、`file:///`、`http/https` 不再以内文蓝色下划线作为最终展示，而是改为与输入框同风格的行内小气泡
- 文件类气泡只展示文件名或末级路径摘要，URL 气泡展示可读摘要；每个气泡内部仍会保留完整原始路径或 URL，供复制、预览、下载文件、打开目录、打开网页等动作复用
- 点击 assistant 小气泡会直接弹出动作浮层，不再要求先双击或框选；动作顺序固定为 `复制` 优先，并继续沿用现有文件预览、URL 预览、下载文件、打开目录和打开网页规则
- 如果同一目标在 SSE 中被拆成多个 chunk，页面会等现有提取规则稳定命中后再气泡化，避免半截路径误显示或在文字链接与气泡之间反复闪烁

## restore 恢复 CLI 子任务历史

- 页面调用 `/api/restore` 拉取历史时，除了用户消息和 assistant 消息，也会同步消费返回中的 `cli/get`、`cli/pub` 记录，在右侧 `CLI` 子面板重建对应的 `CMD` 历史
- `cli/get` 会恢复成一条待完成的 CLI 子任务，前端会尽量从原始 `content` 中提取真实命令文本，兼容直接 `{"cmd":"..."}`、嵌套 `message`、`messages[].content` 等现有日志结构
- `cli/pub` 会作为上一条尚未完成命令的执行结果恢复，兼容纯文本输出和 JSON 包裹的 `message`、`content`、`messages` 结构；一旦命中，会直接把原记录补全为成功/失败与输出结果
- 同一次 restore 或后续轮询续拉中，同一条 `cli/get` 不会重复插入；已恢复但还没匹配到结果的记录会继续保持 `执行中`
- 恢复出来的 CLI 历史会和手动 `CMD` 共用同一套展示样式、状态文案以及复制回 `CMD` 输入框逻辑，并继续按 `createdAt/id` 时间线排序
- 如果某条 `cli/pub` 没有找到可配对的待完成命令，前端会忽略这条孤立结果，不会影响当前轮的消息恢复
