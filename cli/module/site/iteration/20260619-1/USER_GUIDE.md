# 20260619-1 用户手册

本次迭代把居中对话框里的 `__RETRY__` SSE 提示统一收敛到了 assistant 气泡的临时提示位，不再额外生成独立红框。

## `__RETRY__` footer 提示

- 当 SSE 响应报文里的 `choices[0].metadata.__RETRY__` 非空，且这条报文本身仍属于正常 retry 提示包时，页面会把提示展示到当前会话的统一临时提示位；默认落在最后一个 assistant 气泡底部的 footer 槽位
- footer 展示内容直接取 `choices[0].delta.content`，不再使用前端兜底文案；例如服务端下发 `\n[服务将在 15 秒后重试，错误码 503]\n` 时，页面会直接展示这段文本归一化后的结果
- 文本归一化规则与现有前端收口保持一致：去掉 `\r`、裁掉首尾空白、把连续换行折叠为空格，再把连续空白折叠为单个空格
- 如果 `choices[0].delta.content` 归一化后为空，则不会展示空提示，而是直接清空当前会话的 retry footer
- 这类纯 `__RETRY__` 报文在实时 SSE 和 restore 历史恢复时都不会进入居中对话框正文，也不会再插入独立 retry 红框

## 会话隔离与计时

- `__RETRY__` 的作用域只绑定到当前 `ChatId`；`agentId` 不参与隔离键匹配
- 不同会话之间的 retry 提示互不串扰；只有当前活跃提示仍然属于同一个 `ChatId` 时，到时自动清空才会生效
- 展示时长优先取 `choices[0].metadata.delay`，并按毫秒处理
- 如果 `delay` 缺失、非法或小于等于 `0`，则默认展示 `30` 秒
- 如果下一轮又收到新的 `__RETRY__` 报文，页面会立即用最新文案替换旧提示，并按最新 `delay` 重新开始计时

## 与 `__PROCESS__` 和错误态的关系

- `__RETRY__` 与 `__PROCESS__` 共用同一个 assistant footer 展示位，谁后到就立即覆盖谁
- 如果对应 SSE 报文里的 `choices[0].metadata.__TARGET__` 为非空标记，则这条临时提示会改为展示在当前等待响应的 assistant 气泡内侧；这个标记只影响位置，不参与作用域匹配
- 两者各自沿用自己的展示时长：`__PROCESS__` 为 `5` 秒，`__RETRY__` 为 `metadata.delay` 或默认 `30` 秒
- `努力工作中` 的位置和逻辑保持不变，仍只跟当前会话 busy 状态相关，不会被 `__RETRY__` 替换
- 红色错误气泡只保留给真正错误场景：HTTP 非 `200`、网络错误、SSE 报文 `code` 不在 `200-299` 范围内，或 `finish_reason=error`
- 如果一条错误报文本身仍带有 `__RETRY__` 标记，但它并不属于正常 retry 提示包，页面仍按错误红框展示，不会进入 footer

## 新手引导

- 首次收到 `__RETRY__` 时，原有的三步引导链路继续保留
- 第一阶段不再高亮旧的独立红框，而是改为高亮 assistant footer 里的最新 retry 提示，并提示 `这类错误通常是模型配置引起的。`
- 后续两步仍会继续引导用户检查当前模型配置，并在需要时使用中间输入区的 `终止` 按钮重新执行
