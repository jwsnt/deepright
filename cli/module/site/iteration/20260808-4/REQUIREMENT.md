### 需求介绍
+ 所有请求类可编辑输入框都应在光标离开输入框后识别其中完整的文件路径和 URL，并直接转换为可操作气泡；粘贴完整文本时应立即识别。覆盖居中请求、右侧备忘录、Chat 便签、消息编辑、页面标注和迷你应用修复原因输入框。
+ 识别规则必须与 assistant SSE 响应正文的路径 / URL 识别规则共用同一份定义，支持 `http://`、`https://`、`www.`、`file:///`、绝对路径、`~/` 路径，以及既有白名单相对路径；不得为输入框另建一套会漂移的正则规则。
+ 文件路径无论是否存在都必须转换为气泡；转换阶段不得请求文件系统、工作区或网络接口验证存在性。
+ 粘贴完整文本后，已识别的完整目标应立即转换。用户连续键入或输入法提交时均不得转换；只有输入框失焦、光标离开后才识别，避免路径或 URL 尚未输入完即被替换。
+ 文件气泡提交时保留既有 `[FILE:完整原始值]` 语义；URL 气泡提交时保留完整原始 URL。气泡可以显示文件名、末级路径或 URL 摘要，但必须在 DOM 中保存完整原始值，复制、预览、下载、打开目录和打开网页均以完整值为准。
+ 自动转换必须跳过已有气泡，不能重复嵌套；替换文本节点后应恢复当前光标或选区的连续编辑位置，不能导致输入焦点跳出当前输入框。
+ 用户点击文件或 URL 气泡时，应复用现有动作浮层。文件根据实际可用状态显示复制、预览、下载文件、打开目录等动作；URL 显示复制、预览、打开等动作。文件是否不存在只影响可用动作，不影响气泡生成和复制。
+ 自动生成的气泡必须沿用现有删除按钮、主题样式、草稿持久化、待发送消息、文件所有者传递和消息渲染语义，不能改变已有 `@` 文件 / 技能 / Agent 气泡行为。

### 编写代码
+ 自动转换逻辑必须收口为可复用公共函数，由粘贴和失焦入口调用，禁止为各输入框复制独立解析逻辑。
+ 固定定位的动作浮层必须继续复用既有分域和层级管理；隐藏态不可点击、不可聚焦且不拦截其它输入框。
+ 代码应保持简洁，并优先复用既有 SSE 路径解析、气泡渲染和动作项构建能力。
