### 需求介绍
+ 左侧虚拟文件系统中，凡是直属包含 `SKILL.md` 的目录，都需要在目录图标位置展示可点击的技能目录开关
+ 技能目录开关需要按当前会话展示三种状态：
    + 正常态：目录可用，标题提示 `禁用当前技能目录及其子孙技能`
    + 自身禁用态：当前目录已被当前会话禁用，标题提示 `启用当前技能目录及其子孙技能`
    + 继承禁用态：当前目录因父级技能目录被禁用而不可用，标题提示 `当前目录因父级技能目录被禁用，需先恢复父级`
+ 页面请求虚拟文件系统目录数据时，需要携带当前 `chatId`，并根据 `/api/files` 返回的 `hasSkill`、`skillDisabled`、`skillDisabledSelf`、`skillDisabledInherited` 渲染目录状态
+ 点击技能目录开关时，需要调用 `POST /api/skill_state`，按当前会话切换禁用/恢复状态
+ 切换成功后必须立即刷新当前虚拟文件系统目录，并在 Tips 位置提示：
    + 禁用成功：`技能目录已禁用`
    + 恢复成功：`技能目录已恢复`
+ 切换失败时，需在 Tips 位置展示明确错误信息，不允许静默失败
+ 当当前没有有效会话时，点击技能目录开关不发送请求，并提示 `请先选择会话`
+ 当目录处于继承禁用态时，点击该目录开关不能直接切换，而是提示 `当前目录因父级技能目录被禁用，需先恢复父级`
+ 首次真实禁用任意技能目录后的独立新手引导逻辑保持不变，并需要与本次目录状态展示和切换逻辑兼容

### 页面与展示
+ 技能目录开关需要复用虚拟文件系统现有行内按钮布局，不新增额外行高和独立浮层
+ 继承禁用态与自身禁用态在视觉上都需要明显区别于普通目录，且深浅色模式都要可辨认
+ 目录行点击、双击、拖拽、多选、现有 warning/repair/doc tidy 按钮逻辑不能被破坏；技能目录开关只拦截自身点击事件
+ 切换成功后以当前目录刷新结果为准；如果当前目录或父目录状态发生变化，列表展示需要同步更新所有受影响的技能目录图标
+ 页面继续按现有 `index.html` 的 HTML/CSS/JavaScript 组织方式实现，不引入新的构建流程和额外运行时依赖
