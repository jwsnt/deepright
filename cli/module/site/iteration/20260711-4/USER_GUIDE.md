# Site 迭代 20260711-4 使用手册

## 本次更新

- 站点启动链路升级为“两段式轻量接管”：浏览器首次进入时先显示 integration 层的 `/launch` 过渡页，真正进入 `index.html` 后再由页面内 boot loading overlay 接管。
- 本地存储预算治理继续作为常驻能力保留，并与这次启动链路一起作为本轮正式收口。

## 启动链路

- 集成入口首次打开站点时，浏览器不会直接撞到 `/site/?v=...#app`，而是先进入极轻量的 `/launch` 页面。
- `/launch` 默认显示两行状态：`正在启动`、`等待完成`，下方提供一个 `立即重试` 按钮。
- 如果重试次数较多，第二行会升级为 `首次打开新安装包时，页面资源可能还在准备`，提示这通常是新安装包首次打开时的资源准备阶段。
- `/launch` 只负责轮询 `/site/` 是否已可访问；一旦检测通过，就会立刻 `location.replace(...)` 跳转到真正的站点地址，不在该页继续停留。
- 浏览器进入 `index.html` 后，会立即显示页面内的 boot loading overlay，默认文案为 `正在加载中 / 请稍后`。
- 如果主页面骨架接管偏慢，boot loading 会升级为 `仍在加载，请稍候 / 页面主体即将显示，后台初始化会继续补齐。`
- boot loading 只覆盖主页面基础骨架接管前的短暂初始化阶段；主页面一旦可见，这层提示就会立即释放，不会阻塞后续的 token、插件状态、知识库、历史恢复等异步补齐流程。

## 本地存储治理

- 页面继续使用浏览器 `localStorage` 保存本地会话，但会按当前 origin 下的总占用做预算治理，而不是只盯某一个 key。
- 当总占用超过约 `2.5 MB` 时，页面会自动压缩本地聊天历史，目标压回约 `1.5 MB`。
- 页面初始化完成后会启动定时巡检，默认每 `30s` 检查一次；页面重新可见和每次 `saveChats()` 成功后，也会补做一次预算检查。
- 每个 `chat` 持久化到本地的 `cliCommandHistory` 只保留最近 `30` 条；右侧 `CLI` 子面板的本地历史窗口也统一只保留最近 `30` 条。
- 自动压缩会优先删除已完成 assistant 消息中仅用于恢复的 `rawSse`，再优先裁剪非活跃会话的 CLI 历史与较旧消息窗口，尽量保住当前可直接阅读的中心正文。

## 运行边界

- 当页面存在进行中的 SSE 或 restore 流式恢复时，自动治理会暂时让位，不会在中途压缩本地副本。
- 真正发生自动压缩后，压缩后的 payload 会同步回当前页面运行时状态，聊天主区、右侧 `CLI` 子面板和相关 UI 都会按新状态刷新。
- 自动治理默认静默运行；只有第一次真实发生“超过 `2.5 MB` 后自动压缩”时，页面才会提示 `本地存储超过 2.5 MB，已自动压缩本地历史`。
- 如果主动治理没来得及拦住 quota error，原有写入阶段的 fallback 压缩链路仍会继续兜底。
