### 第一性原则

- 仅允许新增、更新或删除 `cli/module/site` 及其子目录中的文件。
- 本次治理对象仅为浏览器当前 origin 的 `localStorage`；不得改变 SSE 协议、上游转发方式或服务端会话日志。
- 必须保留当前页面已经渲染的消息内容和流式渲染节奏；本地持久化的压缩不能造成气泡闪烁、回退、重建或中断 SSE。

- 严格遵守整体设计文档：`../../../DESIGN.md`。
- 严格遵守站点模块设计文档：`../../DESIGN.md`。

### 需求介绍

长时间 SSE 响应会持续向 assistant 消息的 `rawSse` 追加原始事件；旧实现会在存在 SSE/restore 流时跳过本地存储治理，导致占用可在请求未结束时超过浏览器配额。需要把治理调整为由 SSE 包驱动的本地存储预算控制，避免空闲时周期性做重计算，同时保证已显示 DOM 完全不受影响。

### 本地存储预算

- 总占用软阈值为 `2.5 MB`，压缩后的目标占用为 `2 MB`；统计范围是当前 origin 下全部 `localStorage` 键值。
- 页面初始化、重新可见、常规保存和 `30s` 巡检仍可触发常规预算维护。
- 当存在 SSE 或 restore 流时，预算维护不得再直接跳过；它必须使用当前内存会话快照估算“下一次持久化后的总占用”，而不能只读上一次已经落盘的数据。
- 首次启动 SSE 时，需要记录一次精确的持久化快照体积；若此时已超过 `2.5 MB`，先做一次治理再开始流式接收。

### SSE 包驱动治理

- 每收到一个可持久化的 SSE `data:` 包后，只能执行常数级、轻量的增长估算，不得对完整会话反复 `JSON.stringify` 或重复扫描全部 `localStorage`。
- 估算需保守覆盖原始 SSE、JSON 转义和消息元数据的增长；当累计预估触及预算检查线时，才允许执行一次精确序列化和总占用计算。
- 精确计算确认超过 `2.5 MB` 后，立即持久化压缩后的 payload；压缩后重新设定下一次检查线，至少相隔 `64 KB` 的预计增长，避免连续小包反复触发重计算。
- 不得使用“每 1.5 秒”等仅为 SSE 而新增的定时压缩任务；没有 SSE 包时不能发生逐包治理计算。
- SSE 结束后的单会话回收仍需保留，作为流中治理的补充而不是唯一的压缩时机。

### 压缩顺序与持久化投影

- 优先清理备忘录查询缓存；随后按既有顺序处理 `cliCommandHistory`、已完成响应的 `rawSse`、思考快照和较旧会话消息窗口。
- 流式响应仍在进行而占用继续超限时，允许删除当前消息的 `rawSse` 与可丢弃快照，但必须保留当前已展示的正文。
- 最后兜底阶段允许只在持久化 payload 中保留更小的恢复窗口，并将单条 `content` / `cliSubContent` 压缩为首尾保留的文本片段。运行时消息对象不得被截断。
- 流中产生的“持久化投影”必须保存在运行时消息的非枚举元数据中；后续正常 `saveChats()` 仍须按该投影落盘，不能将已清理的原始流或已截断的持久化正文重新膨胀回 `localStorage`。

### DOM 与流式渲染保护

- 流中压缩不得调用 `renderMessages()`、不得替换当前流式 chat/message 对象、不得修改已经插入页面的消息 DOM。
- 对正在进行 SSE 或 restore 的会话，只允许更新其持久化投影；非流式会话可按现有规则同步压缩后的运行时数据。
- SSE 包到达、正文拼接、增量 Markdown 渲染、自动滚动及右侧 CLI 子任务渲染必须继续使用原有链路。
- 如果压缩无法落盘，保留既有“本地存储已满，新的会话历史暂未保存”提示；已经在页面中显示的本轮内容仍应继续显示。

### 告警与统计

- 左侧“本地存储统计”图标在总占用超过 `2.5 MB` 时显示红色告警；启动、保存、页面恢复、常规巡检和流中精确预算检查后都需要同步状态。
- 统计浮层必须显示实际已落盘的 `localStorage` 占用；流中压缩完成后刷新统计应能看到目标占用已下降。
