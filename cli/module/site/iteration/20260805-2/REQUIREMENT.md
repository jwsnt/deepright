### 需求介绍
+ WSL/Linux 用户在非引导状态下点击会话沙盒按钮时，页面必须先向同源 Integration 发送 `GET /api/bubblewrap/check`；不得依赖浏览器 User-Agent、页面本地命令探测或配置副本判断运行平台和依赖状态。
+ 检查期间必须复用既有依赖检查锁定层并防止重复点击。检查请求失败、HTTP 非成功、响应缺失或 `status != 0` 时，不得打开沙盒浮层，并显示服务端返回的可理解错误。
+ 当响应表示当前平台不需要 Bubblewrap，或 Bubblewrap 已可用时，才可继续打开既有会话沙盒浮层并刷新当前 Chat 的沙盒状态。当前平台需要 Bubblewrap 且 `available == false` 时，不得打开该浮层。
+ 缺少 Bubblewrap 时，页面显示与 FFmpeg 一致的安装确认框。取消、点击遮罩或 `Esc` 仅关闭确认；确认或 `Enter` 必须将服务端返回的非空 `install` 文本作为用户消息自动发送到当前 Chat，使用现有消息发送链路，不写入输入框、不再二次确认，也不得在浏览器中执行安装命令。
+ 沙盒新手引导仍优先于真实交互；引导过程中的演示展开不得触发依赖检查或安装确认。完成引导后的真实点击才执行本需求的预检。
