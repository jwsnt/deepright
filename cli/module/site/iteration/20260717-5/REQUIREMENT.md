### 需求介绍
+ 右侧 Sidebar 的“备忘录元数据”列表及其居中“备忘录配置预览”浮层，需要与任务明细浮层采用一致的悬停保持和编辑语义：
    + 鼠标悬停任一备忘录元数据时展示对应居中浮层；鼠标离开来源元数据或浮层本体后，不得立即关闭，而是统一等待固定 `500ms`。
    + 在 `500ms` 内重新进入同一元数据或进入对应浮层本体，必须取消关闭计时并继续展示；直接移到另一条元数据时，浮层必须立即切换为新元数据内容。
    + 编辑态期间，浮层固定归属当前元数据：鼠标移出来源与浮层范围、悬停其他元数据、列表刷新都不得自动关闭或覆盖未保存草稿；只有保存成功或取消编辑后，才恢复普通的 `500ms` 悬停关闭语义。编辑态浮层必须升级为全页交互锁：浮层卡片自身的输入、保存、取消与 Esc 可用，卡片外背景全部不可点击。
    + 元数据浮层标题右侧操作区需为所有实际展示的备忘录元数据提供无文字编辑小图标，位置、尺寸、热区、主题适配、hover/focus 状态及无障碍文案与任务明细浮层的编辑图标保持一致。
    + 点击编辑图标后，原位置替换为保存和取消两个小图标；保存进行中两个图标不可重复操作。点击取消或编辑态按下 `Esc` 必须等同：恢复进入编辑前的完整快照、退出编辑态、保留浮层打开，且不得触发其他浮层的 `Esc` 行为。
    + 编辑态应复用任务明细编辑的时间、模型、Agent、Thinking、SWARM、校验和内容控件与校验规则；元数据额外允许编辑“周期”。Agent 下拉选项、默认值、必填校验和创建备忘录保持一致；元数据没有任务明细状态，状态位继续以只读占位展示。
    + 每次点击保存时，若所选 Agent 与当前已保存的 Agent 不同，必须先展示红色警示小浮层：红色警示框标题固定为“注意”，说明固定为“备忘录尚未启动的任务将切换至 $Agent”（`$Agent` 为目标 Agent 名称），操作区固定提供“取消”和“知道了”。点击“知道了”后只继续本次保存；点击“取消”只关闭提示并保留编辑界面和草稿，不得提交。后续任意一次再次点击保存，只要目标 Agent 仍与当前已保存的 Agent 不同，均必须重新提示；若已从 A 切换至 B 又切回 A，则保存时不提示。
    + 备忘录明细预览和备忘录元数据预览的标题操作区删除小图标必须在非编辑态与编辑图标同时出现、进入编辑态时同时隐藏。点击删除必须先收起当前预览，再复用右侧列表的既有确认交互：明细使用“确定忽略此任务？”确认框并展示模型、思考、状态，确认后走列表相同的忽略任务链路；元数据使用“确定删除此备忘录？”确认框并展示内容，确认后走列表相同的删除链路。
    + 周期控件必须沿用创建备忘录的重复周期视觉样式和同一组选项：仅一次、工作日、自然日、每小时、每15分钟、每30分钟。已有自定义 Cron 元数据在未切换周期时保持其原 Cron 表达式；选择任一标准周期后，按所选周期重新生成表达式。
    + 执行时间仍不得早于当前时间：编辑控件最早可选下一整分钟，前端保存校验与服务端更新接口都必须拒绝过去时间；自定义 Cron 且无起始时间时允许保持无起始时间。
+ 元数据保存必须通过受服务端保护的单一更新/重建接口完成，不允许前端组合多次删除/创建请求：
    + 新增 `POST /api/cron/meta/update?agentId=xxx`，请求接受 `metaId`、`agentId`、`rawTime`、`cycle`、`content`、`model`、`thinking`、`verify`、`router_disable`；Agent 切换必须经现有 Agent 校验后更新元数据及重建明细归属，不得接受或修改会话、任务类型、响应结构、已完成结果等历史字段。
    + 服务端需在一个事务中验证元数据归属和可编辑字段，更新当前 `task_meta`，删除该元数据下且仅 `started = 0`（待执行）的任务明细，并按更新后的元数据重新生成其待执行明细；不得删除或重建 `started = 1`、`2`、`3` 的明细。
    + 重建规则必须与创建备忘录一致：仅一次创建一个明细；工作日/自然日、每小时、每15分钟、每30分钟按现有未来窗口生成明细；重新生成的明细写入更新后的模型、时间、内容、Thinking、校验和 SWARM 配置。自定义 Cron 保留原表达式且不伪造标准周期明细。
    + 元数据更新、删除的待执行明细与新增明细均需记录现有审计日志；任一验证、更新、删除或重建失败时事务整体回滚，页面保留编辑草稿并显示失败原因。
    + 元数据保存提交和元数据删除二次确认后，页面必须显示全局不可交互的进度锁定层，直到对应服务端请求成功或失败才解除；锁定期间不得因点击遮罩、Esc、切换浮层或其他页面动作中断提交。元数据删除提示须明确其将一并删除该元数据创建的所有未完成备忘录明细任务。
    + 保存成功后以服务端返回的最新元数据回填当前浮层、退出编辑态并保持浮层打开；刷新元数据列表和受影响的任务明细列表。取消、前端校验失败或服务端保存失败都不得关闭浮层。
+ 兼容边界：
    + 任务明细浮层现有的 `500ms` 悬停、编辑、Esc 取消、时间校验、保存和任务启动竞态保护必须继续有效；元数据浮层不能抢占或破坏任务明细浮层及现有新手引导。元数据浮层仍在展示（包括其 `500ms` 关闭延迟）时，鼠标经过任务明细必须忽略任务明细浮层，不得替换、关闭或覆盖当前元数据浮层；只有元数据浮层真正消失后，任务明细悬停才可再次展示。
    + 元数据列表切换、Agent 切换、右侧栏收起、元数据被删除或浮层对应来源不再存在时，非编辑态必须取消旧计时并回收浮层；编辑态中的刷新只能同步后台列表，不能静默丢失当前草稿。

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，优先复用现有备忘录明细缓存、`rsMetaCenterPreview`、overlay 域管理、创建备忘录控件、既有前端校验、`scheduleRefreshCronViews()`、VFS Tips 与 cron 请求链路，避免实现第二套表单和浮层体系
    + 将当前悬停/编辑的明细或元数据 ID、关闭计时器、鼠标是否位于来源或浮层、编辑草稿和原始快照保存在页面运行时；不得写入 chat payload、`saveChats()`、`localStorage` 或 URL
    + 延迟关闭必须统一由可取消的计时器管理；所有切换、刷新、销毁和进入编辑态路径均要显式清理计时器，避免旧计时器误关闭新明细的浮层
    + 浮层从被动展示转为可接收鼠标和按钮事件时，需与现有 overlay 域状态管理显式兼容，确保浮层未激活时不拦截底层交互，激活时可稳定承接 `pointerenter` / `pointerleave` 和图标点击
    + 编辑表单的模型选项、开关联动、输入长度与必填校验必须调用或抽取自创建表单的单一实现；周期控件复用创建备忘录的重复周期样式与选项来源；禁止复制后形成两套规则
    + 前端刷新仅用于同步展示，保存结果和“任务是否已启动”的最终判定必须以更新接口响应为准；不得用悬停时缓存的 `started` 代替服务端条件更新
    + 代理层按既有 cron API 的 JSON 返回结构、Agent 校验、数据库访问、错误响应和元数据/明细日志方式实现更新重建接口，并补充正常更新、仅删除待执行明细、保留非待执行明细、周期重建、非法 Agent/元数据、字段校验失败与事务回滚的自动化测试
    + 编辑图标、保存图标、取消图标的 DOM 落位、显隐、禁用态、焦点顺序和 aria 文案必须稳定，禁止在不同状态下漂移出浮层标题操作区
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
