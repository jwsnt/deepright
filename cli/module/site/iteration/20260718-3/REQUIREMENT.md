### 需求介绍
+ `STOP` 是服务端持久化的 **Agent 级定时任务运行开关**，不是创建备忘录的参数，也不是任务元数据或任务明细的属性。
+ 创建职责与运行控制必须分离：
    + `POST /api/cron/create?agentId=...` 只创建元数据、Cron 表达式和任务明细；不得接收、写入或返回任何 `session_disable` / STOP 信息。
    + 不新增 `/api/cron/meta/{id}` 的 STOP 语义。该接口面向单条元数据，而 STOP 对象是 Agent，使用它会重新引入错误耦合。
    + 新增 Agent 级接口 `GET /api/cron/agent/stop?agentId=...` 与 `PATCH /api/cron/agent/stop?agentId=...`。`PATCH` 请求体为 `{ "enabled": true|false }`；响应返回 `agentId`、`enabled`、`updatedAt` 及用于恢复积压任务的服务端状态。
+ Agent STOP 状态必须独立保存在 cron SQLite 中，以 Agent ID 为唯一键。至少保存 `enabled`、最近开启时间、最近更新时间及恢复积压任务所需的游标/时间边界；Agent 删除时同步清理该状态。
+ 必须删除任务级 STOP 方案：
    + 前端创建 payload、cron 请求/响应模型、`task_meta`、`task_detail`、元数据编辑/重建、周期补充、执行日志和自动化测试中不得再出现 `session_disable`。
    + 新数据库 schema 不得定义该列；已有 SQLite 数据库须安全迁移并移除历史 `session_disable` 列，保留其他元数据、明细和执行状态。
    + STOP 的开启、关闭和同步不得改写任何任务元数据字段、任务明细字段、`started`、`chat_id` 或任务状态日志。
+ 定时执行语义：
    + 每轮扫描按 Agent 读取 STOP 状态；STOP 开启时，该 Agent 的待执行任务直接跳过，不进行 Agent/模型校验、不创建会话、不调用模型或上游服务，也不写入任务状态。
    + 被跳过的明细始终保持原始待执行状态；STOP 关闭后，仍须在后续扫描中被重新发现并按原流程执行。
    + 现有仅扫描最近一小时到期任务的窗口不得让 STOP 期间积压的明细永久遗漏。服务端须以 Agent STOP 的开启时间和恢复游标补偿该时间段内 `started=0` 且已到期的明细；补偿完成后恢复既有正常扫描窗口，避免把无关的历史失败任务一并执行。
    + 同一 Agent 的 STOP 变更采用服务端最后一次成功写入为准；执行器在一次扫描内使用一致快照，避免多浏览器并发切换产生半轮混合状态。
+ 前端与视觉要求：
    + 在右侧备忘录创建区的周期展示位置，以及备忘录列表底部左侧，均提供 `STOP` 小图标。两个入口展示并修改同一份当前 Agent 服务端 STOP 状态，不再作为当前备忘录草稿或创建请求状态，也不得保留第二份本地状态。
    + 图标关闭态使用页面现有浅色暖色系 / 深色冷色系中的中性低强调颜色；开启态使用暖色警示红并持续闪动。
    + 用户手动切换时，只有 `PATCH` 成功后才确认 UI 状态，并通过虚拟文件系统 Tips 提示“当前 Agent 的定时任务已开启/关闭 STOP”；失败时恢复服务端已知状态并显示错误提示。
    + 创建区的周期值与 `STOP` 复用同一展示区域：已显示周期文字（包括“仅一次”）时隐藏创建区图标条；周期文字为空时展示。备忘录列表底部左侧的 `STOP` 入口始终显示。隐藏仅影响展示，不得改变服务端 Agent STOP 状态。两处入口的状态、标题、禁用态和开启闪动必须同步；创建区周期槽位必须固定宽度并淡入淡出，禁止横向抖动。
    + 页面首次载入、切换 Agent、页面从后台回到前台时立即读取一次当前 Agent 状态。前台常规模式每 `15 秒` 轮询一次，节能模式每 `30 秒` 轮询一次；页面隐藏、无 Agent、请求在途时暂停重复请求。轮询结果仅更新图标，不弹 Tips；过期/乱序响应不得覆盖当前 Agent 的较新状态。
+ 执行时间校验：
    + 仅一次任务的已选日期/时间早于当前时间时，提交前自动归一为当前本地分钟，不显示“执行时间需要晚于当前时间”，确认框与创建请求必须使用归一后的时间。
    + 工作日、自然日、每小时、每 `15` 分钟、每 `30` 分钟及自定义 Cron 等周期任务不适用该归一规则；过去时间继续提示“执行时间需要晚于当前时间”并拒绝提交。
+ 范围与验证：
    + 沿用原始约束：飞书、邮件和连接类任务不受 STOP 影响；STOP 只阻止本地 `cron` 任务进入会话执行链路。
    + 验证创建接口不再携带或持久化 `session_disable`，任务元数据和明细 schema 中不存在该字段。
    + 验证 Agent A 开启 STOP 不影响 Agent B；A 的到期本地任务在开启期间保持 `started=0`、`chat_id` 不变且不触发模型调用；关闭后，STOP 期间积压的明细会被补偿扫描并执行。
    + 验证创建区与备忘录列表底部两个入口始终同步，并验证两处浏览器页面对同一 Agent 的状态在下一次低频同步后收敛，且节能/后台状态遵守轮询约束。
    + 验证仅一次任务选择过去时间时不提示错误、日期与时间均改为当前本地分钟并正常创建；验证周期任务的过去时间仍不提交。
