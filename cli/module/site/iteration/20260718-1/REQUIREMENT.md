### 需求介绍
+ 在右侧备忘录标题左侧、截图红圈所示的位置新增无文字的放大镜小图标，作为“备忘录查询”入口：
    + 图标的尺寸、热区、浅深色主题、hover/focus 效果和无障碍文案需与现有小图标体系一致；提供稳定的 `aria-label` 与 `title`。
    + 点击图标打开备忘录查询浮层；再次点击可将其收起为该放大镜图标。浮层的打开、关闭、Esc 和焦点处理必须纳入既有 overlay 域管理，不能影响日历、备忘录详情预览或其他浮层。
    + 查询浮层为固定高度的两段布局：上半段为查询条件，下半段为查询结果。浮层整体不得因条件或结果增加而撑高；结果区域占用剩余高度并独立显示纵向滚动条，条件区保持可见。
    + 窄屏时浮层高度可按可视区域收缩，但条件区和结果区的固定分区语义不变；横向内容不得遮挡右侧栏、日历或底部操作栏。

+ 查询条件以“元数据”和“任务明细”两个互斥维度组织：
    + 使用清晰的 tab 或等价单选切换；切换维度后只展示该维度的条件与结果，并保留两个维度各自已填写的条件、已加载结果和滚动位置。
    + 元数据维度的周期类型、原始时间起止、Agent、模型、状态共六个条件控件必须在同一行紧凑显示；任务内容与查询操作单独位于下一行。窄屏可按现有响应式规则折行，但不得遮挡控件。
    + 起止时间必须使用浏览器原生日期时间控件，并以分钟为步进；元数据周期类型不展示 Cron 和“仅一次”选项，元数据查询结果也必须排除“仅一次”任务。
    + Agent 下拉选项的实际值保留完整 Agent 标识；名称超过 10 个字符时，选项文字仅展示前 10 个字符及 `...`，并通过悬停提示提供完整名称。
    + 每次查询只检索当前维度：元数据结果对应 `task_meta`，任务明细结果对应 `task_detail`。不得在一个结果列表中混排两种记录；Agent、模型、状态、周期、时间和任务内容等多维条件必须由服务端参数化 SQL 组合筛选，前端不得为元数据状态再额外加载全量任务明细后筛选。
    + 所有已填写条件按 AND 组合，条件为空时不参与过滤；新增、删除或调整任意条件必须仅收窄或扩大当前维度结果，不能悄然重置其他条件。
    + 点击“查询”或在条件区按 Enter 后发起请求；条件变化只标记结果为待更新，不得为每个输入字符立即请求。查询按钮需要有进行中态，连续提交时取消或忽略前一个过期请求，确保后返回的旧响应不会覆盖新条件的结果。
    + 条件重置只清空当前维度的条件和结果显示；已缓存结果可保留，后续再次使用同一条件时优先命中缓存。

+ 元数据维度条件和语义如下：
    + 周期类型：使用创建备忘录时相同的重复周期选项与值来源，但不包含 Cron 和“仅一次”；空值表示任意重复周期。
    + 原始时间范围：支持开始和结束时间，范围两端均包含；开始不得晚于结束。仅比较元数据的 `raw_time`，不得用任务明细执行时间替代。
    + Agent：选项来自现有 Agent 列表，空值表示不限制；后端必须校验传入的非空 Agent 存在，禁止将未经校验的任意字符串直接作为查询范围。
    + 模型：使用现有模型标识，空值表示不限。
    + 状态：元数据不新增持久化状态字段。按关联任务明细的现有 `started` 状态筛选，即元数据命中当且仅当存在至少一条关联明细具有所选状态；状态值和文案复用现有 `0=待执行、1=已启动、2=无需启动、3=已完成` 映射。
    + 任务内容：支持模糊包含查询，去除首尾空白后按 `content LIKE '%关键词%'` 查询。

+ 任务明细维度条件和语义如下：
    + 执行时间范围：支持开始和结束时间，范围两端均包含；开始不得晚于结束。比较 `task_detail.exec_time`，统一使用页面和服务端既有的本地时区/时间格式转换规则。
    + Agent、模型、状态和任务内容分别匹配任务明细自身的 `agent_id`、`model`、`started` 和 `content`；空值表示不限。
    + 状态值与文案复用 `0=待执行、1=已启动、2=无需启动、3=已完成`，不得在查询模块另建一套状态口径。
    + 任务内容同样使用模糊包含查询 `content LIKE '%关键词%'`。

+ 查询服务与性能边界：
    + 扩展既有 `POST /api/cron/detail/metadata` 与 `POST /api/cron/detail/list` 查询链路，不新增与旧接口语义重叠的查询端点。两个接口分别支持当前维度的筛选字段、`limit` 和游标/页码，并在响应中返回稳定的下一页标记；不得通过现有无上限列表接口一次性拉取全部历史记录。
    + 首页默认最多返回 `50` 条，单次 `limit` 最大 `100` 条；后续页仅在用户滚动接近列表底部时请求。服务端须拒绝零、负数、非数字和超过上限的分页参数。
    + 元数据结果按原始时间倒序、ID 倒序；任务明细按执行时间倒序、ID 倒序。分页边界必须稳定、无重复、无漏项；列表滚动接近底部时可继续加载下一页，已加载项目在浮层内滚动展示。
    + 查询必须使用参数化 SQL。内容模糊查询中的 `%`、`_` 和转义字符按字面量处理，防止通配符扩大结果范围；所有时间、周期、状态、分页参数和排序方向均需服务端校验，排序字段不得由页面自由传入。
    + 为元数据的 Agent/周期/原始时间、模型/原始时间，任务明细的 Agent/状态/执行时间、模型/执行时间及关联 `meta_id`/状态建立或复用适配 SQLite 的索引；包含式内容查询必须在其他已填条件已缩小范围后执行。
    + 元数据状态筛选使用关联明细的 `EXISTS` 或等价去重查询，禁止 JOIN 后因一条元数据存在多条同状态明细而在列表中重复出现。
    + 查询实现需要通过 `EXPLAIN QUERY PLAN` 或等价自动化断言验证：带 Agent、时间/状态和内容模糊条件的查询先使用范围筛选索引；无条件查询始终受分页上限保护。
    + 结果响应只返回列表所需字段和预览所需的完整单条字段；不得在每一行重复携带无关的关联明细集合或大型结果内容。单条预览如未随结果返回完整数据，可按记录 ID 懒加载。

+ 结果列表与预览：
    + 结果使用带固定表头的表格呈现，预览按钮固定为首列。元数据表头依次展示预览、周期、时间、模型、思考、SWARM、校验、Agent、状态和任务内容；任务明细表格使用相同属性但不展示周期列。时间必须完整显示；任务内容仅展示前 10 个字符，剩余内容以 `...` 省略并可通过 `title` 或预览查看完整内容。表格不得出现横向滚动条，结果区保留独立纵向滚动条且表头保持可见。
    + 每行固定保留一个无文字的预览小图标，不因状态或内容长度改变位置。点击后打开对应的备忘录预览浮层，预览中展示该记录已有的完整配置与内容；任务明细预览还需展示执行结果（如有）。
    + 打开预览时，查询浮层不得销毁或清空：它应最小化回放大镜图标的运行时状态，保留当前维度、条件、结果、分页游标和滚动位置。关闭预览后，用户点击放大镜即可恢复原查询浮层，而不应重复请求已缓存页面。
    + 预览、查询浮层和日历/列表中的既有备忘录预览复用同一套预览数据格式、关闭语义和 overlay 管理，避免并存两套不一致的预览组件。
    + 加载中、无匹配、请求失败和继续加载失败必须在结果区域给出明确状态；失败不得清除最后一次成功结果，重试仅重试当前条件和失败页。

+ 查询缓存与本地存储：
    + 按“维度 + 规范化后的全部条件 + 排序 + 分页游标 + 当前数据版本”生成稳定缓存键；缓存内容仅包含已返回的查询页、总数/是否还有下一页、缓存时间和必要的预览数据，严禁缓存 DOM、事件对象、密钥或聊天 payload。
    + 查询浮层关闭后再次打开时，当前条件与结果保留 5 分钟，不得因打开动作删除或重新请求。用户主动点击“查询”时必须绕过缓存，立即向服务端刷新当前条件的结果；缓存有效期固定为 `5` 分钟，最多保留 `100` 个查询页，采用有限容量的 LRU 策略并记录缓存时间。
    + 备忘录创建、更新、删除、任务状态变化、当前 Agent 列表变化或手动刷新备忘录视图后，必须失效受影响 Agent/记录的查询缓存及其预览缓存；无法精确定位影响范围时宁可清空备忘录查询缓存，不得继续展示过期数据。
    + 持久化查询缓存必须进入现有本地存储容量预算和压缩/紧凑化流程：配额检查、自动压缩、写入失败处理与清理策略均复用现有机制，禁止新增一个绕过压缩和配额维护的未压缩 `localStorage` key。触发本地存储压缩或配额维护时，必须第一优先级完整清空备忘录查询缓存，之后才允许压缩会话历史；不能删除用户设置。
    + 本地存储统计浮层顶部摘要区（截图红框）新增“备忘录查询缓存”卡片，展示缓存压缩后的实际占用空间、占总本地存储比例，以及缓存条目数。总存储、剩余空间和告警判断均须将该缓存计入；刷新统计后数值与实际持久化 key 一致。
    + 缓存被淘汰、失效或清空后，统计卡片、总占用和剩余空间必须同步更新。缓存统计不得把运行时内存缓存重复计算为本地存储占用。
    + 会话明细中的高亮必须标记会话存储用量最大的行，不得因当前激活会话或最小用量而高亮错误行。

+ 兼容与验收边界：
    + 查询、缓存、预览与统计不得中断 SSE、聊天滚动、日历选择、备忘录创建/编辑/删除、右侧 CLI 子面板及新手引导。引导锁定备忘录区域时，查询入口和浮层遵循引导优先级。本地存储统计和备忘录查询浮层必须纳入现有节能模式，开启节能后关闭其模糊等高能耗视觉效果。
    + 条件区与结果列表中的所有可操作元素均可通过键盘访问，有清晰焦点态；图标按钮均有可读的无障碍名称。
    + 至少覆盖以下自动化验收：两维度独立保留条件；各字段单独筛选与多条件 AND；时间范围边界；元数据状态的关联明细筛选和去重；内容模糊包含匹配与通配符转义；分页稳定性；缓存命中、失效、过期和压缩时的第一优先级清空；预览打开后查询浮层最小化并可恢复；结果列表滚动加载；统计卡片、总空间和缓存清理后的数值一致；索引查询计划满足性能约束。
