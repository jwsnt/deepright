# 20260706-4 用户手册

本次迭代为 `Thinking` 模式补充了“目标校验”联动能力。现在在居中对话输入框、右侧备忘录输入框，以及邮件 / 飞书插件浮层里，只要把思考模式从 `Auto` 切到 `Thinking`，都会立即询问是否同时开启目标校验。

## 触发方式

- 居中输入框点击 `Thinking`，从 `Auto` 切到 `Thinking` 时，会弹出 `是否开启目标校验`
- 右侧备忘录输入框点击 `Thinking`，从 `Auto` 切到 `Thinking` 时，也会弹出同样确认
- 邮件、飞书等支持 `Thinking` 的插件配置浮层，在切到 `Thinking` 时同样会弹出确认
- 这个确认不是一次性引导，而是每次从 `Auto` 切到 `Thinking` 都会再次出现

## 确认后的效果

- 点击 `确认` 后，会在保留 `Thinking` 状态的同时开启目标校验
- 点击 `取消` 后，当前区域仍保持 `Thinking`，只是不开启目标校验
- 当后续再把 `Thinking` 切回 `Auto` 时，目标校验会一并关闭，不会单独保留

## 视觉反馈

- 开启目标校验后，`Thinking` 开关会切换为和协作按钮一致的暖色系
- 浅色模式和深色模式都会分别套用对应色系，不再沿用普通 `Thinking` 的默认蓝色表现
- 关闭目标校验后，开关会恢复普通 `Thinking` 外观

## 绑定范围

- 居中输入框的 `Thinking / 目标校验` 与当前 `ChatId` 绑定；不同会话各自独立
- 右侧备忘录的 `Thinking / 目标校验` 与当前备忘录配置绑定，不跟随居中会话共用
- 邮件、飞书插件浮层中的 `Thinking / 目标校验` 与各自插件配置绑定，彼此独立

## 请求与提交行为

- 居中会话发送消息时，会继续写入 `metadata.thinking`
- 只有在当前会话已开启目标校验时，才会额外追加 `metadata.verify=true`
- 如果没有开启目标校验，请求里不会携带 `metadata.verify` 字段
- 备忘录保存和邮件 / 飞书插件启动时，也会带上各自当前配置中的 `thinking` 与 `verify` 状态，保证执行行为和界面选择一致

## 典型使用方式

- 如果只是希望模型进入深度思考，但不需要目标校验，切到 `Thinking` 后点击 `取消` 即可
- 如果希望在深度思考时同时增加目标校验约束，切到 `Thinking` 后点击 `确认`
- 如果某个会话、备忘录或插件不再需要目标校验，直接把对应区域切回 `Auto`，或再次进入 `Thinking` 后选择不开启即可
