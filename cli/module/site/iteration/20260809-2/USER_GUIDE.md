# SSE 思考分组与完成判定

## 思考片段

原先页面用 `created` 组合思考片段标识。同一轮响应里的多个思考包可能共享这个值，因此会被合并为“思考 1”。

现在每个 SSE 包直接使用服务端提供的 `payload.id` 分组：相同 ID 的内容继续追加，不同 ID 的内容会触发原有爆炸收起效果，当前居中内容进入左上思考气泡，右侧思考列表显示为新的“思考 N”。实时 SSE 和页面刷新后的恢复展示采用相同规则。

CLI 子任务包（`biz=cli`、`workflow=sub`）只显示在右侧 CLI 子任务面板，不会进入居中正文或思考片段。正常 SSE 期间，面板只消费这类实时包，不会用 `/api/restore` 的 `cli/get` / `cli/pub` 补充或重复渲染。

页面刷新或 SSE 中断后的恢复才会读取 `cli/get` / `cli/pub`：前端从 `cli/get` 取得 `tid` 和 `subOps.echo`，在当前会话内按 `chatId + tid` 关联后续结果。`subOps.echo` 严格为 `false` 时不显示该 CLI 回显；任务仍会执行，`cli/pub` 仍会被消费，但不会补到任何可见命令。

## 完成状态

SSE 只有收到 `data: [DONE]` 才显示为正常完成。末行即使没有换行，只要内容为该标记仍会正常结束；其它 EOF 会显示连接中断，不会误显示为完成。
