### 需求介绍
+ 本迭代只调整 Site 对既有聊天 SSE 数据包、CLI 子任务和完成判定的前端展示；不得修改服务端接口，也不得修改恢复场景已有 `/api/restore` 的 URL、`chat`、`timeline`、`lastId` 参数或轮询间隔。
+ 原逻辑中，居中 SSE 与恢复解析会用 `biz + workflow + created` 组合生成中心逻辑 ID 和思考快照分组键。多个 `workflow=__sub` 包可共享同一 `created`，会被错误合并为同一个“思考 1”。
+ 现逻辑中，服务端保证每个 SSE 数据包均有 `payload.id`；居中 SSE、恢复解析、恢复记录的逻辑 ID 与思考快照分组键必须只使用该 `id`。不得使用 `created`、`biz`、`workflow`、前端段号或任意兜底键参与分组。
+ 同一 `payload.id` 的增量内容继续追加到同一思考片段；新的 `payload.id` 必须复用既有逻辑分支切换效果：当前居中 SSE 内容爆炸、清空并收进左上思考气泡，再开始渲染新内容。右侧思考列表据此显示多个“思考 N”。
+ 实时 SSE 与 `/api/restore` 对同一数据包必须采用完全相同的 `payload.id` 分组语义；恢复过程的居中爆炸/消除效果、左上思考气泡和右侧思考片段都必须与实时 SSE 一致。
+ `biz=cli && workflow=sub` 只属于右侧 CLI 子任务面板，不得进入居中 SSE 正文、思考气泡或右侧思考片段。`workflow=__sub` 等非 CLI 数据继续属于居中 SSE/思考展示，两条展示链路不得混用。
+ 正常实时 SSE 时，右侧 CLI 子任务面板只能消费当前聊天 SSE 内的 `cli/sub`，不得并发调用 `/api/restore`、读取 `cli/get` 或 `cli/pub` 来渲染。页面刷新、SSE 已断开等恢复场景，才由既有 `/api/restore` 返回的 `cli/get` 与 `cli/pub` 重建该面板。
+ `subOps.echo` 只控制 CLI 回显可见性：值严格为 `false` 时不在右侧 CLI 子任务面板渲染；字段缺失、为空或为 `true` 时正常渲染。无论值为何，任务仍须执行，`cli/pub` 仍须消费和推进状态。
+ 恢复时必须从同一条 `cli/get` 原始任务数据读取 `tid` 与 `subOps.echo`，以当前会话的 `chatId + tid` 保存任务可见性和完成状态；后续 `cli/pub` 只允许匹配该键。不得按“最近待完成命令”回退匹配，不得串会话，也不得把隐藏任务的结果补到可见任务。
+ SSE 只有接收到协议结束标记 `data: [DONE]` 才视为正常完成。最后一行没有换行但内容为该标记时仍须正常完成；其它 EOF 必须按连接中断处理，不得错误标记为完成。

### 编写代码

+ 必须复用既有逻辑分支切换、爆炸动画、思考快照和 CLI 气泡渲染能力，不得新增第二套渲染模式或外部依赖。
+ 删除实时 SSE 期间的 CLI 恢复轮询及其遗留渲染状态；不得保留未调用的轮询、最近待完成命令匹配或兼容回退代码。恢复请求与游标推进仍只服务于恢复场景。
