### 需求介绍

当当前系统缺少 `config.json.install_app` 指定的应用时，在 Site 的“最近”区域附近提示用户，并在用户确认后把安装请求自动发送到当前会话。

- 页面启动后必须异步执行一次应用检查；之后以服务端 `GET /install_app?details=1` 返回的 `interval` 分钟值为间隔继续检查。应用清单唯一来自 `config.json.install_app` 当前平台的数组，不接受 CLI 追加项；网络或响应异常不应影响页面其余功能，也不得把未知状态误显示为待安装应用。
- 详情响应中的 `apps` 非空时，用闪烁的安装小图标替换“最近”右侧原有的存储统计小图标；无缺失应用、正在冷却或检查失败时恢复原有存储图标。图标的可访问名称和提示应明确说明待安装应用。
- 点击安装图标后弹出确认浮层，显示全部待安装应用。取消按钮与 `Esc` 均取消，确认按钮与非组合键 `Enter` 均确认；快捷键只作为交互绑定，不得写进“取消”或“确认”按钮文案。点击浮层遮罩视同取消。
- 用户打开安装浮层后，无论最终取消还是确认，均进入一个 `interval` 的冷却期：冷却期间恢复存储统计图标、不再显示安装图标，也不因页面其它重绘提前再次提示；冷却结束后重新扫描。
- 确认时，将待安装应用按中文顿号 `、` 连接，并替换服务端 `content` 模板中的全部 `$namelist`，把结果写入当前会话输入框后自动发送。页面不直接调用系统安装命令。
- 没有当前会话、当前会话正在响应、Agent 不可用、未选择模型或模型密钥不可用时，不得发送请求，应沿用既有提示并保留浮层，供用户处理后重试。

### 编写代码
+ 以现有 site 页面技术栈在 `../../index.html` 最小范围实现；不引入新的构建流程、第三方依赖或持久化状态。
+ 兼容旧 `/install_app` 字符串数组响应，并优先使用带 `apps`、`interval`、`content` 的详情响应；无效扫描间隔按 `60` 分钟处理。
+ 保持既有存储统计、会话输入与发送、浮层互斥、全局 Esc／Enter、可访问性、低功耗调度及其它最近区域图标的行为不变。
+ 覆盖首次扫描、按配置周期刷新、缺失／无缺失图标切换、取消与确认的 Esc／Enter 行为、一个周期的冷却、模板所有占位符替换、自动写入并发送，以及错误状态不误提示的前端自动化测试。
