# Site 使用手册

## 简介

Site 是 DeepRight 的单页聊天界面，提供类似 Gemini 的对话体验，支持 SSE 流式响应、Markdown 渲染、多会话管理、深色/浅色主题切换。

## 部署

将 `index.html` 放入 Proxy 的静态站点目录（默认 `./site`），启动 Proxy 后访问：

```
http://127.0.0.1:9876/site/
```

或直接在浏览器中打开 `index.html` 文件本地使用。

## 首次使用

1. 点击左下角「设置」按钮
2. 选择 Agent（从 `/api/agentId` 接口加载）
3. 添加至少一组模型和密钥
4. 点击「保存」

- 如果当前浏览器第一次打开站点，且本地还没有任何 DeepRight 相关浏览器记录，页面会自动进入新手引导
- 新手引导会先高亮 `请选择 Agent` 选择框，并提示新手可以从 `DEF_AGENT` 开始，随后自动展开左侧栏并高亮 `设置`
- 打开设置后，会继续高亮 `模型与密钥`
- 引导还会继续高亮 `新建Agent`、左侧虚拟文件系统、虚拟文件系统中的 `新增` 和 `上传`
- 引导最后一步点击 `完成` 后结束；结束前，其它区域会被暗化且不可点击
- 设置面板底部左侧新增了一个 `新手引导` 总开关，默认显示 `✓`
- 这个开关现在采用“修改后需保存才生效”的语义：在设置里点成 `×` 或切回 `✓` 时，只会修改当前草稿；只有点击设置里的 `保存` 后，新状态才真正生效
- 如果把它保存成 `×`，后续所有 onboarding 都不会再触发；如果保存成 `✓`，后续 onboarding 才允许继续触发
- 大多数 onboarding 卡片右上角现在会显示一个 `×`，点击后会直接跳过当前整条引导；只有最后一步主按钮文案为 `完成` 时，这个 `×` 不显示
- 首次点击设置里任意模型的 `客户化配置` 小图标时，如果本地还没有“点击过客户化配置”的记录，页面会额外启动一条独立的客户化配置引导
- 这条客户化配置引导会依次高亮 `模型URL`、`快速响应`、`深度思考`、`多模态输入` 和 `多模态输出`
- 前四步按钮均为 `知道了`，最后一步按钮为 `完成`；在引导结束前，其它区域会被暗化且不可点击
- 首次点击设置中 Agent 的蜂群小图标时，如果本地还没有“点击过蜂群开关”的记录，页面会额外启动一条独立的蜂群引导
- 这条蜂群引导会依次高亮 `蜂群开关`、`Thinking`、`蜂群模型`、`蜂群描述`、`确认`、设置内小蜜蜂图标和中间输入区小蜜蜂图标
- 蜂群描述步骤会提示补充 Agent 的作用、需要的输入信息和预计输出内容，帮助蜂群更准确地调用
- 首次点击设置里的 `deviceId` 复制小图标，或当前 Agent 右侧的 `R` 小图标时，如果本地还没有“点击过远程 Agent 引导入口”的记录，页面会额外启动一条独立的远程 Agent 引导
- 这条远程 Agent 引导会统一从 `R 小图标` 开始，而不是从当前点击的入口原地开始；随后依次高亮 `外部设备连接面板`、`确认`、`设置保存` 和 `deviceId 复制小图标`
- 引导文案依次为“开启蜂群远程Agent。”、“填写远程Agent的唯一标识。”、“点击确认。”、“保存后让蜂群生效。” 和 “远程Agent点击此处获取唯一标识。”
- 前四步按钮均为 `知道了`，最后一步按钮为 `完成`；在引导结束前，这些入口只推进引导，不会执行真实的展开、确认、保存或复制动作
- 首次点击设置里的 `导入 Agent` 或 `导出 Agent` 按钮时，如果本地还没有“点击过导入/导出入口”的记录，页面会先启动一条独立的新手引导
- 这条引导会先高亮 `导出 Agent`，约 `2` 秒后自动切到 `导入 Agent`，并提示“导出或导入 Agent 配置，方便备份与协作。”
- 如果当前还没有已选中的 Agent，原本隐藏的 `导出 Agent` 按钮也会在引导期间临时显示；点击 `完成` 后恢复原状，并且在引导结束前这些导入导出入口只用于说明，不会立即执行真实导入或导出
- 首次点击中间输入区左上角的 `沙盒` 按钮时，如果本地还没有“点击过沙盒按钮”的记录，页面会额外启动一条独立的会话沙盒引导
- 这条会话沙盒引导会先高亮 `沙盒按钮`，随后自动展开 `会话沙盒` 浮层，并依次高亮 `目录权限`、`离线执行` 和 `双重限制`
- 引导文案依次为“会话沙盒用于控制系统命令执行权限。”、“目录权限控制可读写文件范围，防止误删。”、“离线执行保证系统命令执行处于无网状态。” 和 “双重限制同时控制文件和网络权限。”
- 前三步按钮均为 `知道了`，最后一步按钮为 `完成`；在引导结束前，这些沙盒入口只用于演示说明，不会立即切换真实沙盒模式
- 首次点击左侧插件按钮时，如果本地还没有“点击过插件按钮”的记录并且当前存在可用插件，页面会额外启动一条独立的插件引导
- 这条插件引导会依次高亮 `扇形插件菜单`、`第一个插件图标`、`插件浮层`、`插件启动按钮` 和 `插件日志按钮`
- 当任意插件第一次真正启动成功时，如果本地还没有“插件启动成功引导”的记录，页面会额外启动一条独立引导
- 这条引导会自动展开左侧扇形插件菜单，并同时高亮已经变成绿色的插件开关和展开后的插件区域，提示 `插件启动成功后图标会变为绿色。`
- 首次点击虚拟文件系统里 `SOUL.md` 或 `USER.md` 的任意位置时，如果本地还没有“点击过 SOUL.md / USER.md”的记录，页面会额外启动一条独立的文档整理引导
- 这条文档整理引导会优先依次高亮 `SOUL.md 文件行`、`SOUL.md 小灯泡`、`USER.md 文件行` 和 `USER.md 小灯泡`
- 如果当前不存在 `SOUL.md`，引导会直接从 `USER.md` 开始；如果当前不存在 `USER.md`，则会在 `SOUL.md` 相关步骤结束后直接完成
- 首次打开（非悬停）虚拟文件系统中的 `mcp.json` 时，如果本地还没有“打开过 mcp.json”的记录，页面会启动一条独立的 MCP 配置引导
- 这条引导会高亮 `mcp.json` 文件，并提示“用于配置MCP服务（可选）。”；除引导卡片和 `完成` 按钮外，页面其它区域会被暗化且不可点击
- 点击 `完成` 后引导关闭，`mcp.json` 会在后续实际打开时恢复正常行为；这条记录与首次使用及其它新手引导分别保存、互不影响
- 首次把鼠标移入左侧虚拟文件系统的文件目录展示区域，或首次点击这个区域时，如果本地还没有“点击过/悬停过虚拟文件系统文件目录展示区域”的记录，页面会额外启动一条独立的拖拽上传引导
- 这条拖拽上传引导会先高亮整个文件目录展示区域，提示“将系统文件或目录拖入虚拟文件系统即可自动上传”，点击 `知道了` 后会继续播放一段模拟鼠标拖拽文件进入虚拟文件系统的动画，并提示“拖入文件，开始上传。”
- 动画播放期间左右侧和中间区域都会继续被暗化且不可点击；动画结束后才会显示 `完成` 按钮，关闭后恢复正常交互
- 首次点击右侧边栏第一栏中的备忘录日历、任务明细或备忘录元数据区域时，如果本地还没有“点击过右侧备忘录区域”的记录，页面会额外启动一条独立的备忘录引导
- 这条备忘录引导会依次高亮 `备忘录区域`、中间输入区的 `当前 Agent 展示区域`、`复用当前会话`、中间对话区的 `响应区域`、`模型选择`、`SWARM + Thinking`、`时间选择`、`仅一次`、`其他周期选项`、`创建按钮`、`备忘录列表按钮`、`模拟测试任务`、`模拟重置按钮`、`已完成任务明细`、`待执行任务明细删除按钮` 和 `已完成任务明细查看按钮`
- 如果当前 Agent 名称在中间输入区被截断，引导会额外显示一段完整名称的高亮提示动画
- 引导中的 `测试任务`、`已完成测试任务明细` 和 `待执行测试任务明细` 都只用于演示，不会写入真实数据；点击最后一步 `完成` 后会立即清理这些模拟内容
- 当备忘录新手引导已经完成、且至少已配置一个模型后，第一次把鼠标悬停到右侧备忘录输入框，或第一次点击该输入框时，页面会额外询问一次“是否需要试试备忘录？”
- 如果选择 `是`，页面会在右侧备忘录区域模拟输入 `推荐下我明天的着装风格`、选择首个已配置模型、设置为当前时间 1 分钟后并点击提交；动画会直接帮助用户创建这条备忘录任务
- 如果提交失败，引导结束后会恢复原来的备忘录草稿状态；如果提交成功，则保留提交后的界面结果
- 当右侧备忘录第一次成功创建 `非仅一次` 的周期任务时，如果本地还没有“首次周期备忘录创建引导”的记录，会额外启动一条独立引导
- 这条引导会依次高亮 `备忘录列表按钮`、刚创建的 `周期备忘录元数据`、中间会话区里的 `元数据预览浮层`、左侧日历下方的 `任务明细列表`，最后再回到这条元数据的 `删除按钮`
- 引导文案依次为“点击查看备忘录元数据列表。”、“鼠标悬停查看备忘录原数据。”、“核对周期性备忘录任务。”、“周期性备忘录会定时创建子任务。”和“删除周期性备忘录时也会删除子任务。”
- 当右侧备忘录任务明细里第一次出现 `已完成` 任务、且当前任务明细列表总数正好只有 `1` 条时才会触发这条独立引导；这里的总数会把其它状态的任务也一并算入，且本地还不能已有“已完成任务引导”记录
- 这条引导会依次高亮 `唯一一条已完成任务明细`、悬停中的 `任务明细行`、中间会话区的 `备忘录任务明细预览`、该任务的 `放大镜查看按钮`，随后进入两段无文案的过程动画，最后切到中间会话区的 `备忘录任务响应区域`
- 引导会自动滚动到对应已完成任务，先模拟鼠标悬停查看任务明细，再高亮预览浮层与放大镜按钮；随后会先模拟点击放大镜唤起右下角确认浮层，再模拟点击 `查看` 恢复会话结果，帮助用户理解如何查看备忘录任务结果
- 首次点击右侧边栏 `CLI` 子面板中的任意元素时，如果本地还没有“点击过 CLI 子面板”的记录，页面会额外启动一条独立的 CLI 引导
- 这条 CLI 引导会依次高亮模拟 `ls` 命令、模拟命令的 `终止按钮`、模拟命令的 `复制按钮` 和 `CMD` 执行按钮，分别讲解命令展示、终止预期外命令、重复执行命令以及执行自定义系统命令
- 右侧边栏 `CLI` 子面板标题栏中的 `CMD` 按钮右侧新增了一个展开按钮；点击后系统指令区域会占满整个右侧边栏，再次点击恢复原来的上下布局
- 该展开态只作用于右侧边栏，不会覆盖主页面，也不会进入浏览器原生全屏
- 系统指令展开态与知识库 `WIKI` 展开态互斥：任一面板进入展开态时，另一个面板会自动恢复常态
- 系统指令展开态只保存在当前页面运行时；切换会话、收起右侧边栏或刷新页面后都会自动恢复常态
- 当系统指令面板已经处于展开态时，新的系统日志继续流入不会打断当前展开态；空态下同样支持展开
- 首次在 `浏览器` 插件浮层里点击 `重启` 按钮时，如果本地还没有“点击过浏览器插件重启按钮”的记录，页面会额外启动一条独立的浏览器插件重启引导
- 这条浏览器插件重启引导会先高亮 `重启` 按钮，提示“浏览器插件与Chrome共享Cookie，无需重复登录”，随后再高亮 `headless` 参数区域，提示“默认使用无感模式，填写TRUE或true开启有感模式”
- 点击最后一步 `完成` 后才会恢复真实的重启行为；在引导期间，插件浮层中的其他区域都会被暗化且不可点击
- 首次点击左侧快捷菜单旁的 `初始化浏览器实例` 小绿点时，如果本地还没有“点击过初始化浏览器实例”的记录，页面会额外启动一条独立的新手引导
- 这条引导会先提示 Windows 需要手动登录网站获得权限，再模拟一个带地址栏的 Chrome 浏览器并展示 `http://example.com`，随后高亮闪动登录警示框，分两行提示“在自动新建的空白浏览器中依次在地址栏输入网址并登录。”和“首次启动时请耐心等待。”；进入“正在进行浏览器插件登录”这一步后，会先高亮整个浮层，再用约 `2` 秒过渡高亮到 `完成` 按钮，最后补充“不同会话间登录状态隔离”的提示；整条引导结束前不会真的执行初始化浏览器实例
- 浏览器插件第一次真正开始初始化时，页面会额外锁定整个界面，并提示首次初始化需要等待 `1` 至 `2` 分钟；初始化成功后才会继续原来的启动流程
- 当居中对话框第一次识别出可操作的文件路径或图片 URL 时，如果本地还没有“文件 URL 操作引导”的记录，页面会额外启动一条独立的新手引导
- 这条引导会直接高亮识别出的目标区域和对应动作浮层；如果这次目标来自 assistant 响应，则会围绕 assistant 行内小气泡展开，不再要求先双击或框选文本
- 引导会展示当前目标可用的 `预览`、`下载文件`、`打开目录` 等动作，并提示 `文本文件或图片可以通过预览进行编辑。`
- 引导进行期间，其它区域会被暗化且不可点击；如果触发时正有其它引导进行中，会等待当前引导结束后再自动补播
- 如果居中对话框的 SSE 响应区在当前一轮响应里首次收到 `choices[0].metadata.__WARN__` 非空的报文，页面会额外启动一条独立的新手引导
- 页面会高亮当前会话最新的荧光红色 retry 提示，提示“这类错误通常是模型配置引起的。”；默认提示会落在最后一个 assistant 气泡底部 footer 槽位，如果当前报文的 `choices[0].metadata.__TARGET__` 是非空标记，则会改为落在当前等待响应的 assistant 气泡内侧左下，并与右侧时间保持同一水平线
- 点击第一步的 `知道了` 后，会自动打开设置、展开当前 Agent 正在使用的模型客户化配置区并展示密钥；第二步会提示 `确认模型配置。`
- 再点击第二步的 `知道了` 后，会把高亮切到中间输入区的 `终止` 按钮；第三步提示 `如果模型配置错误，点击终止后重新执行。`
- 首次在 `远程` 插件浮层里点击 `重启` 按钮时，如果本地还没有“点击过远程插件重启按钮”的记录，页面会额外启动一条独立的远程插件重启引导
- 这条远程插件重启引导会只高亮 `重启` 按钮，并提示“远程插件提供 SSH 操控远程主机的能力”；点击 `完成` 后才会恢复真实的重启行为
- 首次点击输入框左上角的 `全屏` 按钮时，如果本地还没有“点击过全屏按钮”的记录，页面会在成功进入浏览器全屏后额外启动一条独立的全屏引导
- 这条全屏引导会先高亮左侧菜单控制按钮持续约 `2` 秒，然后自动切到右侧菜单控制按钮，并提示 `全屏状态下会保留左右菜单当前的展开状态。`
- 最后一步会提供一个 `完成` 按钮；在引导结束前，左右侧和中间区域的其他位置都会继续被暗化且不可点击
- 首次点击右侧边栏 `知识库WIKI` 区域中的任意元素时，如果本地还没有“点击过知识库WIKI区域”的记录，页面会额外启动一条独立的知识库引导
- 这条知识库引导会依次高亮 `知识库整个区域`、`展开知识库全屏按钮` 和 `整理知识库按钮`，分别讲解知识自动归档、全屏展开和主动整理
- 首次点击右侧边栏 `知识库WIKI` 标题栏中的 `自动` 开关时，如果本地还没有“点击过自动整理开关”的记录，页面会额外启动一条独立的自动整理引导
- 这条自动整理引导会只高亮 `自动整理` 开关，并提示“知识库会自动整理，点击关闭后切换为手动模式”；点击 `完成` 后才会恢复该开关的真实切换能力
- 首次在居中输入框或备忘录输入框通过 `@` 选择 `__internal_token`，且当前选中的模型已经配置了可用密钥时，页面会额外启动一条独立的技能引导
- 这条引导会在居中输入区询问 `需要了解__internal_token如何使用吗？`；`Enter` 等同于点击 `是`，`Esc` 等同于点击 `否`
- 点击 `是` 后，居中输入框会自动用技能气泡样式插入 `[SKILL:__internal_token]`，继续补全 `给我几个用自然语言描述[SKILL:__internal_token]的案例`，随后自动发送这条示例消息

- 这条代理安全引导会固定显示在 `模型URL` 输入框上方，并提示“注意数据安全，谨慎使用三方代理。”；点击 `完成` 后才会恢复其它区域交互

- 这条模型客户化配置引导、远程 Agent 引导、会话沙盒引导、CLI 引导、浏览器插件重启引导、浏览器实例初始化引导、文件 URL 操作引导、远程插件重启引导、知识库WIKI引导、自动整理引导、`__internal_token` 技能引导、Skills 文件错误修复引导、代理安全引导、虚拟文件系统拖拽上传引导、右侧 iframe 预览引导、“插件启动成功后图标变绿”引导和“切换模型后上下文仍生效”引导都和首次使用引导、首次点击输入框引导、蜂群引导、插件引导、`SOUL.md / USER.md` 引导、右侧备忘录引导、Skill 提炼引导相互独立，可以兼容共存

- 如果左侧 Sidebar 当前处于收起状态，且页面本地还没有配置任何模型，那么点击输入框、点击模型选择入口或直接发送消息时，左侧 Sidebar 会自动展开，方便直接进入 `设置` 补充模型和密钥

## 功能说明

### 会话沙盒

- 输入框左上方、全屏按钮左侧提供一个 `沙盒` 按钮
- 如果本地还没有“点击过沙盒按钮”的记录，第一次点击这里不会立刻切换沙盒，而是会先进入独立的新手引导
- 这条引导会先高亮 `沙盒按钮`，点击 `知道了` 后自动展开 `会话沙盒` 浮层，再依次讲解 `目录权限`、`离线执行` 与 `双重限制`
- 在引导完成前，这些入口只用于演示说明，不会立即切换真实沙盒模式；点击最后一步 `完成` 后才恢复正常交互
- 按钮与当前 `Chat` 会话绑定；切换会话后会自动请求 `/api/sandbox_status?chatId=yyy` 刷新状态
- 即使当前未选中 `agentId`，只要存在 `chatId` 也会恢复当前会话沙盒状态
- 点击按钮后会在中间会话区弹出居中的模式浮层，支持 4 个操作：
  - `目录权限`：调用 `/api/sandbox=filepick?agentId=xxx&chatId=yyy`
  - `离线执行`：调用 `/api/sandbox=net?agentId=xxx&chatId=yyy`
  - `双重限制`：调用 `/api/sandbox=filepick_net?agentId=xxx&chatId=yyy`
  - `关闭沙盒`：调用 `/api/sandbox=off?agentId=xxx&chatId=yyy`
- 前端不需要区分平台；后端会自动在 macOS 走原有 `CLI_SANDBOX.app`，在 Windows/WSL 走新的 WSL `bubblewrap` helper
- 同一 `chatId` 下即使切换不同 `agentId`，沙盒按钮高亮、浮层模式和更新时间也会保持一致
- 只要当前会话存在有效沙盒模式，按钮就会高亮；关闭后恢复灰色
- 浮层会显示当前选中的 Agent、会话 ID、最近更新时间与当前模式名称；其中 Agent 仅用于展示，不参与沙盒状态定位
- 浮层右上角提供叉按钮关闭，按 `Esc` 也会直接关闭，不再单独保留底部 `取消` 按钮
- 如果目录授权被取消，会在 `会话沙盒` 标题下方左对齐显示红色提示，但不会把下面的绑定信息和操作按钮挤动

### 浏览器全屏

- 中间会话框左上方新增了一个小型全屏图标，位置在输入框左侧小地球图标的正上方，并与右侧 `SWARM / HTML / Auto` 开关保持同一水平线
- 非全屏状态点击该图标后，页面会进入浏览器全屏，并立即收起左侧 Sidebar 和右侧 Sidebar，让中间会话区直接铺满视野
- 如果这是当前浏览器第一次点击这个全屏图标，进入全屏后还会自动播放一条简短新手引导：先高亮左侧展开按钮约 `2` 秒，再切到右侧展开按钮，提示全屏模式下左右菜单会自动收起
- 全屏状态再次点击该图标后，会退出浏览器全屏；退出时不会额外改动左右侧边栏当前状态
- 如果通过浏览器原生方式退出全屏，例如按 `Esc`，页面上的全屏图标状态也会自动同步恢复
- 如果当前浏览器不支持全屏模式，点击时会提示失败原因，不会影响原有对话功能

### 关闭应用按钮

- 左侧边栏底部 `关闭应用` 按钮左侧新增一个 `单机 / 协作` 切换按钮；协作态按钮为金色
- 当前服务处于协作模式时，按钮显示 `协作`；点击后会调用 `/api/standalone=true`，把当前 `--port` 端口上的全部 HTTP 服务切换为仅本机访问
- 当前服务处于单机模式时，按钮显示 `单机`；点击后会调用 `/api/standalone=false`，重新允许其他 IP 访问当前 `--port` 端口上的全部 HTTP 服务
- 这个切换按钮只在通过 `localhost` 或 `127.0.0.1` 打开站点时显示；切换过程中按钮本身会播放加载动画，页面不会再弹出额外 Tips 提示
- 如果浏览器本地还没有任何单机 / 协作切换记录，第一次点击这个按钮会先弹出独立的新手引导：高亮 `协作` 按钮，在居中的引导卡片里用动画输入当前协作访问的 HTTP 地址，并提示 `协作模式允许通过浏览器进行内网团队合作，但请注意数据安全。`
- 这条引导只用于说明协作访问方式，不会真的修改当前端口的访问模式；在当前页面点击引导卡片里的 `完成` 后，再次点击按钮才会执行真实切换
- 左侧边栏底部 `设置` 按钮右侧新增了一个独立的关闭应用按钮，也只在通过 `localhost` 或 `127.0.0.1` 打开站点时显示
- 点击后会先显示一个整窗居中的关闭应用确认浮层，并模糊背景
- 确认浮层包含 `关闭应用` 和 `取消` 两个按钮，其中 `关闭应用` 绑定回车，`取消` 绑定 `Esc`
- 点击 `关闭应用` 后才会进入关闭应用动画，并显示 `5` 秒倒计时
- 动画开始后，页面会立刻请求 `/api/shutdown`
- 倒计时结束后，页面会主动关闭当前窗口，并绕过原有的离开页面确认提示
- 进入关闭应用动画后不支持取消；再次点击按钮也不会重复发起第二次关闭应用请求

### Token 用量浮层

- 左侧边栏左上角的 `logoSvg` 会根据任务状态在两种图标之间切换：
  - 无任务时显示为慢速闪动的报表小图标
  - 开始执行任务后切回原来的默认图标
- 无论当前显示的是哪一种图标，点击它都会在中间会话区弹出 `Token 用量` 浮层
- 浮层默认使用最近 `7` 天到当前时刻作为查询时间范围，`最大记录条数` 默认为 `500`
- `最大记录条数` 的上限同样是 `500`，超过时页面会直接拦截
- 浮层打开后会立即自动请求 `/api/consume?starTime=...&closeTime=...&limit=...`
- 查询参数支持直接修改 `开始时间`、`结束时间` 和 `最大记录条数`；如果手动清空，再次查询时仍会回退到默认值
- 每次开始查询后，浮层会进入锁定态并显示加载遮罩；查询完成前不会响应关闭或其他区域点击
- 查询结果支持四个切换视图：`原始记录`、`按 Agent 汇总`、`按 Agent + 模型汇总`、`按 Agent + 用途汇总`
- `按 Agent 汇总` 会按响应明细中的 `agentId` 聚合，并按单行百分比展示 `thinking / total`、`input / total`、`cache / total`，同时显示 `TOTAL / 1000` 后以 `k` 结尾的数值
- 汇总时完全以接口返回的 `agentId` 为准；即使当前 Agent 已经被删除，历史数据仍会继续显示
- `按 Agent + 模型汇总` 会按 `agentId + model` 维度聚合成滚动列表，每行一条，展示格式与 Agent 汇总一致
- `按 Agent + 用途汇总` 会按 `agentId + functionName` 维度聚合成滚动列表，便于区分同一 Agent 在不同用途上的 Token 消耗
- 原始日志明细会按一行一条展示时间、Agent、模型、用途和各项原始数值，不做百分比转换
- 浮层底部会显示本次查询使用的最大记录条数，以及原始记录数、Agent 汇总数、`Agent + 模型` 聚合数和 `Agent + 用途` 聚合数
- 浮层显示期间，中间会话区背景会同步毛玻璃模糊；点击浮层外任意非浮层区域即可关闭

### 本地存储统计浮层

- 左侧 Sidebar 的 `最近` 右侧新增一个统计小图标；点击后会在中间会话区弹出 `本地存储统计` 浮层
- 当前 origin 的本地存储总占用超过 `2.5 MB` 时，该图标会切换为红色告警状态；移回阈值内后恢复正常颜色
- 浮层内容完全基于当前浏览器当前 origin 下已经写入的 `localStorage` 做本地分析，不会额外请求服务端接口，也不会回退统计当前页尚未落盘的运行时状态
- 顶部第一排会用中文名展示总览数据：
  - `本地总占用`
  - `会话存储`
  - `最大会话`
- 下方改为单一的 `会话空间汇总` 列表，不再展示 key 明细、当前会话拆解或逐项诊断结论
- 每个会话都会显示：
  - 会话名称
  - 当前会话总占用
  - 几类汇总空间占比：`正文`、`快照`、`原始流`、`元数据`
- 这些占比全部以该会话已经落盘的 `localStorage` 占用为分母计算，目标是帮助快速判断“哪个会话最占空间、主要占在哪一类”，而不是查看逐条记录明细
- 浮层右上角提供关闭按钮，按 `Esc` 或点击浮层外空白区域也可以关闭；右上角 `刷新` 会重新按当前页面状态即时重算

### 设置

- 如果页面检测到没有可用模型或没有任何 Agent，会持续高亮左侧栏底部的 `设置` 按钮；点击这里完成配置即可消除提示
- **选择 Agent**：必填，从下拉框选择已配置的 AgentID
  - 切换 Agent 并保存时，如果右侧备忘录有未保存输入，将自动重置备忘录
  - 在设置中切换 Agent 下拉框时，右侧小蜜蜂图标和蜂群开关会同步切到该 Agent 当前已保存的蜂群配置状态，不再沿用上一个 Agent 的开启/关闭状态
  - 点击 `新增` 创建 Agent 时，只会创建该 Agent 对应的基础配置并切换下拉框选中项，不会自动展开蜂群配置面板
  - 如果当前 Agent 列表里存在可用 Agent，下拉框小三角左侧会显示一个复制小图标；必须先选中一个 source Agent 才能点击
  - 点击这个复制图标后，会复用新增 Agent 的同一行输入框，但确认按钮会变成 `复制`
  - 点击 `复制` 后，页面会先调用 `/api/agent/init?name=新名称` 创建 target Agent，再调用 `/api/copy?source_agentId=当前Agent&target_agentId=新名称`
  - 复制进行中会锁定中间界面；成功或失败后都会自动解锁
  - `/api/copy` 只会同步 source Agent 的 `app/`、`data/`、`skills/`、`SOUL.md`、`USER.md` 和知识库目录，不会覆盖 target 自己的 `config.json`
  - `新增 Agent` 小图标右侧新增 `导入` 和 `导出` 小图标
  - 如果本地还没有“点击过导入/导出入口”的记录，第一次点击 `导入` 或 `导出` 时不会立刻执行真实操作，而是会先在设置面板内播放一条独立引导：先高亮 `导出`，约 `2` 秒后切到 `导入`
  - 如果当前还没有已选中的 Agent，原本隐藏的 `导出` 图标会在这条引导里临时显示，方便理解入口位置；点击 `完成` 后会恢复原本隐藏状态
  - 点击 `导出` 后会请求 `/api/agent/export?agent_id=当前Agent`，浏览器会自动下载一个 zip，并提示 `Agent 配置已开始下载`
  - 导出的 zip 会保留顶层 Agent 目录，并自动过滤该 Agent 一级目录中的 `chrome*`、`data`、`tmp`
  - 点击 `导入` 后会弹出一个二选一浮层，可选择 `上传压缩包` 或 `上传目录`；选定后会调用 `/api/agent/import`
  - 导入成功后，Agent 下拉框会立即刷新并自动选中刚导入的 Agent
  - 如果导入目标与现有 Agent 重名，页面会直接提示先删除同名 Agent，不会覆盖现有目录
- 设置标题右侧新增一个慢速旋转的复制小图标；点击后会优先读取 Agent 共享元数据里的 `deviceId`，复制到系统剪贴板，并在左侧虚拟文件系统的 Tips 位置提示 `注意唯一ID的安全性`
- 首次点击这个 `deviceId` 复制小图标时，如果远程 Agent 引导尚未完成，不会立刻执行复制，而是先进入独立的新手引导
- 点击左下角 `设置` 后，会像扇形菜单插件浮层一样，只在中间会话区弹出水平垂直居中的面板，并带有同款背景模糊效果，不会遮挡左右 Sidebar 的可操作控件
- 在设置中的 `打开 Agent 目录` 按钮点击后，会先关闭设置浮层，再弹出中间会话区专属的目录确认浮层；浮层相对居中会话框水平垂直居中，带背景模糊，点击 `取消` 或浮层外任意空白区域即可关闭
- 输入框区域的 `打开 Agent 目录` 按钮会复用同一套目录确认浮层，但不会额外打开或关闭设置浮层
- 左侧虚拟文件系统中的 `打开目录` 按钮会直接打开当前目录，不会额外弹出设置浮层
- 设置面板底部左侧新增 `新手引导` 开关，默认显示 `✓`
  - 在设置里点击 `✓ / ×` 时，只修改当前设置草稿，不会立刻影响页面上正在进行或即将触发的 onboarding
  - 只有点击设置右下角 `保存` 后，新的 onboarding 开关状态才真正写入本地并生效
  - 点击 `取消` 或未保存关闭设置时，这次切换会被丢弃
  - 如果保存为 `×`，页面会立即停止当前 onboarding、清掉待播 onboarding，并阻止后续 onboarding 再触发
- **模型与密钥**：至少配置一组
  - 应用启动时会读取并缓存运行时 `config/config.json.provider`，页面通过服务接口使用该缓存；`deepright` 固定第一，其余可选模型取 `provider` 的 key 并按英文首字母排序。修改配置文件后需重启应用并重新打开页面。
  - 打开设置时，Agent 列表、provider 目录和已保存密钥会并行加载。
  - Agent 列表接口只读取 Agent 根目录的一级目录名，不会为加载下拉框扫描技能、知识库或插件状态。
  - 密钥：密码输入框，最长 250 位，点击小眼睛图标可切换明文/密文
  - 同一模型不可重复配置
  - 添加或修改模型时，当前已配置的其它模型会自动从下拉列表中移除；即使密钥错误，也不会重复出现在候选列表里
  - 每条模型记录在删除按钮前提供一个“客户化配置”小图标；每次重新打开设置时，这个补充配置区默认都保持收起
  - 如果本地还没有“点击过客户化配置”的记录，第一次点击任意模型的客户化配置小图标时，会先触发独立的新手引导，并依次讲解 `模型URL`、`快速响应`、`深度思考`、`多模态输入` 与 `多模态输出`
  - 点击客户化配置小图标后，会在该模型条目下展开补充配置区，再次点击会收起
  - 如果本地还没有“点击过模型URL”的记录，第一次点击任意模型补充配置中的 `模型URL` 输入框时，会先触发独立的代理安全引导，而不是立刻进入编辑
  - `deepright` 不显示客户化配置图标
  - 如果把一条已配置模型直接切换成 `deepright`，客户化配置图标会立刻隐藏；保存时还会一并清空原先残留的 `__url`、`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output`
  - 补充配置第一栏为模型 URL：`__url`
  - 模型 URL 可以留空以使用默认地址；填写时必须是无用户名和密码、带主机名的完整 `http://` 或 `https://` URL。输入框失焦时，非法输入会标红并在下方显示格式提示，且不能保存或测试
  - 补充配置第二栏为 5 个模型输入框：`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output`
  - 在任一可编辑模型输入框中填写模型名时，会自动补齐同一条配置中其余为空的可编辑模型输入框；已有内容和不支持的字段不会被覆盖
  - 仅当当前模型支持 `多模态输出` 时，这个输入框左上标题旁会显示一个带荧光蓝色小球的 `参数` 入口
  - 点击这个蓝色小球后，会先收起当前模型客户化配置区，再以动画展开一张独立的 `多模态输出参数` 面板
  - 这个面板会按 `Agent -> 模型服务商名 -> 属性集合` 保存配置，默认提供 `aspectRatio:16:9` 与 `imageSize:2K` 两行；允许继续追加更多英文 Key / Value
  - 保存时会自动去掉模型配置、模型 URL 和多模态输出参数值的头尾空格
  - 当参数名为 `aspectRatio` 时，参数值仅支持 `1:1`、`3:4`、`4:3`、`9:16`、`16:9`；当参数名为 `imageSize` 时，参数值仅支持 `1K`、`2K`、`4K`
  - `模型服务商名` 会直接使用当前模型下拉框里选中的名称写入 `media`，不再兼容或回退旧的 key 形式
  - 面板内 `Esc` 等同于点击 `取消`，`Enter` 等同于点击 `保存`
  - 面板保存时会立即通过 `/api/config?agentId=...` 与 `/api/edit?agentId=...&path=config.json` 写回当前 Agent 的 `config.json.media.<模型服务商名>`
  - 切换设置中的 Agent 后，这张多模态输出参数面板会自动重载新 Agent 的最新 `media` 配置
  - 当 `基础模型`、`快速响应`、`深度思考`、`多模态输入`、`多模态输出` 的输入内容超过输入框可见宽度时，把鼠标悬停在对应输入框上，会在该输入框下方浮出完整内容；鼠标移开后立即消失
  - 多模态输入与多模态输出现在是两条独立配置链路，不再共用旧的单一多模态字段
  - `token` 仍为必填；`__url`、`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output` 的默认值和是否可编辑均取自对应 provider 配置。字段缺失、非字符串或空字符串时会禁用编辑，保存时不会写入该字段
  - 同一时刻只会展开一条模型记录的客户化配置区，避免设置浮层内部出现多个重叠交互区
  - 页面会按 `provider` 配置自动带出默认值，并禁用所有不支持的字段
  - 如果当前模型已经存在任意客户化配置值，例如 `__url`、`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output` 中任一项被实际自定义过，但当前面板仍处于收起状态，则小图标会持续闪动提示
  - 每条已支持客户化配置的模型记录，在展开区右下角都会提供 `重置` 和 `清空` 两个按钮
  - 点击 `重置` 后，会把当前模型的 URL 和各模型字段恢复为该模型默认值，但不会清空密钥
  - 点击 `清空` 后，会清除当前模型的 URL 和全部扩展模型字段，但不会清空密钥；保存后再次打开也不会自动回填默认客户化配置
  - 点击模型删除按钮时，如果该模型已经保存在服务端，则会立即通过 `/api/config` 持久化删除，不需要等到整个设置面板再次点击保存
  - 以上远程访问限制只看当前页面是否通过 `localhost` 或 `127.0.0.1` 打开；即使当前服务处于“协作”模式，只要访问来源不是这两个本机地址，也仍然按远程访问规则处理
  - 当页面不是通过 `localhost` 或 `127.0.0.1` 访问时，接口读取到的已保存密钥会统一显示为 `**********`
  - 远程访问下，模型配置整体为只读：不允许新增、修改或删除；客户化配置展开后只可查看，不显示 `重置`、`清空`
  - 远程访问下，设置面板底部只保留 `取消`，不再显示 `保存`
- **蜂群配置**：通过 Agent 右侧的小蜜蜂图标展开
  - `Thinking` 开关固定显示在蜂群开关右侧，只控制当前 Agent 的蜂群配置，不再和当前会话输入框的 `Thinking` 联动
  - 支持通过小地球图标选择蜂群专用模型；模型只能从下拉中显式选择
  - 当蜂群处于开启状态时，模型和描述都为必填项；缺少任一项时不会保存
  - 当设置中新增、删除或修改模型条目时，蜂群模型下拉会立即刷新可选项
  - 如果当前蜂群配置引用的模型已被删除，蜂群模型标签会红色高亮并提示该模型不存在
  - 点击蜂群保存后，会把 `description`、`router_disable`、`thinking` 和 `provider` 一起写回当前 Agent 的 `config.json`，其中蜂群模型持久化在 `provider`
  - `router_disable=true` 表示关闭蜂群，`router_disable=false` 表示开启蜂群；页面展示名称仍保持为 `蜂群`
  - 如果本次把蜂群模型从旧值切换成新值，例如从 `deepseek` 改成 `deepright`，最终写回 `config.json.provider` 会以本次最新选择为准，不会再被旧配置覆盖回去
  - 首次点击设置中 Agent 的蜂群小图标时，会触发一条独立的蜂群新手引导；引导会固定在设置面板内部展示，不会被设置面板自身遮住
  - 引导切到设置内小蜜蜂图标时，会先关闭蜂群配置小面板，只高亮 Agent 右侧的小蜜蜂图标；切到中间输入区小蜜蜂图标时，会自动关闭设置浮层并在中间会话区继续引导
- **外部设备连接**：通过 Agent 右侧的 `R` 小图标展开
  - `R` 小图标与小蜜蜂图标使用同频旋转效果；再次点击 `R` 会收起面板，点击小蜜蜂图标会自动切回蜂群配置
  - 面板会在蜂群配置原位置展开，支持多行输入；每行只有一个输入框，最长 `50` 个字符，并提供小眼睛切换明文/密文显示
  - 面板内容区会在固定高度内滚动，不会把设置浮层整体撑高
  - 点击 `确认` 后只会先收起面板，真正持久化会和设置保存一起写回当前 Agent 的 `config.json.router_remote`
  - 首次点击 `R` 小图标时，如果远程 Agent 引导尚未完成，不会立刻展开面板，而是先进入独立的新手引导
- 点击保存后，模型与密钥会通过 `/api/token` 写入服务端 SQLite
- 已保存模型的删除动作通过 `/api/config` 单独持久化；保存按钮继续负责批量新增或更新当前剩余模型
- 模型保存成功后会锁定“选择模型”下拉框，不能再变更其模型服务商；如需改用其他服务商，请删除该模型配置后重新新增。
- 页面本地仅保存 `agentId`，不再把模型密钥落到浏览器 localStorage

Seedream 特殊说明：

- `seedream` 可以在设置里的 `模型与密钥` 中正常配置
- 但 `seedream` 不会出现在居中会话输入框的模型选择列表中，不能作为主聊天模型直接选择
- `seedream` 也不会出现在右侧备忘录输入框的模型选择列表中，不能作为备忘录执行模型直接选择
- `seedream` 同样不会出现在插件浮层的模型选择列表中，不能作为插件运行模型直接选择
- Seedream 的能力改为通过内部技能 `__internal_seedream` 暴露，而不是把 `seedream` 当成普通对话模型直接使用
- 这个内部技能只会在 Seedream 已完成可用配置时出现；未配置完成时，前端 `@技能` 菜单、后端 `/api/skills`、转发 `/v1/chat/completions` 的 `metadata.agents[].skills` 以及 `cli/get` 的 `metadata.agents[].skills` 都不会上报它
- 可用配置的判定以 `integration token --provider seedream` 为准：必须拿到可用 `token`，并且 `__url` 与 `__model_multi_output` 在显式配置或默认值补全后都有效

客户化配置默认值由 `config/config.json.provider.<模型>` 动态决定：

- `__url`、`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output` 的非空字符串值分别是模型 URL、基础模型、快速响应、深度思考、多模态输入和多模态输出的默认值。
- 字段未配置、不是字符串或为空字符串时，表示该模型不支持此项，页面会禁用该输入框。
- 删除某个 provider 后，其已保存密钥和客户化配置会保留在服务端但在页面隐藏；将 provider 加回配置文件并重启后，原配置会重新显示。
- 仅配置多模态输出且未配置基础模型的 provider 只能用于保存模型与密钥配置，不能作为普通会话、备忘录、插件或蜂群模型选择。

### 会话管理

- **新建会话**：点击左侧「新会话」按钮
  - 当会话数量达到 `10` 个上限时，会在中间会话区弹出与扇形菜单同域、同背景模糊效果的居中提示浮层，显示 `会话数量已达上限（10个）`；该提示只作用于中间会话区，不会遮挡左右 Sidebar
  - 该上限提示会复用中间会话区专属的 `center notice` 浮层样式与层级规则；未显示时保持彻底失活，不会额外拦截左侧或右侧区域点击
- **快捷扇形菜单**：左上角 `新会话` 按钮右侧紧贴新增一个即时通讯图标入口，`新会话` 按钮会自适应收缩
  - 点击后会展开浅色/深色模式均适配的扇形菜单
  - 如果本地还没有“点击过插件按钮”的记录，并且当前至少存在一个可用插件，第一次点击这里会先触发独立的新手引导；引导会自动展开左侧栏、展开扇形菜单，并依次带到第一个插件、插件浮层、启动按钮和日志按钮
  - 菜单项会通过 `/api/plugins/meta` 动态加载
  - 页面可见时会每 `30` 秒自动重新请求 `/api/plugins/meta`，同步插件列表变化并刷新左上角插件入口状态
  - 返回数组中每个元素的 `name` 会作为扇形菜单展示名称，`key` 会作为日志读取时对应的插件标识
  - 当前菜单按钮数量会随插件数量自动变化，不再写死
  - 中文插件名展示时最多保留 `4` 个字，不再固定只截取前 `2` 个字
  - 扇形菜单圆按钮会根据中文名称长度在 `2/3/4` 个字之间自动放大，保证文案完整显示且仍保持圆形
  - 中文按钮文案不再强制使用英文式大写与拉开字距，避免 `3` 个字或 `4` 个字被挤压截断
  - 页面加载完成后会先通过 `/api/plugins/status?name=插件key` 同步一次插件运行态；如果任一插件已启动，左上角扇形菜单主入口会先显示绿色闪动，方便未展开菜单时也能快速识别
  - 每次展开扇形菜单时，页面会额外通过 `/api/plugins/status?name=插件key` 刷新各插件运行态；已经启动的插件圆按钮会显示绿色闪动，方便快速识别
  - 展开时被遮挡的 `新会话` 按钮、`最近` 标题和会话列表会做模糊处理，收起后恢复
  - 如果当前没有可用插件，即时通讯按钮会保持禁用态
  - 点击任意扇形菜单按钮后，会在中间会话区弹出居中的插件浮层，不会遮挡左右 Sidebar 的可操作控件
  - 浮层第一段默认按 `复用当前会话`、`选择 Agent`、`模型选择`、`SWARM`、`Thinking` 的顺序排布容器配置项
  - 页面会根据 `/api/plugins/meta` 返回的 `scope` 实时决定这些容器配置项是否展示
  - 当插件没有返回 `scope` 时，仍按兼容模式展示全部五项
  - 当插件返回空 `scope` 数组时，这五项会全部隐藏并彻底失活，仅保留插件自定义参数区
  - 当插件只返回部分 `scope`，例如 `["reuse"]`，浮层就只展示对应的那一项容器配置
  - 如果当前所有插件都处于关闭状态，插件浮层会把可见容器配置项重置为默认值：`复用当前会话` 不勾选、`Agent` 取第一个可用项、`模型` 取第一个可用项、`SWARM` 关闭、`Thinking` 关闭
  - `选择 Agent` 下拉框会通过 `/api/agentId` 动态加载；只要仍有插件处于启动态，就会优先回填当前会话绑定的 Agent，其次回填设置中的 Agent
  - 如果插件声明支持 `swarm`，插件浮层里的 `SWARM` 开关在“仍有插件启动”时会优先按已保存的 `router_disable` 回显；未配置时默认关闭
  - 浮层会根据 `/api/plugins/meta` 返回的 `param` 生成输入框；当接口返回 `[{"headless":"选填说明"},{"chrome":"选填说明"}]` 这类结构时，会按顺序渲染多行表单，每行固定展示参数名与对应输入框
  - `param` 中每个字段的 value 会作为输入框的 `placeholder` 提示文案，只在当前字段还没有实际值时展示，不会被当作真实默认值提交
  - 如果接口同时返回已配置 `meta`，浮层中的对应输入框会优先直接展示实际配置值，不再显示原始 `placeholder`
  - 当 `placeholder` 文案过长且当前输入框为空时，鼠标悬停或聚焦该输入框，会在浮层内额外显示完整提示，方便查看长说明
  - 参数较多时，浮层保持整体尺寸不变，中间表单区域会自动滚动
  - 若当前浮层勾选 `复用当前会话`，但切换了与当前会话不同的 Agent，页面会自动取消复用并提示，避免把不同 Agent 误绑到同一 `chatId`
  - 浮层下半部分固定展示 `启动`、`关闭`、`日志`、`取消` 四个按钮，并复用设置面板同一套按钮风格；点击遮罩层空白区域或按 `Esc` 会直接取消
  - 点击 `启动` 后，会立即把当前表单参数提交到 `/api/plugins/config` 更新对应插件配置，并继续调用 `/api/plugins/start` 启动插件
  - 启动或重启后，浮层会立刻进入等待动画态，并异步等待服务响应；如果等待超过一轮进度条时长，进度条会继续循环，直到收到结果
  - 启动成功后，插件浮层会直接关闭，并在左侧虚拟文件系统 Tips 位置提示 `插件名 启动成功`
  - 启动失败时，浮层会立即切到日志查看区，方便直接排查日志；如果失败发生在配置保存阶段，则会保留在配置态并直接提示错误
  - 点击 `日志` 后，浮层中间的参数输入区域会切换为日志流展示区，按钮文案同步变为 `返回`
  - 日志流通过 `/api/plugins/log?name=插件key` 读取，展示样式与右侧 `CMD` 子面板保持一致，但不显示复制和终止按钮
  - 日志流展示期间会持续自动滚动到底部；点击 `返回`、`取消`、浮层空白区域或按 `Esc`，都会立即关闭当前日志 SSE 读取并恢复参数输入区域
  - 点击 `关闭` 会调用 `/api/plugins/stop?name=插件key` 尝试关闭对应插件
  - 这里的访问限制同样只按当前站点访问来源判断；只要不是通过 `localhost` 或 `127.0.0.1` 打开，即使当前服务已经切到“协作”模式，也仍然不能操作插件参数或生命周期按钮
  - 当页面不是通过 `localhost` 或 `127.0.0.1` 访问时，插件浮层会隐藏全部插件参数，并禁用 `启动 / 重启` 与 `关闭`，只保留日志查看能力

- 日志范围确认后，页面会先收起浮层并锁定界面，调用 `/log_skill` 导出当前 `Agent + 会话` 的日志；导出失败时会复用左侧虚拟文件系统 Tips 位置提示错误，且返回日志大小为 `0` 也会按失败处理
- 日志导出成功后，会再次以相同风格在中间会话区居中弹出浮层，展示导出的日志绝对路径和大小，并提示 `日志导出成功，请补充提炼目标`；输入框会默认预填 `把文件中最近几轮对话和工具调用提炼成可复用的SKILL`，用户可以直接修改
- 提炼目标浮层底部新增 `重置` 按钮；点击后只会清空当前提炼目标输入框，不会关闭浮层，也不会影响已导出的日志路径与范围条件
- 目标确认后，页面会立即收起浮层，并自动在当前会话中发送如下请求，不需要手动再复制粘贴：
  `将文件中的请求、响应和工具调用整理成Skill，文件保存在:$日志绝对路径。需要提炼的目标是：$用户输入的提炼目标`
- 这条由 `Skill` 小图标触发的 SSE 请求会直接在请求体中附带 `metadata.skill_extract = true`
- 同时这条自动发送的请求还会附带 `metadata.requestSource = "skill_extract"`，用于标记当前轮由左侧 `Skill` 小图标发起
- 普通手动请求发送时，如果当前 `Skill` 图标已点亮，会先带动画回到灰色常驻态
- 如果当前轮请求来源是 `Skill` 小图标，这一轮结束后会直接保持灰色常驻态，不会再重新调用 `/log_skill_status` 依据本轮结果点亮自己
- `metadata.requestSource = "skill_extract"` 用于标记并阻断这类自触发回流；即使这一轮内又产生了 `cli/get` 或 `cli/pub`，左侧 `Skill` 小图标也不会因为本轮 `skill_extract` 再次从灰色态点亮
- 只有在当前会话正在发送请求、等待 SSE 响应期间，`Skill` 小图标才会临时不可点击，避免和进行中的响应链路冲突
- 每次 SSE 响应结束后，提炼浮层草稿都会重置：范围恢复为默认轮数 `1` 且时间清空，提炼目标恢复为默认预填文案
- 如果本地还没有“点击过 skills 目录或创建SKILL按钮”的记录，第一次点击左侧虚拟文件系统中的 `skills` 目录或左上角 `Skill` 小图标时，会优先触发独立的新手引导
- 这条技能提炼引导会依次高亮 `skills` 目录、`Skill` 小图标、提炼范围浮层、`提炼最近N轮对话`、`开始时间/结束时间`、`提炼目标`，最后继续高亮目标输入区域并播放一段“清空默认文案后重新输入新目标”的鼠标与键盘演示动画
- 最后一段演示会模拟输入 `把文件中最近几轮对话和工具调用提炼成可复用 生成最近1周，HTML格式财务报表 的SKILL。`，提示用户明确约束、目标和格式
- 引导期间只允许通过 `知道了/完成` 推进；`Skill` 浮层里的取消、重置、确认与发送按钮不会真正触发导出或发消息

### 对话

- 在输入框输入消息，按 Enter 发送（Shift+Enter 换行）
- 任意新手引导任务进行中时，即使键盘焦点停留在居中输入框，按 Enter 也不会发送消息，避免误触；引导完成后会自动恢复正常发送
- 如果当前浏览器还没有“点击过输入框”的本地记录，那么第一次点击左侧 `新会话` 或第一次点击居中输入框时，页面会触发一组独立的新手引导
  - 引导会依次高亮输入框左侧小地球模型选择按钮、发送按钮、输入区 `@` 提示、会话渲染区、左侧 `logoSvg`、右侧 `CLI` 子面板区域、`SWARM`、`HTML`、`Thinking/Auto`、右侧刷新会话按钮、左侧 `新会话`、左侧会话列表和首个会话删除按钮
  - 会话渲染区之后会额外带到左侧 `logoSvg`，提示可以查看所消耗的 Token 明细，然后再切到右侧 `CLI` 子面板
  - `CLI` 步骤会自动展开右侧栏，并高亮右侧边栏第二栏整个 `CLI` 子面板区域，提示执行的系统命令会在这里显示
  - `@` 提示步骤会临时模拟输入 `@`，并主动弹起文件/技能菜单；如果当前会话已开启 `SWARM`，菜单里还会额外出现 `Agent`，用于插入 `[TEAM:AgentId]` 气泡
  - 如果左侧 Sidebar 当前处于收起状态，引导切到 `logoSvg`、`新会话` 和会话列表相关步骤时会自动展开左侧栏
  - 每一步都需要点击 `知道了` 继续，最后一步点击 `完成` 后结束
  - 引导与首次打开站点时的 Agent / 模型配置引导互相独立；如果首次打开引导正在进行，这条由 `新会话` 或输入框触发的输入引导不会抢占当前流程
- 点击输入框左侧小地球图标选择当前使用的模型
- 当当前会话已经至少出现过一条正常结束的 assistant SSE 响应后，第一次把这里切换到另一个不同模型时，会额外触发一条独立新手引导，提示 `当前上下文切换到不同模型后依然生效。`
- 如果居中输入框当前还没有选择模型，点击输入框或直接发送时，不再弹浏览器 `alert`；页面会在中间会话区弹出带背景模糊的居中提示浮层，文案为 `请先选择模型` 与 `点击输入框左侧小地球选择模型`
- 该“未选择模型”提示会复用会话上限提示相同的 `center notice` 浮层样式、层级和分域遮罩规则，只作用于中间会话区，不会跨区域遮挡左右 Sidebar
- 在居中对话框输入框和右上角备忘录输入框中直接粘贴系统剪贴板图片时，页面会自动调用 `/api/edit` 将图片保存到当前 Agent 的 `tmp/` 目录，并按 `@文件` 相同规则插入 `FILE` 气泡：输入框中显示为 `[FILE:图片文件名]`，后续提交时发送为 `[FILE:图片绝对路径]`
- 从本地文件系统把文件、图片或文件夹直接拖入居中输入框或右上角备忘录输入框时，页面会先调用 `/api/upload` 上传到当前 Agent 的 `tmp/` 目录，再插入 `FILE` 气泡；气泡展示为 `[FILE:文件名]`，提交时发送为 `[FILE:上传后的绝对路径]`
- 如果拖入的是文件夹，插入的 `FILE` 气泡对应的是上传后文件夹本身的绝对路径，而不是仅其中某个文件的路径
- 拖入文件夹时会尽量保留原有目录结构，拖入空目录时也会在 Agent `tmp/` 下补建对应目录
- 本地拖入上传期间会按交互域锁定界面：拖入居中输入框时只锁定中间会话区，拖入右上角备忘录时只锁定右侧 Sidebar，不会跨区域遮挡左侧 Sidebar
- 右上角备忘录中的 `FILE` 气泡在路径或文件名特别长时，会在输入框内自动截断省略显示，避免把输入框横向撑破；删除按钮仍会保持可点击
- 输入框右侧新增重新加载按钮，点击后会弹出确认浮层，可为当前 Agent 和会话增量恢复最后一条已知 SSE 时间之后的对话数据；下方文件夹按钮可打开 Agent 目录
- 自动重载与手动重载共用同一套恢复链路；如果当前会话正在等待 SSE 响应，则不会触发自动重载，也不会叠加新的恢复请求
- 居中输入框上方的 `Thinking/Auto` 开关按会话独立保存；开启后，当前会话后续发送到 `/v1/chat/completions` 的请求会显式附带 `metadata.thinking = true`
- 居中输入框上方新增 `SWARM` 开关，并固定放在当前会话 `HTML` 开关左侧；该开关按 `Agent + Chat` 独立保存，切换会话时会自动切回该会话自己的蜂群状态
- 这项 `@ Agent` 扩展只在居中会话输入框生效；右侧备忘录输入框仍只保留原有的文件和 Skill 菜单
- 当当前 `Agent + Chat` 会话的 `SWARM` 处于开启状态时，居中输入框输入 `@` 后的菜单会额外显示 `Agent`
- 输入 `@` 后，文件和技能入口会立即显示；Skill 与 SWARM Agent 的可用性在后台更新，避免主菜单等待接口返回。
- `Agent` 菜单请求 `/api/swarm_agent?agentId=当前AgentId`，读取 `router_disable=false` 且排除当前 Agent 自身的 Agent ID。接口数据由 Integration 的 `config/config.json.at` 缓存管理；如果接口返回空数组或请求失败，这个入口会自动隐藏，不会使用旧数据。
- 同一次菜单打开期间，预取与立即点击“技能”或“Agent”会复用同一个请求；页面不额外持久化 Skill 或 Agent 列表。
- 在文件区禁用或恢复技能目录成功后，无需刷新页面；后续当前会话的 `@ Skill` 菜单会直接使用服务端已筛选并重新计时的缓存结果。
- 保存任意 Agent 的蜂群开关后，无需刷新页面；后续 `@ Agent` 菜单会直接使用服务端已更新并重新计时的 Agent 列表。
- 选择某个 Agent 后，会在当前光标位置插入 `[TEAM:AgentId]` 气泡；气泡展示文案和提交时透传文本都保持为同名格式
- 居中输入框上方新增 `HTML` 开关，并固定放在当前会话 `Thinking/Auto` 开关左侧；该开关按会话独立保存
- `Thinking` 开关只影响居中会话区的主聊天请求，不会额外改写右侧备忘录、插件或其他接口的请求结构
- 消息会先进入 3 秒等待阶段，整个页面中央显示 100x100 的转圈等待图标，随后再通过 SSE 协议发送至 `http://127.0.0.1:8080/v1/chat/completions`；该等待效果与当前会话绑定，切换会话时会按对应会话实时显示，但不会重新计时
- 如果当前会话已经进入 SSE 等待响应阶段，这时在居中输入框继续提交下一条查询，页面会把新查询加入当前 `Agent + Chat` 作用域的待发送列表；加入后会立刻清空居中输入框，避免残留旧内容
- 如果当前 `Agent + Chat` 作用域的待发送列表已经达到 `10` 条上限，居中输入框会临时锁定为不可编辑；只要队列数量回落到上限以下，就会自动恢复可编辑
- 只要存在待发送消息，输入框左侧小地球图标右上角都会出现一个闪动的蓝色小圆点；新加入的待发送消息会以收起动画缩到这个小圆点
- 鼠标悬停蓝色小圆点会向右上展开待发送列表，最多累计 `10` 条；每条消息只展示前 `10` 个字符，超出部分自动显示 `...`，鼠标移出后会保留 `2` 秒再自动收起
- 如果当前浏览器还没有“待发送消息队列引导”的本地记录，那么第一次把消息加入待发送列表时，会自动触发一条独立新手引导
- 这条引导会先高亮整个待发送列表，再依次高亮第一条待发送消息、`编辑` 按钮、`删除` 按钮、`插入` 按钮和左侧拖拽手柄，分别讲解自动发送、发送前修改、从队列移除、立即插入消息以及拖动排序
- 引导期间除当前高亮目标和 `知道了/完成` 按钮外，其它区域都会被暗化且不可点击；如果首次触发时已有其他新手引导进行中，这条引导会等当前引导结束后再补播
- 待发送列表支持 `编辑`、`删除` 和拖拽排序；点击 `编辑` 会复用原有的居中消息编辑浮层，保存后只更新待发送内容，不会立即发送，取消则直接关闭浮层
- 如果某条待发送消息关联了 `message_insert` 记录，那么无论是手动删除它，还是轮到它自动发送，页面都会先调用 `/api/message_insert/delete` 清掉对应 `tid`；只有删除成功，这条消息才会真正从前端队列里移除
- 待发送列表拖拽时需要按左侧六点手柄操作；松手完成排序后，被插入到新位置的那条待发送消息会在新位置闪动 `3` 秒，方便确认顺序变化
- 当前请求执行中时，右侧按钮会按当前输入状态自动切换：输入框有内容且队列还有容量时显示为“加入待发”的输入按钮；输入为空或队列已满时保持取消按钮
- 当前请求执行中时，如果点击的是取消按钮，则会优先取消当前正在执行的那一轮请求，而不是重复向待发送列表追加消息
- 当前请求结束后，待发送列表会按顺序自动发送；轮到某条消息时，页面会先清理它关联的 `message_insert` 记录，清理成功才会把它从列表里移除并继续发送
- 如果上述 `message_insert` 清理失败，这条消息会继续留在队列头部，当前轮自动发送会直接停住，等待下次重试或人工处理
- 待发送消息一旦从队列里取出开始执行，就不会因为成功、取消、异常或其他终止状态再次自动塞回队列，整个队列始终保持严格的单向消费
- 待发送列表浮层会保持在输入区同域的最高展示层级，不会再被沙盒按钮、全屏按钮或同区域其他浮层遮挡
- 响应实时流式渲染，支持标准 Markdown、LaTeX 公式（例如 `$E=mc^2$`、`$$\int_0^1 x^2 dx$$`）、图片、HTML 嵌入
- 如果整条响应内容以 `<deepright>...</deepright>` 作为最外层包裹，页面会把它识别为 DeepRight 专属输出卡片，去掉外层标签后继续渲染内部的 Markdown、公式、表格和安全 HTML
- SSE 增量返回过程中，会基于当前累计文本实时做 Markdown 渲染；标题、列表、引用、代码块、表格等结构不再等到响应结束后才一次性成型
- 在送入流式 Markdown 渲染前，页面会先清理 SSE 文本中的 ANSI/OSC 控制序列、`\r` 回车、零宽字符等隐藏干扰内容，避免 `#### 正在加载技能 weather`、列表序号、引用符等结构因前缀脏数据而退化为原始符号文本
- 流式阶段与最终完成态复用同一套 Markdown/HTML 安全渲染链路；中间态若存在未闭合代码块、表格或 HTML 片段，会按当前可解析结果持续展示，而不会长时间停留在原始 `#`、`*`、``` 符号状态
- 居中 assistant 气泡会按 SSE 报文里的 `biz/workflow` 区分 `过程报文` 和 `结果报文`：`biz=main && workflow=base@close` 与 `biz=base && workflow=close` 会按结果报文处理，`[DONE]` 作为结束标记归到结果侧，其余报文按过程报文处理
- 同类型报文会继续在当前 assistant 气泡里累加；一旦两种类型来回切换，当前已累计片段会先爆炸清空，再从新类型的这条报文重新累计；开启 `节能` 时仍保留切换逻辑，但不播放爆炸动画
- 居中对话框现在支持直接渲染安全 HTML 片段，并继续兼容 Markdown 与 LaTeX 混排；常见标签如 `iframe`、`img`、`video`、`table`、`details` 会沿用会话气泡样式展示，同时会自动过滤脚本和危险属性
- SSE 或 HTML 响应中的表格默认采用“按内容撑开 + 外层横向滚动”的展示策略，不会再强行压缩到消息气泡宽度内
- 当表格包含 `位置`、`路径`、`行号`、`范围`、`Location`、`Path`、`Line`、`Range` 等定位类列时，这些列会默认保持横向阅读，避免被挤压成单字竖排
- 居中对话框中的用户请求气泡仍会把 `http/https` 超链接以及文件系统绝对路径（含 `file:///` 路径与目录绝对路径）渲染成蓝色下划线链接；相对路径仅对白名单目标生效：`skills`、`skills/...`、`tmp`、`tmp/...`、`SOUL.md`、`USER.md`
- assistant SSE 响应气泡在实时渲染和历史恢复时，会复用同一套目标提取规则，把可识别的文件路径、`file:///`、`http/https` 从正文里改渲染为与输入框同风格的行内小气泡，而不再以最终蓝色下划线文本形态展示
- assistant 文件类小气泡默认展示文件名或末级路径摘要，URL 小气泡默认展示可读摘要；超长时会按现有气泡规则截断，但每个气泡内部都会继续绑定完整原始路径或 URL，供复制、预览、下载文件、打开目录、打开网页复用
- SSE 分片如果把同一个 URL 或路径拆到了多个 chunk，页面会等到现有提取规则能稳定识别后再气泡化，避免半截路径提前变成错误气泡，也避免同一目标在文字链接和小气泡之间来回闪烁
- assistant 气泡中的文件路径或 URL 现在支持直接单击弹出动作浮层，不再要求先双击或手动框选文本；同一条 assistant 消息里如果存在多个目标，每个小气泡都会独立绑定自己的完整值和动作
- assistant 小气泡的动作顺序固定为 `复制` 优先：文件类为 `复制`、`预览`、`下载文件`、`打开目录`；普通 `http/https` 为 `复制`、`预览`、`打开`；资源类 `http/https` 为 `复制`、`打开`
- 点击 assistant 小气泡里的 `复制` 时，复制到系统剪贴板的是完整原始路径或 URL，不是气泡上的摘要文本；成功后会在左侧虚拟文件系统 Tips 位置提示 `已复制到粘贴板`，失败时也会给出明确提示
- 与消息 URL/路径相关的既有新手引导、动作浮层层级和交互域隔离规则都已同步适配到 assistant 小气泡方案；如果命中原有文件 URL 操作引导，引导会直接围绕小气泡和对应动作浮层展开，不会和其它消息域或侧栏浮层串扰
- 在居中对话框中双击路径或超链接文本时，会按前后标点、空白、空行边界自动框选当前这段明确目标；如果双击的是链接，则会优先框选整段链接文本，再按目标类型在路径附近弹出可用的小气泡操作
- 文件系统路径仅在目标文件真实存在且文件名后缀属于纯文本、Markdown、图片、HTML、PDF，或浏览器原生 `<video>` 可播放的视频格式时才会出现 `预览`；文件存在时才会出现 `下载文件`；可打开目录存在时才会出现 `打开目录`，如果双击目标本身就是目录，则直接对应这个目录本身；相对路径只接受 `skills`、`tmp`、`SOUL.md`、`USER.md` 这类白名单目标，并且会先拼接当前 Agent 工作目录再判断
- `http/https` 超链接双击后会显示 `预览` 与 `打开` 两个小气泡：`预览` 会把右侧 Sidebar 切换为独立 iframe 预览区，`打开` 会新开浏览器窗口访问对应网页
- assistant 消息里的文件类小气泡会继续沿用相同的 `预览`、`下载文件`、`打开目录` 出现条件；如果目标本身是目录，则不会显示 `下载文件`，也不会展示无效 `预览`
- assistant 消息里的 `http/https` 小气泡会继续沿用现有 URL 浮层的 `预览` / `打开` 规则；资源类 URL 仍不会进入右侧 iframe 预览链路，只保留允许的动作
- 如果 assistant `http/https` 小气泡对应的目标 host 是 `localhost` 或 `127.0.0.1`，点击 `预览` 或 `打开` 时，页面会自动在实际访问 URL 上补齐当前 `agentId`、`chatId`、`themeLabel`；其中 `themeLabel` 会按当前主题传 `深色模式` 或 `浅色模式`
- 右侧 iframe 预览区会整体替换原右侧内容，并让 iframe 尽量吃满右侧可用高度；打开与切回时会带毛玻璃淡入淡出效果，但不会抬高整体布局
- 右侧 iframe 预览状态与当前 `Agent + Chat` 会话绑定；切换会话后会按目标会话自己的状态决定是否继续展示 iframe
- 预览区边界处会悬浮一个切换按钮，用于恢复原右侧布局；按钮与居中会话框左上角 `复制会话` 按钮保持同一水平线
- 右侧 iframe 预览区左边界靠上的位置会新增一个展开小图标；点击后，当前网站浏览会以站内页内覆盖的方式展开成一个超大浮层，覆盖当前 HTML 可视区域，并在四周各保留 `15px` 缩进
- 展开态下点击右上角按钮或按 `Esc`，都会还原到当前右侧 iframe 预览尺寸，不会关闭正在浏览的网站
- 展开态浮层外的页面背景会同步做毛玻璃模糊，普通页面点击会被遮罩拦截；如果展开期间切换会话、预览失败、加载超时或预览被关闭，页面会自动退出展开态
- 展开态期间不会再触发任何新的新手引导，右侧原有“关闭网站浏览”入口也会暂时失效，只保留右上角还原按钮
- 如果这是当前浏览器第一次成功打开右侧 iframe 预览，还会额外出现一条独立新手引导，高亮这个切回原布局按钮，并提示 `点击关闭网站浏览。`
- 这条引导会提供一个 `完成` 按钮；在点击前，其它区域会继续被暗化且不可点击；点击后只关闭引导遮罩并恢复正常交互，不会强制关闭当前 iframe 预览
- 如果目标站点不可访问、返回 `404/5xx`，或明确通过 `X-Frame-Options` / `Content-Security-Policy frame-ancestors` 禁止 iframe 嵌入，页面会自动关闭 iframe 并切回原右侧布局，同时在 VFS Tips 位置提示具体原因
- 如果前端实际加载阶段超时或触发加载错误，也会自动关闭 iframe 并切回原布局，避免右侧停留在不可用预览态
- Markdown 表格与原始 HTML 表格会沿用同一套布局规则；在窄窗口、长文本或流式增量更新过程中，优先保持表头对齐和整体可读性
- 当前支持的 HTML 片段结构包括：
  - 文本结构：`div`、`section`、`article`、`p`、`span`、`br`、`hr`
  - 标题：`h1` 到 `h6`
  - 强调：`strong`、`em`、`u`、`del`、`sub`、`sup`
  - 列表：`ul`、`ol`、`li`
  - 引用与折叠：`blockquote`、`details`、`summary`
  - 代码：`pre`、`code`
  - 表格：`table`、`thead`、`tbody`、`tr`、`th`、`td`
  - 媒体：`img`、`iframe`、`video`、`audio`、`source`
  - 语义容器：`figure`、`figcaption`
  - 链接：`a`
- 当前允许的常用属性包括：
  - 全局属性：`class`、`title`、`aria-label`、`aria-hidden`、`role`
  - 链接：`href`、`target`、`rel`
  - `iframe`：`src`、`loading`、`allow`、`allowfullscreen`、`referrerpolicy`
  - 图片：`src`、`alt`、`loading`、`width`、`height`
  - 视频：`src`、`controls`、`preload`、`poster`、`muted`、`playsinline`、`loop`、`autoplay`
  - 音频：`src`、`controls`、`preload`
  - `source`：`src`、`type`
  - 表格单元格：`colspan`、`rowspan`，其中 `th` 额外支持 `scope`
- 以下内容会被自动过滤或限制：
  - `script`
  - 所有行内事件属性，例如 `onclick`
  - `style`
  - `srcdoc`
  - 危险协议：`javascript:`、`vbscript:`、非图片型 `data:`
  - `iframe` 的 `src` 仅接受 `http(s)` 或 `/` 开头的同源路径
- 页面前端依赖全部使用 `site/vendor/` 下的本地静态资源，不依赖 CDN 在线下载
- 发布链路必须保证页面引用到的本地前端依赖真实可访问，并返回正确的 JS/CSS MIME；禁止出现页面已引用但静态服务未实际发布、返回 `404 text/plain` 导致脚本或样式被浏览器拒绝执行的情况
- 当前实现已将公式渲染依赖直接随页面交付，避免 `/site/vendor/*` 未发布时导致居中对话框中的 LaTeX 无法生效
- 当向上滚动惰性加载更早历史消息时，中间会话区会短暂进入同域锁定态；只锁定中间会话区，不影响左右 Sidebar，待本批历史消息与对应毛玻璃效果完成后自动解锁
- 居中对话框中的所有用户请求气泡与 SSE 响应气泡，右下角外侧均带有一个 `15x15px` 复制图标；点击后会将当前气泡文本复制到系统剪贴板，并复用左侧虚拟文件系统的 Tips 位置提示复制成功
- 居中对话框中的用户请求气泡在复制图标左侧额外带有一个 `15x15px` 重试图标；点击后会自动使用该请求内容重新发送一轮 HTTP 请求，并新增一条新的请求气泡，同时在左侧虚拟文件系统的 Tips 位置提示 `重试成功`；仅当当前会话不存在活跃 SSE 连接或恢复轮询时才允许重试，否则提示 `消息正在发送中`
- 用户请求气泡也会在气泡内右下角显示发送时间，格式为 `yyyy-MM-dd hh:mm:ss`，样式与 assistant 气泡右下角的 SSE 时间标记保持一致
- 居中对话框中已经成功展示过的远程图片会自动写入浏览器本地缓存；后续即使原始图片链接失效或返回 `404`，页面刷新后也会优先尝试从本地持久缓存恢复显示
- 虚拟文件系统中的图片文件预览已升级为可编辑模式：打开后以 canvas 展示，支持橡皮擦工具，拖动涂抹区域会直接擦成透明像素（Alpha=0）；保存时不会覆盖原图，而是在原目录下生成“原文件名+时间戳”的新图片，并自动将新图片绝对路径复制到系统剪贴板，同时在 VFS Tips 位置提示路径已保存至黏贴板
- 如果原图是 `jpg/jpeg` 或其他不支持透明通道的格式，只要使用过橡皮擦，保存时会自动改为 `png`，避免透明区域被重新压扁成不透明背景
- 左侧虚拟文件系统中的 `新建文件或目录` 弹窗会始终只接受单个文件名或目录名；当前位于子目录时，页面会自动把“当前目录 + 输入名称”拼成 workspace 内相对路径后再调用 `/api/agent/create`
- 创建弹窗会拒绝 `/`、`\`、空白字符、`.`、`..` 等非法名称；创建失败时会在原错误提示位置直接展示后端返回内容
- 左侧虚拟文件系统会每 `30` 秒自动调用 `/skills_warning` 拉取当前 `SKILL.md` 解析异常；如果存在异常，则从当前可见目录开始，把通往错误 `SKILL.md` 的整条路径都做高频高亮闪动
- 命中的错误 `SKILL.md` 条目末尾会额外出现一个高频高闪的红色感叹号小图标；点击后会在左侧 Sidebar 分域内弹出错误原因浮层，展示错误文件绝对路径和解析失败原因
- 所有被这条红色闪动链路命中的文件或目录，末尾还会额外出现一个同色系的修复小图标；如果当前条目本身不是 `SKILL.md`，页面会自动取离它最近的异常 `SKILL.md` 作为修复目标
- 点击修复小图标后，会在左侧 Sidebar 分域内弹出确认浮层，标题固定为 `是否需要修复SKILL.md`，正文展示目标 `SKILL.md` 的绝对路径
- 点击确认浮层中的 `是` 后，页面会自动向当前活跃会话发送一条预填请求：`参考[https://agentskills.io/specification]修复<绝对路径>的错误。`
- 如果调用 `/skills_warning?refresh=1` 或后端下一轮自动扫描发现该文件已经修复，则左侧对应高亮和感叹号会在下一次前端轮询后自动消失
- 如果这是当前浏览器第一次出现 Skills 文件错误提醒，页面会额外启动一条独立新手引导：先高亮被提醒的路径，再逐层模拟展开目录并切到目标 `SKILL.md`
- 引导最后一步会继续高亮出错的 `SKILL.md`，提示参考 `https://agentskills.io/specification` 修正错误；在点击 `完成` 前，其它区域会被暗化且不可点击
- 左侧 Sidebar 收起时，原本显示在虚拟文件系统底部的 `Tips` 会自动改为显示在居中对话框左下角；重新展开 Sidebar 后恢复原位置，颜色和展示时长保持一致
- 所有固定定位的遮罩层、确认框、弹窗都按左侧 Sidebar、中间会话区、右侧 Sidebar 分域管理 pointer-events 与层级；未激活浮层不会再跨区域拦截其他区域的点击
- 中间会话区的数量上限提示、Agent 选择提示、设置面板、插件浮层、CMD 浮层都会各自复用同一套 center overlay 管理，并实时跟随主会话区的实际矩形；左右 Sidebar 在展开、收起或动画过渡中都不会再让遮罩、模糊边界和 loading 圈漂移
- 当当前会话绑定的 Agent 已失效或不存在时，会在中间会话区弹出居中的 Agent 选择浮层，并复用同一套分域 overlay 与背景模糊规则
- 图片编辑器还支持使用不同颜色和线粗，为指定区域拖拽绘制圆、椭圆、矩形、三角形，并可通过拖拽起止范围控制图形放大缩小
- 图片编辑器支持后退操作，最多可撤销最近 `10` 步橡皮擦或图形标注编辑
- assistant 气泡会在右下角显示 SSE 响应时间和状态，格式为 `yyyy-MM-dd hh:mm:ss 状态`，并在每次增量响应渲染时刷新；流未结束时显示`等待`，自然结束后显示`完成`，主动中断后显示`已取消`
- 如果这条 assistant SSE 响应里存在可识别的思考内容，气泡左上角会额外出现一个 `收起思考内容` 入口；点击后会在当前气泡内切换为 `展开思考内容 / 收起思考内容`。普通响应、用户请求气泡和右侧 CLI 子任务气泡都不会显示这个入口
- 这组思考内容与正式回复仍然归属于同一条 assistant 响应气泡，不会因为收起或展开而拆成两条消息；首次渲染时默认优先展示正式回复，思考内容从收起态开始，并且收起后不再占用正文高度
- 在 SSE 持续流式返回期间，如果当前气泡正处于收起态，后续新增的思考内容会继续缓存到思考区，但不会因为流式更新反复把气泡撑开；如果当前已经展开，则新增思考内容和正式回复都会继续按现有节奏实时渲染
- 这条展开/收起状态会绑定到当前 `Agent + Chat + assistant 响应气泡`；切换到其他会话不会串用，重新渲染当前会话、轮询恢复未结束响应或从历史记录恢复消息时，也会按该气泡自身记录恢复；如果历史里没有保存过状态，则默认按收起处理
- 收起思考入口与现有复制、重试、`__PROCESS__ / __WARN__` 提示、任务气泡等交互共存；交互范围只限制在当前 assistant SSE 气泡内，深色和浅色主题下都会保持可见且不遮挡原有热区
- 当会话滚动条仍停留在底部附近时，新的 SSE 内容会自动跟随到底部；如果已经主动上滑查看历史，后续增量不会强制把视图抢回底部
- 发送期间显示「努力工作中」浮层，可点击暂停按钮终止请求；终止时会立即中断本地连接，并在 3 秒等待后调用会话取消接口。若已有响应，会保留当前已经收到并渲染的内容，再将最后一条响应消息改为`已取消`；若尚未收到任何 SSE 内容，会补一条样式一致的`已取消`响应，状态均标记为`完成`，最后提示取消成功
- assistant 气泡预留了统一的 `__PROCESS__` / `__WARN__` 临时提示位；默认展示在当前响应气泡外侧底部 footer 槽位，如果对应 SSE 报文的 `choices[0].metadata.__TARGET__` 是非空标记，则会改为展示在当前等待响应的 assistant 气泡内侧左下，并与右侧时间处在同一水平线；展示内容都直接取对应 SSE 报文里的 `choices[0].delta.content`，并做统一文本归一化
- 如果当前请求自己的 assistant 气泡还没创建出来，这类临时提示会先保留在当前会话状态里，等新气泡出现后再挂上，不会回贴到上一条历史 assistant 响应上
- 内侧 `__TARGET__` 提示不再按固定字符数预截断，而是直接跟随当前居中对话框这条 SSE 响应气泡的可用宽度自适应裁切；与右侧时间之间固定保留 `15px` 间距
- 文本归一化会去掉 `\r`、裁掉首尾空白、把连续换行折叠为空格，再把连续空白折叠为单个空格；如果归一化后为空，则会直接清空当前会话的这条统一临时提示
- 这个临时提示只按 `ChatId` 绑定；`agentId` 和 `__TARGET__` 都不参与作用域匹配，不同会话之间不会串扰；页面刷新、SSE restore 或历史恢复补拉到纯 `__PROCESS__` / `__WARN__` 报文时，也不会把这类状态包写进居中对话框正文，更不会重复回放这类临时提示
- `__PROCESS__` 与 `__WARN__` 共用同一个临时提示位，后到达的状态会立即覆盖先前状态，并按各自时长重新计时：`__PROCESS__` 统一为 `5` 秒，`__WARN__` 优先取 `choices[0].metadata.__DELAY__` 毫秒，缺失、非法或小于等于 `0` 时默认 `30` 秒；`__TARGET__` 只改位置，不改计时规则
- 当前一轮 SSE 响应如果收到 `choices[0].metadata.__TASK_START__` 非空报文，且该报文 `choices[0].delta.content` 归一化后仍能取到首字符，当前等待响应的 assistant 气泡右上角会新增或更新一个闪烁小气泡；唯一 key 直接取 `__TASK_START__`，气泡正文只显示归一化后的首字符并转成大写
- 如果后续又收到新的 `__TASK_START__` key，新气泡会追加到最右侧，原有气泡整体左移；如果同一个 key 再次收到新的可展示首字符，则会直接更新现有气泡正文；如果收到 `choices[0].metadata.__TASK_CLOSE__` 非空报文，则按这个 key 删除对应气泡，让剩余气泡自动右移补位
- 任务气泡的出现和消失都会带动画；如果一整轮 SSE 到结束都没有收到过非空 `choices[0].metadata.__TARGET__`，前端会在收尾时把当前会话残留的任务气泡统一清掉，避免残影
- 这些任务气泡同样只按 `ChatId` 作用域隔离，不受 `agentId` 或 `__TARGET__` 影响；它们属于等待响应期的临时展示，不会进入居中对话框正文，也不会在 restore / 历史恢复时重复回放
- 如果当前浏览器还没有“看过任务气泡引导”的本地记录，那么第一次看到这个 `__TASK_START__` 小气泡时，会额外触发一条独立的新手引导，高亮该小气泡并提示 `启动多Agent时会在此提示。`
- `努力工作中` 的位置与显隐逻辑保持不变，仍只跟当前会话是否处于 busy 状态有关，不会被外侧或内侧的 `__PROCESS__` / `__WARN__` 提示替换
- 红色错误气泡只保留给真正错误场景，例如 HTTP 非 `200`、网络错误、SSE 报文 `code` 不在 `200-299` 范围内，或 `finish_reason=error`；单独的 `__WARN__` 提示不再生成独立红框，也不再使用前端兜底文案
- 如果某条流式消息在实时 Markdown 渲染阶段仍触发异常，界面会保留当前已收到文本的可见展示，并在浏览器控制台输出统一前缀 `[stream-markdown] fallback to plain text` 便于排查
- 如果首次进入页面或切换到某个会话时，本地已没有该会话的 SSE 连接，但最后一轮请求仍未完成或取消，界面会自动恢复为等待响应状态，并每 5 秒重新加载一次该 Agent/会话在最后一次实际请求时间之后的新对话数据；恢复接口返回多条 SSE 增量记录时，页面会按顺序合并到同一条 assistant 消息中，若记录类型为异常则按异常消息展示，收到完成或取消结果后自动恢复为待发送状态
- 首次打开站点时，如果浏览器还没真正进入 `index.html`，会先落到 integration 层的 `/launch` 轻量启动页，显示 `正在启动 / 等待完成`，并在重试较多时升级为 `首次打开新安装包时，页面资源可能还在准备`

### 存储

- 会话消息以滑动窗口形式最多存储最近 2000 条
- 右侧 `CLI` 子任务历史不再作为页面本地持久化内容写入 `deepright_chats`
- 当前页内右侧 `CLI` 子任务仍会保留最近窗口用于即时展示；页面刷新后由 `/api/restore` 与 live poll 重新补齐
- 页面展示最近 500 条，向上滚动时惰性加载历史消息
- 会话、草稿、主题等页面状态保存在浏览器 localStorage 中
- 页面会周期性检查当前 origin 下的 localStorage 总占用；当总占用超过约 2.5 MB 时，会自动把本地聊天历史压缩回约 2 MB
- 触发本地存储自动治理或浏览器配额不足的保存降级时，会先立即清除所有 chat 的页面备注、待发送内容和波浪线展示，再继续回收其它缓存或压缩历史
- 自动治理会在页面初始化后常驻运行，并在页面重新可见、以及每次 `saveChats()` 成功后补做预算检查
- 每次 live SSE 响应结束后，页面还会额外估算当前会话在本地持久化中的相关占用；若单会话超过约 1 MB，会立即从最旧消息开始回收该会话里的冗余副本，不裁 `restore` 回来的正文/历史窗口
- 进行中的 SSE 或 restore 流式恢复也会纳入预算治理：每收到一个可持久化的流式包，页面先做轻量体积估算；只有预估触及阈值时才精确计算并压缩，避免常规小包频繁序列化整个会话
- 流中压缩只调整 `localStorage` 持久化投影，不会替换当前消息对象、调用整页消息重渲染或改动已经显示的 DOM；已显示正文和持续输出的气泡保持不受影响
- 当本地存储空间紧张时，页面会优先从本地持久化 payload 中直接丢弃 `cliCommandHistory`，再从最旧消息开始移除已完成 assistant 消息中仅用于恢复的 `rawSse` 原始流记录，以及“思考片段”这类冗余快照，最后才逐步裁剪较旧的会话消息窗口
- 自动治理默认静默运行；只有第一次真实发生“超过 2.5 MB 后自动压缩”时，页面才会轻量提示 `本地存储超过 2.5 MB，已自动压缩本地历史`
- 如果压缩后仍可成功落盘，会提示 `本地存储空间不足，已仅保存最近部分会话历史`
- 如果经过多轮压缩后仍然无法写入，会提示 `本地存储已满，新的会话历史暂未保存`
- 模型与密钥保存在服务端 `/api/token` 对应的 SQLite `token_store` 表中
- `token_store` 中每条模型记录除了 `token` 外，还会额外保存 `__url`、`__model`、`__model_fast`、`__model_thinking`、`__model_multi_input`、`__model_multi_output`

## 请求协议

```json
{
  "model": "选中的模型名",
  "messages": [{"role": "user", "content": "消息内容"}],
  "stream": true,
  "metadata": {
    "agentId": "选中的AgentID",
    "chat": "当前会话UUID"
  }
}
```

Header 中 `Authorization` 为对应模型的密钥。

当当前会话开启 `HTML` 开关后，请求体中的 `metadata` 会额外包含：

```json
{
  "html": true
}
```

当当前会话开启 `Thinking` 开关后，请求体中的 `metadata` 会额外包含：

```json
{
  "thinking": true
}
```

无论当前会话是否开启 `SWARM`，请求体中的 `metadata` 都会显式带上当前会话绑定的蜂群状态：

```json
{
  "router_disable": false
}
```

关闭时同样会显式发送：

```json
{
  "router_disable": true
}
```

如果当前 Agent 的 `config.json.router_remote` 已保存有效值，请求体中的 `metadata` 还会额外包含：

```json
{
  "router_remote": ["remote_1", "remote_2"]
}
```

如果当前会话同时开启了 `SWARM`、`HTML` 和 `Thinking`，则会和 `router_remote` 一起写入同一个 `metadata` 对象。

## 注意事项

- 需要先启动 Proxy 或 Integration 服务，以提供 `/api/agentId`、`/api/deviceId` 和 `/v1/chat/completions` 接口
- 设置页依赖 `/api/token` 读取和保存模型密钥，因此需要由 proxy 或 integration 提供该接口
- 浏览器需支持 Fetch API 和 ReadableStream
- 已展示远程图片的离线/失效回显依赖浏览器本地缓存能力，当前实现优先使用 `Service Worker + Cache Storage`，并补充 `IndexedDB` 作为刷新后的持久回退
- 清除浏览器 localStorage 会丢失本地会话、主题和当前 Agent 选择，但不会删除服务端已保存的模型密钥
- 如果历史会话较多且浏览器站点配额较紧，页面可能只保留最近一部分本地会话历史；该行为优先牺牲 `rawSse`、较旧 CLI 历史与较旧会话窗口，而不是优先牺牲当前可见会话内容

- 展开态下页面只保留右上角一个高亮的还原按钮；点击该按钮后，只会还原到当前右侧 `iframe` 预览尺寸，不会关闭网站浏览
- 展开态也支持键盘 `Esc` 还原；如果焦点已经进入跨域 `iframe` 内部，父页面不一定能收到 `Esc`，此时仍可使用右上角按钮退出展开
- 这次展开能力只使用当前页面运行时状态，不会写入 chat 持久化；页面刷新后不会保留“已展开”状态
- 展开态浮层外的页面背景会同步毛玻璃模糊，并拦截普通页面点击；如果展开期间切换会话、当前预览被关闭、加载失败或加载超时，页面会自动退出展开态，并恢复到正确的右侧栏展示结果
- 展开态期间不会再触发新的新手引导，右侧原有“关闭网站浏览”入口也会暂时让位，只保留右上角还原按钮

## 迭代 20260711-3：本地存储预算自动治理

- 页面继续使用浏览器 `localStorage` 保存本地会话，但会新增常驻的预算治理能力：当当前 origin 下的总占用超过约 `2.5 MB` 时，页面会自动把本地聊天历史压缩回约 `2 MB`
- 页面初始化完成后会启动定时巡检；页面重新可见和 `saveChats()` 成功后，也会补做预算检查，尽量把问题前移到“超预算即维护”，而不是等浏览器正式拒绝写入
- 每次 live SSE 响应结束后，页面还会单独检查当前会话在本地持久化中的相关占用；若单会话超过约 `1 MB`，会立即从最旧消息开始回收该会话里的冗余副本，不改 `restore` 回来的正文/历史窗口，避免单个会话继续膨胀
- 右侧 `CLI` 子任务历史默认不再持久化到 `deepright_chats`；当前页继续使用运行时窗口展示，页面刷新后再由 `/api/restore` 与 live poll 重建
- 自动压缩会优先从本地持久化 payload 中丢弃 `cliCommandHistory`，再删除已完成 assistant 消息中高体积、低长期价值的 `rawSse` 与思考片段快照，最后才裁剪较旧消息窗口，尽量保住当前可直接阅读的中心正文
- 当页面存在进行中的 SSE / restore 流式响应时，自动治理会使用内存中的待落盘快照进行估算；达到阈值后只压缩持久化投影，不干扰已显示 DOM 或当前流式消息引用

## 迭代 20260718-6：流式响应本地存储保护

- 长时间 SSE 响应期间，页面会按每个收到的可持久化流式包做轻量体积估算；没有 SSE 包时不会额外启动高频存储任务
- 预估达到 `2.5 MB` 才会精确计算并压缩 `localStorage`，目标回收至约 `2 MB`；压缩后至少累积约 `64 KB` 的预计增长才再次精确检查，以减少对流式渲染的影响
- 流中压缩优先删除原始 SSE、思考快照、备忘录查询缓存和旧历史；极端情况下，只有持久化版本的正文会被收敛为首尾保留的恢复窗口
- 当前页面已经展示的正文、正在输出的消息气泡和右侧 CLI 子任务不会被删除、截断、替换或重新渲染；压缩仅影响刷新页面后可恢复的本地历史

## 迭代 20260711-4：两段式启动接管

- 集成入口首次打开站点时，浏览器会先进入轻量 `/launch` 过渡页，而不是直接打开较重的 `/site/?v=...#app`
