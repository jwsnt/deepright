### 需求介绍
+ 新建HTTP POST服务，路径为/api/cron/create?agentId=xxx，创建指定Agent的备忘录元数据
    + Cron需求：../../../cron/REQUIREMENT.md
    + 属性映射：
        + Cron表达式：可选，默认为空
        + Cron的任务内容：输入框内容
        + Cron的模型：选择的模型
        + Cron的Thinking模式：是否开启Thinking
        + Cron的原始时间：左侧日历日期加右侧的时间（小时+分钟）
        + Cron的使用周期：仅一次，工作日，自然日、每小时、每15分钟、每30分钟
        + Cron的AgentId：当前会话Agent
    + 对周期任务（工作日/自然日）在创建后会立即生成后5天内的所有任务明细，不用等定时器
        + 定时器需求：../../../cron/iteration/20260428-1/REQUIREMENT.md
    + 对一次性任务如果早于当前时间（已过期），则禁止创建（比如当前时间是10点01分，10点禁止执行，10点01分可以执行，10点02分可以执行）
+ 新建HTTP POST服务，路径为/api/cron/delete?id=xxx，删除指定Agent的备忘录元数据
    + 删除元数据和关联明细

### 编写代码
+ 以Golang编写以上代码，要求：
    + 新建高频周期任务（每小时/每15分钟/每30分钟）时，需要和工作日/自然日一样在创建后立即生成后5天内的所有任务明细，不能仅依赖每分钟的定时器延迟创建
    + 每分钟的定时器仍需周期检查所有非一次性任务（包括高频周期），为后续5天补充创建新的任务明细，确保持续运行不遗漏
    + 所有Cron相关HTTP接口和定时任务必须复用启动时初始化的全局数据库连接，禁止每次请求单独打开和关闭数据库文件
    + 能用开源包的就用开源包
    + 代码简洁，包体积越小越好
