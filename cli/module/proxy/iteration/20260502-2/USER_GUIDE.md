# SSE 流式日志落库与恢复回放

## 功能说明

修复流式对话日志保存及 `/api/restore` 恢复回放时的中文乱码问题。

本次调整后，Proxy 在处理 SSE 响应时：

- 前端实时流式输出保持不变
- 会话日志落库改为按完整 SSE event 保存
- `/api/restore` 恢复回放改为按完整 SSE event 回放

完整 SSE event 的最小单位示例：

```text
data: {"choices":[{"delta":{"content":"你好"}}]}

```

即以 `data: {...}\n\n` 为一个完整单元进行处理，而不是按固定字节分片直接转字符串。

## 修复原因

之前日志保存链路是按固定字节块读取 SSE 响应，然后直接将字节块转成字符串写入 `chat_log`。

当 UTF-8 中文字符刚好被切在两个字节块之间时，会在转字符串时被替换为 `�`，最终在居中对话框的恢复回放中显示为 `���` 等乱码。

## 当前行为

- Proxy 仍然会将上游 SSE 原始字节流实时转发给前端
- 仅聊天日志落库粒度从“字节块”改为“完整 SSE event”
- `/api/restore` 读取到的记录也按完整 SSE event 逐条恢复
- 页面刷新后，恢复效果仍然是增量回放，不会退化成一次性整段返回

## 注意事项

- 本次修复只影响新产生的流式日志记录
- 历史库中已经写坏的 `���` 乱码记录不会自动修复
- 如需清除旧乱码内容，需要删除旧会话记录后重新生成
