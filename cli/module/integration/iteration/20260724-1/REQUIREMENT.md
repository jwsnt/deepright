### 需求介绍
+ 从应用资源目录 `config/config.json` 读取以下可选 MCP 配置：
  ```json
  {
    "mcp": {
      "interval": 30,
      "file": "mcp.json"
    }
  }
  ```
+ `mcp.interval` 是正整数秒。Integration 首次需要 MCP 元数据时，以及其后每隔该间隔，遍历当前 Agent 列表并检查每个 Agent 工作目录中的 `mcp.file`。`mcp.file` 必须是工作目录内的相对路径；不得接受绝对路径、空路径或可逃逸工作目录的路径。
+ 请求属于 Agent X 时，只使用 X 工作目录下的 MCP 文件检查结果。通过检查时，在最终发往上游的请求顶层 `metadata` 增加 `mcp`，值为该 MCP 文件的系统绝对路径（例如 `/path/to/agents/X/mcp.json`）；不得传送文件内容或其他 Agent 的结果。
+ 判定 MCP 文件有效的条件是：文件存在、去除空白后有内容、能够解析为 JSON 对象或 JSON 数组，且对象至少有一个属性或数组至少有一个元素。非空 JSON 标量（例如 `null`、字符串、数字和布尔值）不属于有效 MCP 配置。
+ 文件不存在、空白、`{}` 或 `[]` 均表示该 Agent 当前没有 MCP 配置：不得添加 `metadata.mcp`，也不得产生页面错误提示。
+ 文件有内容但无法解析为 JSON 对象或数组（包括 JSON 语法错误和非空 JSON 标量）时，不得添加 `metadata.mcp`，并在页面展示与 `SKILL.md` 校验失败相同样式的 Agent 级错误提示。MCP 提示必须使用独立的数据、接口与刷新链路，禁止复用 `/skills_warning`。下次周期检查后，文件改为有效、空白、`{}`、`[]` 或删除时，必须清除该错误提示。
+ 该逻辑必须覆盖所有向上游发送的相关请求：普通页面对话的 `/v1/chat/completions`、备忘录定时任务、飞书插件任务、邮件插件任务，以及 Integration 主动发起的 `/cli/get`。备忘录、飞书和邮件的任务即使绕过普通聊天处理器，也必须获得相同结果。
+ 客户端请求中伪造或遗留的 `metadata.mcp` 不得透传；仅能由本次 Agent 工作目录检查结果写入。缓存刷新期间必须保证并发请求读取一致的同一批检查结果。

### 编写代码
+ 以 Golang 实现 MCP 配置读取、路径校验、JSON 对象/数组内容判定、按 Agent 刷新状态和元数据注入；优先复用已有配置读取、Agent 元数据、页面告警和请求元数据合并机制，不增加依赖。
+ 刷新状态须以配置的间隔为准，并按 Agent ID 保存有效 MCP 文件的系统绝对路径与解析错误状态。告警接口和页面仍只使用相对路径，避免向页面暴露本机绝对路径。首次请求立即检查；配置的文件名或间隔变化后，下一次检查应使用新配置。
+ 在 `../../main.go` 的普通聊天转发、`/cli/get` 心跳及定时任务直连上游的请求构造处使用同一个注入函数。定时任务覆盖 `cron`、`feishu` 和 `mail` 类型，确保备忘录与两个插件不依赖普通聊天处理器。
+ 新增独立的 MCP 页面告警接口与状态；页面可沿用 `SKILL.md` 解析错误的红色文件标记、错误浮层和清理交互，但不得读取、写入或调用 `/skills_warning`。告警按 Agent 隔离；仅允许在上游请求的 `metadata.mcp` 传递 MCP 文件的系统绝对路径，不得将 MCP 内容、绝对路径或原始解析错误回显到日志或页面。
+ 覆盖自动化测试：配置缺失或非法、相对路径校验、首次与间隔刷新、每个 Agent 独立结果、有效非空对象/数组、空对象/数组、空文件、缺失文件、语法错误、JSON 标量、错误提示的产生与清除、客户端伪造字段剥离，以及普通聊天、`/cli/get`、备忘录、飞书和邮件任务的请求元数据。
+ 作为其他模块可以调用的子模块和可独立运行的CLI命令来编写
+ 最小范围更新
