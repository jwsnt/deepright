### 需求介绍
+ 备忘录、邮件、飞书及其他由 Integration 自动触发的任务，在请求 `/v1/chat/completions` 时，当前只会传递 `__provider` 和 `__token`；需要补齐与居中对话输入框一致的模型客户化配置。
+ 自动触发任务必须按任务选择的模型传递当前有效的 `__url`、`__model`、`__model_fast`、`__model_multi_input`、`__model_thinking`、`__model_multi_output`；各字段的取值、默认值补全、模型名归一化和非空字段传递规则必须与居中对话输入框完全一致。
+ 本需求只调整 Integration 自动任务执行链路，不改变备忘录、邮件、飞书等任务的创建接口、任务表结构、模型配置接口和居中对话输入框的既有行为。

### 技术实现
+ 适用范围：
    + 覆盖由 `task_detail` 执行器发起的所有自动任务，不得按任务类型分别实现或遗漏。
    + 至少覆盖备忘录/普通定时任务、邮件、飞书；后续新增且复用同一任务执行器的触发类型自动继承此行为。
    + 不影响用户从居中对话输入框直接发起请求时已有的 metadata 合并和模型配置传递逻辑。
+ 配置读取与取值：
    + 每次任务实际执行、组装上游请求 metadata 前，使用任务的 `model` 从 Integration 当前数据目录的 `token_store` 查询模型配置。
    + 查询、模型名归一化、默认值补全及客户化配置的有效性判定必须复用或等价复用居中对话转发链路的实现；禁止维护第二套 provider 默认值或模型配置映射。
    + 任务创建时不得把 `__url`、`__model`、`__model_fast`、`__model_multi_input`、`__model_thinking`、`__model_multi_output` 快照保存到 `task_meta`、`task_detail` 或其他任务持久化记录中。
    + 因此任务执行前更新同一模型的 URL 或模型配置后，下一次执行必须立即使用更新后的配置；已创建但尚未执行的任务不需要重新创建。
+ Metadata 组装与覆盖规则：
    + 在自动任务现有的 Agent、会话、任务类型、`thinking`、`verify`、路由、知识库、沙盒和插件 metadata 完成组装后、请求序列化前，注入模型客户化配置。
    + `__url`、`__model`、`__model_fast`、`__model_multi_input`、`__model_thinking`、`__model_multi_output` 均仅在当前模型配置中的值有效且非空时写入 metadata；未配置、空字符串或该 provider 不支持的字段不得写入空值或伪默认值。
    + 已注入字段必须覆盖自动任务组装过程中同名的陈旧值，确保上游收到的值与该次执行时居中对话输入框会使用的值相同。
    + 保持现有 `__provider`、`__token` 及 `Authorization` 传递方式不变；本需求不得把 token 写入任务表、普通日志、错误日志或新增的响应字段。
    + 请求日志、调试输出和实际发送给上游的请求必须使用同一份已补齐 metadata，便于排障；日志展示 token 时必须继续遵守既有脱敏规则。
+ 失败与兼容：
    + 读取模型配置失败时，沿用自动任务当前的失败、重试/状态回退和日志行为，不得发送一份缺少客户化配置的降级请求。
    + 模型仅配置 token、未配置上述任一客户化字段时，自动任务继续按现有行为执行；metadata 中不新增这些空字段。
    + 不新增或变更对外 HTTP/CLI 参数，不迁移既有任务数据，不改变任务的 `model`、`thinking`、`verify` 和 `router_disable` 语义。
+ 测试要求：
    + 覆盖普通备忘录任务、邮件任务和飞书任务三类自动触发任务；验证三者均使用同一套 metadata 注入逻辑。
    + 对配置了六个字段的模型，捕获实际发往上游的请求，断言 `__url`、`__model`、`__model_fast`、`__model_multi_input`、`__model_thinking`、`__model_multi_output` 的值与居中对话请求一致，并保留 `__provider`、`__token` 的既有行为。
    + 覆盖部分字段为空的模型配置：只传递有效非空字段，空字段不得出现在 metadata 中。
    + 创建任务后修改 `token_store` 中的 URL 或任一模型字段再执行，断言上游收到更新后的值，证明配置按执行时读取而非创建时快照。
    + 覆盖模型配置读取失败和仅配置 token 两种场景，验证不回归现有任务状态、认证和错误处理逻辑。
