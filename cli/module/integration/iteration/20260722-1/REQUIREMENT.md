### 需求介绍
+ 新增一个受服务端保护的单一“立即运行”创建接口，例如 `POST /api/cron/detail/run?agentId=xxx`。接口只负责创建一条当前时间的 `task_detail`，不直接调用模型、不修改任务状态为已启动，也不等待或返回任务完成结果。
+ 请求必须显式区分来源并只接受以下最小参数：`sourceType`（`detail` 或 `meta`）、`detailId` 或 `metaId`、`reuseChat`。`agentId` 保持沿用 cron API 的查询参数语义。不得接受来自前端的模型、内容、时间、状态、Agent、响应结构、任务类型或其他可继承业务字段。
+ 明细来源规则：
    + 读取并验证指定明细归属 `agentId`，以及其关联的元数据仍存在且同属该 Agent；找不到、无归属或关联元数据失效时返回现有 JSON 错误结构。
    + 仅允许源明细 `started` 为 `0`（待执行）、`2`（无需启动）或 `3`（已完成）。`started = 1`（已启动）必须被服务端拒绝，即使客户端绕过隐藏图标直接请求接口也不得创建重跑明细。
    + 新明细继承源明细的 `meta_id`、`agent_id`、模型、Thinking、校验、SWARM、内容、响应结构和任务类型；不得复制明细 ID、`started`、结果内容、完成/回复时间或其他运行结果字段。
    + `reuseChat = true` 时继承源明细 `chat_id`；`reuseChat = false` 时写入空 `chat_id`。
+ 元数据来源规则：
    + 验证元数据归属 `agentId` 后，读取元数据并创建关联至该 `meta_id` 的一条新明细。新明细继承元数据的 Agent、模型、Thinking、校验、SWARM、内容、响应结构和任务类型；`reuseChat = true` 时继承元数据 `chat_id`，否则写入空值。
    + 该入口仅插入一条即时明细，不得调用 Cron 解析、未来窗口补全或标准周期拆分逻辑，不得修改 `task_meta` 或既有任何明细；因此它不受 Cron/周期限制。
+ 两种来源均以服务端生成的当前 Unix 秒级时间写入 `exec_time`，初始状态固定为 `started = 0`（待执行）。该状态仍由既有执行器在后续轮询中处理，必须继续遵守 Agent 暂停、模型配置/可用性、已删除 Agent 和其他既有运行门禁。
+ 创建必须在一个事务内完成：验证来源与归属、读取继承字段、插入新明细、写入现有 `cron_detail_log` 审计记录。任一步失败均整体回滚，不得出现没有审计记录的明细或没有对应明细的成功审计记录。
+ `task_detail` 的 `(meta_id, exec_time)` 唯一约束必须保留。若当前秒发生并发或重复点击导致冲突，服务端应在同一事务内以递增秒数重试，直至插入成功；响应必须返回实际写入的明细和执行时间。重试耗尽时返回明确错误并回滚，不得静默忽略请求。
+ 成功响应沿用现有 cron API JSON 风格，至少返回 `status: 0` 和新建的完整任务明细；失败响应返回 `status: 1` 与可展示的 `content`。接口必须校验 HTTP 方法、数据库就绪状态、Agent 存在性、来源类型、ID、`reuseChat` 布尔值和来源必要继承字段的完整性。

### 编写代码
+ 以Golang编写以上代码，要求：
    + 能用开源包的就用开源包
    + 代码简洁，包体积越小越好
    + 在 `../../main.go` 复用既有 cron 数据模型、`ensureCronSchema`、Agent/模型校验、SQLite 事务、任务明细查询和 `appendCronDetailLog`；不得通过前端组合现有创建、状态更新或周期拆分接口实现。
    + 将接口注册到 Integration 的 HTTP mux，并保持 `/api/cron/detail/*` 现有路由、响应结构和认证/归属校验风格兼容；不得修改既有任务创建、更新、删除、周期生成或轮询执行语义。
    + 插入后的审计日志 `action` 使用清晰且稳定的立即运行创建标识，并记录实际 `exec_time`、继承字段与 `started = 0`；日志写入必须随事务提交，不能在事务失败后单独落库。
    + 覆盖自动化测试：明细来源的三种可运行状态、已启动拒绝、元数据来源、两种会话复用模式、字段继承与结果字段清空、非法 Agent/来源/ID/参数、元数据归属失效、事务回滚、审计记录、同秒冲突重试，以及确认任务在后续执行器轮询前始终为待执行。
+ 作为其他模块可以调用的子模块和可独立运行的CLI命令来编写
+ 最小范围更新
