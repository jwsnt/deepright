# 视频切分画面裁剪接口

`POST /api/video_trim` 在已有时间切分字段之外，可选接收结构化 `crop`。不传 `crop` 时保持原有视频切分行为。示例：

```json
{
  "agentId": "AgentId",
  "path": "media/source.mp4",
  "start": 0,
  "end": 12.5,
  "crop": {
    "shape": "ellipse",
    "background": "black",
    "x": 0.1,
    "y": 0.15,
    "width": 0.8,
    "height": 0.7
  }
}
```

- `shape` 仅接受 `rect`、`ellipse` 或 `polygon`；矩形和椭圆使用源画面比例坐标 `x`、`y`、`width`、`height`。`polygon` 使用至少三项、最多 48 项的 `points: [{"x": 0.1, "y": 0.2}]` 闭合多边形。
- `start` 与 `end` 必须是有限的非负秒数且 `end > start`。时间滑块虽然按 `0.5` 秒定位，但整段导出可传媒体真实结束时长（例如 `12.4`），不会因非半秒整数而被拒绝。
- 所有坐标必须是 `0–1` 内的有限数值，选区必须在源画面内且有面积。`background` 仅接受 `black` 或 `white`，省略时为 `black`。未知字段和退化、越界或过长的选区会被拒绝。
- 服务端从经过校验的几何数据自行生成固定 FFmpeg filter graph：选区内容等比缩放并居中至源画布，比例差、椭圆外部和多边形外部以黑/白填充；必要时只向右/下补至偶数像素以满足 H.264。
- 接口不接受客户端滤镜、命令或任意输出路径。源和输出仍受当前 Agent 工作区约束，成功文件固定另存到 `videos/`，同名不覆盖；为保持高分辨率源画布，受控转码最长可运行 `15` 分钟。失败、超时或依赖缺失不会保留最终文件。
