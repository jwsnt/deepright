### 需求介绍
+ Integration 在 macOS 上仅按需持有 `caffeinate -d -i -m -s` 子进程；不修改屏幕保护、自动锁屏或其他系统偏好，也不支持合上笔记本盖子后继续运行。
+ 防休眠条件采用“任一满足即开启”：
    + 飞书或邮件关联插件已经成功启动；
    + 存在状态仍为待处理、计划执行时间位于 `[当前时间, 当前时间 + 24 小时)` 的备忘录任务；
    + 存在尚未结束的 SSE 响应。
+ `config/config.json` 必须提供顶层正整数 `caffeinate`，单位为分钟，作为条件定时复核间隔；缺失、非整数或小于等于零时必须记录清晰日志并拒绝启动 Integration。配置只在服务启动时读取，变更后重启生效；不得在代码中硬编码扫描间隔。
+ 服务启动后应立即执行一次条件评估，并按 `caffeinate` 配置周期复核。SSE 开始、正常完成、上游错误、EOF、解析失败、客户端断开、写入失败、请求或服务上下文取消等状态变化必须立即重新评估，不能等待下一次定时扫描。
+ SSE 仅在响应真实存活期间计入条件；无论正常完成还是异常终止都必须安全注销，重复注销不得改变结果。应有定时兜底复核，避免异常路径遗漏导致长期保留防休眠。
+ 条件从不满足变为满足时创建并持有一个 `caffeinate` 子进程；条件全部不满足时终止该子进程并允许系统休眠。不得创建多个并发的防休眠子进程；子进程意外退出后，后续评估满足条件时可以重新创建。
+ `caffeinate` 仅可在 macOS 启动。Linux、WSL、Windows 和其他平台不得执行该命令，且保持原有启动行为。
+ 若 macOS 无法找到或启动 `caffeinate`，记录清晰日志后继续运行，不得使服务启动失败。
+ 正常退出、`SIGINT`、`SIGTERM`、`integration stop`、重启前停止及本机 `/api/shutdown` 必须先停止条件检查并禁止重新拉起 `caffeinate`，随后尽力终止由当前进程创建的 `caffeinate`，最后再释放插件、任务、HTTP 服务、连接和其他资源。终止失败、子进程已退出或等待超时只能记录日志，不得阻断应用关闭与后续资源释放；重复关闭必须安全。
+ 覆盖测试：配置校验、三类条件及其组合、非 macOS 跳过、SSE 正常及异常终止、条件切换、子进程异常退出后的重建、`caffeinate` 启动失败、关闭顺序与停止失败不阻断资源释放。
