### 需求介绍
+ 主应用随包发布的静态 `config/config.json` 新增（或使用已有）`backup` 对象：`backup.skills` 与 `backup.app` 均为正整数，单位为分钟，分别控制 Agent `skills/` 与 `app/` 的本地 Git 备份周期。发布默认值均为 `30`。
+ Integration 启动后必须在后台立即分别执行一次 `skills` 与 `app` 备份，之后按各自配置的分钟间隔重复执行；两条备份链路必须相互独立，并且不得阻塞服务启动、HTTP 请求、聊天转发、定时任务或其他后台工作。
+ `--agent-dir` 的每个一级目录均视为一个 Agent 工作目录。对每个 Agent 的 `skills/`、`app/`，在该目录内分别维护独立的本地 Git 仓库；只允许本地初始化、暂存与提交，禁止配置远程仓库、拉取、推送或执行其他网络 Git 操作。缺少目标目录时跳过该目录，不创建空目录。
+ 备份必须递归保留所有符合条件的普通文件、符号链接、隐藏文件、目录层级与现有 `.gitignore` 文件；Git 自身不能表示的空目录不备份。备份不得遵从源目录 `.gitignore` 排除普通内容：除本需求明确过滤的项目外，符合条件的文件均必须进入 Git 索引。
+ 所有文件扩展名按大小写无关的内置二进制扩展名表判定；命中图片、音视频、压缩包、可执行文件、动态库、字节码、Office/PDF、字体、磁盘镜像、数据库等二进制扩展名的文件一律不备份。文件大小严格大于 `10,000,000` 字节（10MB）的文件一律不备份；恰好 10MB 的文件允许备份。文件之后变为被过滤、被删除或不再是可备份类型时，必须从对应 Git 索引移除，但不得删除工作目录中的源文件。
+ 每个目录只在暂存区有实际变更时创建本地提交，无变更时不创建空提交。提交需要可在未预先设置全局 Git 身份的环境中完成，且不得覆盖已有 Git 身份。单个 Agent 或单个目录的扫描、Git 初始化、暂存或提交失败时，必须记录包含 Agent、目录、仓库路径和错误原因的 Integration 日志，并继续处理其余目录与 Agent。
+ 虚拟文件系统每次进入当前 Agent 工作目录根下的 `skills/` 或 `app/` 时，必须提示该目录最后一次成功备份的本地时间；只读取对应独立仓库最近一条 `deepright backup` 提交时间，普通 Git 提交不得视为备份。尚无成功备份时应明确提示暂无已提交备份；查询失败时不显示伪造时间，也不得阻止目录内容加载。
