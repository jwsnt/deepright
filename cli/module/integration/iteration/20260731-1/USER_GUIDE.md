# Agent `skills` 与 `app` 本地 Git 备份使用手册

主应用静态 `config/config.json` 使用 `backup` 配置每个 Agent 工作目录中 `skills/`、`app/` 的本地 Git 备份周期，单位为分钟：

```json
"backup": {
  "skills": 30,
  "app": 30
}
```

`skills` 与 `app` 都必须是正整数。Integration 启动后会在后台分别立即备份一次，随后各自按配置间隔运行。任一值缺失、不是正整数、不是对象或超出 `time.Duration` 范围时，整个备份功能禁用并记录配置错误；这不会阻塞 Integration 的 HTTP 服务或其他后台功能。

Integration 扫描 `--agent-dir` 的所有一级目录。每个存在的 `<Agent>/skills/` 与 `<Agent>/app/` 都有独立的本地 Git 仓库：仓库分别位于各自目录的 `.git/` 中。备份只执行本地初始化、暂存与提交，不配置远程仓库，也不会拉取或推送；不存在的 `skills/` 或 `app/` 目录会跳过，不会创建空目录。

备份会递归保留合规的普通文件、符号链接、隐藏文件、目录结构和原有 `.gitignore`。即使源 `.gitignore` 忽略了某项，合规文件仍会被强制纳入备份；空目录因 Git 的限制不会备份。

以下文件不会进入 Git：命中内置二进制扩展名表的图片、媒体、压缩包、可执行文件、动态库、字节码、Office/PDF、字体、镜像或数据库文件，以及严格大于 `10,000,000` 字节的文件。扩展名比较不区分大小写，恰好 10MB 的文件允许备份。已经被跟踪的文件若之后删除、变为被过滤类型或超过大小限制，只会从 Git 索引删除，工作目录里的源文件不会被删除。

没有变更时不会创建空提交。Git 未设置身份时，Integration 仅为该备份仓库设置本地提交身份，不覆盖已有身份。单个目录发生扫描、初始化、暂存或提交错误时，Integration 日志会记录 Agent、目录、仓库路径和错误原因，并继续处理剩余 Agent 与目录。

进入虚拟文件系统的 `skills/` 或 `app/` 根目录时，界面会异步提示最后备份的本地时间。该时间只读取对应仓库最近一条 `deepright backup` 提交，不会把手动创建的普通 Git 提交当成备份；尚未成功提交则提示“暂无已提交备份”。查询异常不会阻止目录内容显示，也不会展示不确定的时间。
