### 需求介绍

Integration 新增基于 `rembg` 的图片主体提取队列。该队列与 Whisper 转写队列相互独立，但采用相同的持久化、状态管理、列表、取消、重试、失败删除与日志语义。

- 活动 `config/config.json` 必须提供 `rembg` 对象：`check` 为正整数小时，`install` 为非空安装请求文本。`GET /api/rembg/check` 必须读取并校验这两项配置；配置缺失或无效时返回可展示错误，不使用隐式默认值。
- 检查接口只可验证受控运行环境中 `rembg --help` 能否启动。服务须继承用户已配置及已发现的 Python 运行时脚本目录：macOS 包括用户安装目录、Python Framework、pyenv、conda、venv、Poetry、asdf 与 mise；Linux/WSL 还须向隔离执行环境只读挂入相应 Python 运行时。检查成功可按 `rembg.check` 缓存；命令不存在、失效或不能启动时，返回 `rembg.install`，不得执行安装、创建任务或写入 Agent 工作区。
- 服务启动时必须幂等创建共享 SQLite 的 `rembg_task` 表，并持久化任务 ID、Agent ID、源图片相对路径、输出相对路径与绝对路径、模型、`alpha matting` 开关、状态、进度、开始时间、创建/更新时间、取消标记与受限大小的执行日志。既有数据库启动时须无损补充模型与开关列；刷新页面或重启服务后，完成、失败与取消任务仍须可查询。
- 任务创建仅接受当前 Agent 工作区内的图片相对路径，拒绝绝对路径、`~`、`..` 逃逸、目录、跨 Agent 路径、符号链接逃逸、未知字段及非图片内容。图片类型须同时经过服务端允许的图片扩展名与文件内容检测；源图片不得被覆盖、删除或改名。
- 允许的图片类型应纳入受控媒体 MIME 白名单，以便路径解析、任务校验与图片预览使用同一安全范围；PNG、JPEG、GIF、WebP、BMP 与 TIFF 的检测不得仅信任文件名后缀。
- 每个任务必须独立保存所选模型；空模型默认 `u2net`（通用）。仅允许受控模型白名单：`u2net_human_seg`、`isnet-general-use`、`u2net`、`u2netp`、`u2net_cloth_seg`、`silueta`、`isnet-anime`，未知模型不得传入子进程。每个任务还可独立保存并启用 `--alpha-matting`。
- 每个任务只能以服务端决定的 `rembg i -m <模型> [--alpha-matting] <source> <output>` 参数执行。模型尚未缓存时，必须由 rembg 在该任务执行过程中自动下载，下载输出与失败原因须写入任务日志。输出必须固定为当前 Agent 工作目录 `images/` 下的透明背景 PNG，默认文件名为 `<源文件名>_subject.png`；已有文件或当前 Agent 已分配的任务输出冲突时，自动追加时间戳与必要序号，绝不覆盖已有文件。
- 队列在全部 Agent 间一次只执行一个图片任务，并按创建顺序调度。创建后为 `queued`；当前任务完成、失败或取消后立即继续下一条。取消接口必须同时取消排队任务和终止正在执行的 `rembg` 子进程。
- 执行状态、进度与标准输出/错误输出须持续写入数据库。任务开始进度为 `0`，仅在成功生成非空 PNG 后置为 `100`；不允许伪造处理中百分比。命令失败、取消或输出无效时不得留下半成品输出文件。
- 服务重启时，未请求取消的 `running` 任务必须恢复为 `queued` 并追加恢复日志；带取消标记的运行中任务转为 `cancelled`。`completed`、`failed` 与 `cancelled` 历史任务不得自动重复执行。
- 已取消任务可重新开始，并必须重新分配安全且不冲突的输出路径；失败任务仅可删除当前 Agent 的失败任务记录，删除不得影响源图片、已生成图片或其它任务。
- 提供受控 HTTP 接口：`GET /api/rembg/check`、`GET/POST /api/rembg/tasks`、`POST /api/rembg/tasks/cancel`、`POST /api/rembg/tasks/restart`、`POST /api/rembg/tasks/delete`、`GET /api/rembg/tasks/log`。列表支持 `queued`、`running`、`completed`、`cancelled`、`failed` 筛选，固定每页 5 条并返回总数和实际页码；任务接口沿用 `status` / `content` JSON 响应约定，且不得泄漏其它 Agent 的文件信息。

### 需求介绍

Integration 新增一套持久化、串行执行的 Whisper 音频转文字任务队列。每个任务独立选择受控转写场景，默认“中文会议”，并在可用时优先使用 GPU。

- 活动 `config/config.json` 新增 `whisper` 配置，格式与现有 `ffmpeg` 检查一致：`check` 为正整数小时，`install` 为非空安装请求文本。`GET /api/whisper/check` 必须验证受控运行环境中的 `whisper` 命令存在且可用；除进程 `PATH` 外，macOS 还必须识别当前用户标准 `~/Library/Python/*/bin/whisper` 安装位置。成功结果可按 `check` 缓存，并将通过验证的同一命令用于转写。不得执行安装命令、创建任务或修改 Agent 工作区；命令缺失、失效或无法启动时返回安装请求，前端不得打开任务浮层。
- Integration 服务启动时必须构建并固定一份规范化的命令环境，供 Whisper/FFmpeg 依赖检查、Integration `cmd`、`CLI_SANDBOX`、独立 `cli/get` 及其普通或沙箱任务执行共同使用。macOS 规范化 `PATH` 必须动态合并当前用户实际存在的 `~/Library/Python/*/bin`；WSL/Linux 必须动态合并 `~/.local/bin`（以及既有系统、Shell、启动服务和用户级目录），不得硬编码用户名或 Python 版本。WSL `CLI_SANDBOX` 使用隔离环境时，仅可只读挂载 `.local/bin` 和实际存在的 Python `site-packages` 并设置对应 `PATH`、`PYTHONPATH`，不得暴露整个用户目录；所有子进程必须在可访问范围内继承同一命令解析结果，确保依赖检查与实际任务一致。
- Whisper 缺失时，检查接口返回已校验的安装请求；前端经用户确认后将其作为消息发送到当前 Chat。配置缺失或无效时返回可展示的错误，且不使用隐式默认值。
- 转写任务必须持久化到共享 SQLite，至少保存：任务 ID、Agent ID、源音频相对路径、场景、开始时间、状态、进度、文本相对路径与绝对路径、执行日志、创建/更新时间和取消标记。既有数据库必须无损补充场景列，既有和未传场景的任务均默认“中文会议”；服务重启后仍可查询完成、失败和取消的历史任务。
- 任务创建接口仅接受当前 Agent 工作区内、服务端允许预览的音频相对路径；拒绝绝对路径、`~`、`..` 逃逸、目录、视频、跨 Agent 路径、符号链接逃逸及未知字段。源音频不可被覆盖、删除或改名。
- 每个任务只能使用服务端白名单中的场景及对应安全参数，浏览器、CLI 和 HTTP 调用均不得传入任意 Whisper 命令行参数。场景为：默认“中文会议”（`chinese_meeting`，`small`、中文、`temperature=0`、`beam_size=5`）、“专业转写”（`chinese_accurate`，`large-v3` 与专业术语提示）、“低延迟”（`realtime`，`base`、`beam_size=1`、不依赖前文）、“批量处理”（`batch`，`small`、`beam_size=3`）、“CPU 轻量”（`cpu`，`base`、`beam_size=1` 且强制 CPU）和“中英技术”（`mixed_technical`，`medium` 与中英技术提示）。输出文本固定写入当前 Agent 工作目录下的 `whisper/`，优先使用与源音频同名的 `.txt`；若同名文件或已有任务输出已存在，服务端自动追加时间戳（必要时追加序号）生成新路径，绝不覆盖已有文本。
- 队列全局一次只运行一个任务，按照创建顺序调度。创建任务后状态为排队中；当前任务完成、失败或取消后，立即选择下一个排队任务。任务取消接口应同时支持取消排队任务和终止正在执行的 Whisper 子进程。
- 执行日志、状态和进度持续写入数据库；创建与执行日志必须体现所选场景，执行日志还须记录本次实际使用的模型、语言、任务类型、温度、搜索宽度、前文上下文、提示词是否启用及 `fp16` 参数。服务端应从 Whisper 输出中尽可能识别百分比进度，无法识别时仍保持“执行中”状态且不得伪造进度。日志须限制单任务持久化体积，防止不受控输出无限增长。
- 已取消任务重新开始时，应重新分配安全的文字输出路径并保留原场景；若重新开始失败，失败原因必须追加到该任务的持久化日志，以便前端日志视图可追溯。
- 失败任务允许从任务列表删除。删除仅移除当前 Agent 的失败任务数据库记录，不得删除源音频、文字输出文件或任何非失败任务。
- GPU 使用优先级为 CUDA、Apple MPS、CPU 回退。服务端只能基于运行环境可验证的能力选择设备；GPU 不可用或不被当前 Whisper 环境支持时，记录原因并以 CPU 完成任务。若 GPU 已通过探测但 Whisper 实际加载或转写失败，任务必须保留失败输出日志并自动使用 CPU 重试一次；CPU 重试仍失败时才标记任务失败。设备探测与回退不得阻塞后续队列调度。
- 提供受控 HTTP 接口用于：查询当前 Agent 的任务列表、创建一批任务、取消指定任务、重新开始指定的已取消任务、查询指定任务日志。任务列表支持上述状态筛选，固定每页返回 5 条、总数和实际页码；响应不得泄漏其它 Agent 工作区的文件信息或任意系统路径。
- 服务启动时，先将中断的“执行中”任务恢复为排队中并追加恢复日志，再继续调度；不会将已取消、完成或失败任务重新执行。
