### 需求介绍
+ 居中对话区 assistant Markdown 代码块的折叠按钮不能只按“代码块字符数是否超过1000”决定
    + 当前仅当代码块内部纯文本字符数大于1000时，才显示折叠按钮
    + 这会导致“视觉上已经很高、需要折叠，但字符数不足1000”的代码块没有折叠按钮
    + 例如多行 Python 代码、中文提示较多但总字符数不足1000的代码块，用户会看到运行和复制按钮，但看不到折叠按钮
+ 代码块折叠按钮改为多条件判定，满足任一条件都要显示折叠按钮
    + 条件一：代码块内部纯文本字符数大于1000
    + 条件二：代码块内部总行数大于18行
    + 条件三：代码块实际渲染高度超过折叠高度阈值
+ 代码块折叠高度阈值保持现有视觉设计，不新增新的展开区样式体系
    + 折叠高度继续使用现有的360px
    + 实际高度判断允许极小的测量容差，避免浏览器布局抖动导致边界反复切换
+ 新逻辑必须兼容现有代码块增强链路
    + 首次全量渲染时生成的代码块要生效
    + SSE流式渲染过程中实时生成和刷新的代码块要生效
    + 历史消息懒加载、恢复渲染后的代码块也要生效
    + 不破坏现有代码块工具栏顺序，仍保持折叠/运行到CMD/复制代码的现有组织方式
+ 新逻辑必须保持已有交互体验
    + 已经不需要折叠的短代码块，不应错误显示折叠按钮
    + 已经处于折叠态的长代码块，仍然默认折叠，并可通过现有展开/收起按钮切换
    + 运行到CMD与复制代码逻辑不变
    + 不引入新的全局配置面板、开关项或额外用户设置
+ 本次需求需要同步编写用户手册
    + 手册中需要说明旧判定问题
    + 手册中需要说明新的字符数/行数/实际高度三重判定
    + 手册中需要说明该逻辑适用的渲染场景：全量渲染、流式渲染、历史恢复/懒加载
