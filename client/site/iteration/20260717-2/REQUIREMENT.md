### 需求介绍
+ 居中对话框需要为“最新一条正常结束的 assistant SSE 响应”增加思考过程查看入口：
    + “最新一条”固定指当前居中对话框中按消息顺序最近一条正常结束的 assistant SSE 消息，不包含用户消息、右侧 CLI 子任务消息、普通 assistant 非 SSE 消息、报错消息、取消消息或终态提示消息。
    + 仅当该消息在本次 SSE 流中曾捕获至少一条可展示思考片段时，才显示思考图标。
    + 思考图标位于该消息右下角操作行的复制图标右侧，与复制图标同尺寸、同一水平操作行，且不得遮挡既有重试、状态或任务类交互热区。
    + 当前会话发起下一条请求后，上一条 SSE 响应的思考图标必须继续保留；在新 SSE 仍在执行期间，用户可继续点击查看原思考过程。
    + 仅当新 SSE 正常结束后，旧消息上的思考图标才隐藏；当前会话始终最多只显示一个此类图标。
+ 图标展示时机与异常边界必须严格收口：
    + SSE 正在流式返回时，不得为正在执行的响应展示新图标；但上一条正常结束响应原有的图标必须继续可见、可点击。
    + 网络异常、用户取消、服务端终态错误、渲染为错误气泡或任何未正常结束的 SSE，均不得为该次异常 SSE 展示新图标；这类失败或取消不得移除上一条正常结束响应已有的图标。
    + 如果正常结束消息没有思考片段，不显示图标。
+ 点击图标后，需要在居中对话框视域正中展示“思考过程”浮层：
    + 浮层必须带遮罩、关闭按钮，支持点击遮罩关闭和按 `Esc` 关闭；关闭时不得影响当前会话、SSE、滚动位置或其他消息操作。
    + 浮层正文按思考片段的捕获顺序展示，继续复用现有 Markdown 渲染能力，不得把思考片段拼回正式 assistant 正文。
    + 浮层内容区使用固定最大高度并允许纵向滚动；滚动条必须可见并可通过拖拉滚动，超长内容不得撑破视口或遮挡关闭入口。
    + 同一片段在现有汇总逻辑中已合并时，浮层按该汇总后的片段展示，不再额外拆分或复制。
    + 思考图标、思考过程浮层、片段卡片、关闭按钮和滚动条必须复用当前主题的 accent、glass、modal 色变量；浅色暖色系与深色冷色系切换后不得残留固定蓝色或其他跨主题色值。
+ 思考片段的持久化与清理状态必须可恢复：
    + assistant 消息对象新增并持久化 `hadThinkingSnapshots` 布尔字段；首次成功捕获可展示思考片段时写为 `true`，用于表示该消息曾拥有思考过程。
    + assistant 消息对象新增并持久化 `thinkingSnapshotsClearedAt` 字段；当本地存储压缩策略删除该消息的 `explodedSnapshots` 思考片段时，写入清理时刻。该字段未设置时表示未发生此类清理。
    + `hadThinkingSnapshots` 与 `thinkingSnapshotsClearedAt` 仅保存轻量状态，不得保存思考正文副本，也不得新增独立的 `localStorage` key 或另一套消息存储。
    + 页面刷新、跨标签同步和历史恢复后，仍需基于这两个字段与现有 `explodedSnapshots` 恢复图标的显隐和点击语义。
+ 思考片段被本地压缩清理后的行为必须明确：
    + 若最新正常结束 assistant SSE 消息满足 `hadThinkingSnapshots === true`，但其思考片段已不存在且 `thinkingSnapshotsClearedAt` 有值，图标仍需显示。
    + 点击此类图标时不得打开空浮层；必须复用虚拟文件系统的 Tips 提示：`思考过程已经被清理`。
    + `explodedSnapshots` 仍存在时优先打开浮层；没有思考片段、也没有上述已清理状态的消息不得显示图标或提示。
    + 现有本地存储预算压缩策略在删除 `explodedSnapshots` 或相关思考快照字段时，必须同步写入 `thinkingSnapshotsClearedAt`，不得只删正文而丢失清理状态。
+ 兼容与验收要求：
    + 不得改变现有思考片段灯泡入口、浮层、SSE 解析、正式正文渲染、复制、重试、URL/路径小气泡、任务气泡和右侧 CLI 子面板的既有行为。
    + 思考图标及其浮层仅作用于居中对话框，不扩展到右侧 CLI 子任务、备忘录、插件或历史恢复中的非 SSE 消息。
    + 浅色和深色主题下，图标、遮罩、浮层、关闭按钮和滚动条均须清晰可用。
