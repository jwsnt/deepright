# 20260704-4 用户手册

本次迭代把 assistant 响应中可识别的文件路径和 URL，从蓝色下划线文本统一升级为行内小气泡，并保留原有动作能力。

## 适用范围

- 仅覆盖 assistant 响应展示链路，包括实时 SSE 增量渲染和 SSE 结束后的历史恢复
- 用户输入框里的既有气泡语义，以及用户消息正文中的蓝色下划线链接规则保持不变
- 识别和归类继续沿用现有消息 URL / 路径提取白名单，不额外放宽可识别范围

## 展示规则

- assistant 响应里识别出的文件路径、`file:///`、`http/https` 会直接渲染为与输入框同风格的行内小气泡
- 文件类小气泡展示文件名或末级路径摘要，URL 小气泡展示可读摘要；超长时按现有截断规则处理
- 每个小气泡内部都会继续绑定完整原始路径或 URL，供复制、预览、下载文件、打开目录、打开网页等动作复用
- 如果 SSE 分片把同一个目标拆到多个 chunk，页面会等提取结果稳定后再气泡化，避免半截路径误显示或前后闪烁
- 同一条 assistant 消息里如果存在多个目标，每个小气泡都会独立绑定自己的完整值和动作，不会串用相邻目标数据

## 点击与动作

- 点击 assistant 小气泡会直接弹出当前消息域已有的动作浮层，不再要求先双击或手动框选文本
- 动作顺序固定为 `复制` 优先：文件/目录类为 `复制`、`预览`、`下载文件`、`打开目录`；普通 `http/https` 为 `复制`、`预览`、`打开`；资源类 `http/https` 为 `复制`、`打开`
- `复制` 会把完整原始路径或 URL 写入系统剪贴板，而不是复制摘要文本；成功后在左侧虚拟文件系统 Tips 位置提示 `已复制到粘贴板`，失败时也会提示错误
- 文件类小气泡的 `预览`、`下载文件`、`打开目录` 行为和出现条件与现有消息路径浮层保持一致；如果目标本身是目录，则不展示 `下载文件`，也不展示无效 `预览`
- `http/https` 小气泡的 `预览`、`打开` 行为和出现条件与现有消息 URL 浮层保持一致；可预览 URL 仍复用右侧 Sidebar iframe，资源类 URL 仍不会进入预览链路

## 兼容与兜底

- 与消息 URL / 路径相关的既有新手引导、浮层层级和交互域隔离规则都已同步适配到 assistant 小气泡方案
- 如果命中原有“文件 URL 操作引导”，引导会直接围绕 assistant 小气泡及其动作浮层高亮，而不再依赖文字选区
- 若仍有少量未被气泡化覆盖的普通文字路径场景，原有双击或选中后弹浮层的兜底交互仍可继续使用
