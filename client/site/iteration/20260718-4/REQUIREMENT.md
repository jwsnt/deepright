### 需求介绍
+ 在设置的“模型与密钥”区域，为新增但尚未保存的模型增加从 CURL 请求导入模型配置的能力，减少手工填写 API Key、请求 URL 和各能力模型名称的操作。
+ 入口与展示规则：
    + 仅当模型行为新增、未保存，且已经选择服务商时，在 API Key 输入框右侧操作区显示 CURL 小图标。
    + 仅支持 `gemini`、`openai`、`kimi`、`bigmodel`、`xiaomi`、`deepseek`、`anthropic`、`minimax`；其他服务商不显示该入口。
    + `seedream` 与 `deepright` 始终不显示 CURL 小图标。
    + 已保存模型不显示 CURL 小图标，远程只读的已保存模型也不显示。
    + 当 Copy 图标存在时，CURL 图标位于其右侧，Copy 图标及密码显示/隐藏图标相应左移；当没有复制来源时，CURL 图标仍显示在操作区最右侧。
+ 浮层交互：
    + 点击 CURL 图标后，设置主浮层进入收起状态而不是关闭状态；原模型行、其他未保存模型行和其输入内容必须保留在 DOM 与运行时草稿中。
    + 在同一设置浮层中展开 CURL 导入浮层，包含固定 `100px` 高度的多行文本输入框，以及“解析”“取消”两个按钮。
    + 浮层沿用站内冷暖主题变量与现有模态动画：输入与解析操作使用冷色强调，取消操作使用中性/暖色系，深浅主题均须可读。
    + 点击“取消”只关闭 CURL 导入浮层并丢弃本次 CURL 文本；不得保存、重置或丢失原设置浮层内的任何未保存模型配置。
    + 解析成功后关闭 CURL 导入浮层，恢复原设置浮层，并回填触发入口所在的模型行；仍须点击设置的既有“保存”按钮才可持久化。
+ CURL 解析范围：
    + 不执行输入的命令，也不请求命令中的 URL；仅在浏览器内解析常见 `curl` 命令参数、请求 URL、请求头和 JSON 请求体。
    + 支持从位置 URL 或 `--url` 参数读取请求地址，从 `-H`/`--header` 读取请求头，从 `-d`、`--data`、`--data-raw`、`--data-binary` 等数据参数读取 JSON 请求体；应兼容单引号、双引号、反斜杠换行和常用空白分隔。
    + `gemini` 使用 Gemini 协议：模型优先从 URL 的 `models/{model}` 路径提取，API Key 从 URL 查询参数 `key` 或 `x-goog-api-key` 请求头提取。
    + `openai`、`kimi`、`bigmodel`、`xiaomi`、`deepseek` 使用 OpenAI 兼容协议：模型从 JSON 请求体的 `model` 提取，API Key 从 `Authorization: Bearer ...` 请求头提取；同时兼容 `api-key` 与 `x-api-key` 请求头。
    + `anthropic`、`minimax` 使用 Anthropic 协议：模型从 JSON 请求体的 `model` 提取，API Key 从 `x-api-key` 请求头提取；兼容 `Authorization: Bearer ...` 作为回退来源。
    + 不支持 `vertex` 协议或 Vertex CURL 请求。
+ 回填与错误处理：
    + 解析结果必须同时具备 URL、模型和 API Key。任一必填信息无法解析、输入不是可识别的 CURL 命令、请求体不是可解析 JSON 或协议与当前服务商不匹配时，显示明确错误并保持原模型表单不变。
    + API Key 或模型值若只是 `$OPENAI_API_KEY` 这类 shell 变量引用，提示用户粘贴实际值；页面不得读取或展开本机 shell 环境变量。
    + 回填 URL 至当前服务商的模型 URL 字段，回填 API Key 至密钥字段。
    + Gemini URL 查询参数中的 `key` 仅用于提取 API Key；回填 URL 时移除该敏感参数，避免密钥在普通 URL 输入框中重复明文出现。
    + 一个 CURL 只解析一个模型；解析出的模型值同时回填当前服务商全部可配置模型字段：基础模型、快速响应、深度思考，以及该服务商支持的多模态输入/输出字段。
    + 当前服务商不支持的配置字段继续保持禁用，不因导入动作改变支持范围或编辑权限。
    + 导入不得修改其他模型配置、不得自动发起保存请求、不得在错误提示或界面中明文额外展示 API Key。

    + 能用现有开源包和浏览器能力的就不要重复造轮子
