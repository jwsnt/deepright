### 需求介绍

在当前会话 Agent 工作区的 `app/` 目录中，“迷你应用”浮层为每个 HTML 迷你应用增加 Debug 入口。该入口必须生成一条普通的当前会话消息，用于请求修复对应 HTML 文件；浏览器不得直接修改迷你应用文件或执行修复命令。

- 保持既有 HTML 与 Markdown 的配对规则。浮层仅显示 `HTML`、`MD` 两个列表标题；每个 HTML 行的 Debug 瓢虫小图标必须置于同一行 MD 单元格的右侧，图标目标始终是该行的 HTML 文件，而不是配对的 Markdown 文件。
- 两列宽度应随浮层可用宽度自适应。MD 文件名占用图标左侧的剩余空间，名称过长时单行以 `…` 截断并保留原生完整名称提示；瓢虫图标保持紧凑固定尺寸，必须完整位于 MD 单元格和浮层可视边界内，不得形成额外列、越出边界或被裁切。
- 点击 Debug 图标前必须确认当前仍处于 `app/` 目录、目标 HTML 仍在当前列表，且当前 Chat 与 Agent 可用。打开后关闭迷你应用列表，并在居中域显示唯一的“调试迷你应用”模态浮层；浮层与其它居中域前景浮层互斥，隐藏时完全失活。
- 浮层必须以单行展示所选 HTML 文件的文件系统绝对路径，路径区域随浮层宽度自适应；超出时以 `…` 截断，悬停以原生提示展示完整路径。浅色主题使用暖色系，深色主题使用冷色系；两种主题均应保证标题、路径、输入、错误和按钮对比度可读。
- “修复原因”使用固定高度的可编辑输入区，超出内容仅在输入区内滚动。输入区支持普通文字、`Shift+Enter` 换行、当前虚拟文件系统路径拖放、系统文件拖放，以及系统剪贴板粘贴的图片、纯文本、PDF、音视频、Word 和 Excel 文件。
- 对系统文件或图片，必须复用既有上传到当前 Agent `tmp/` 并插入 `[FILE:…]` 附件气泡的流程；虚拟文件系统拖入的附件必须保留来源 Agent 标识。发送时应同时携带附件归属，确保普通消息链路能解析附件。
- 取消按钮和 `Esc` 关闭浮层且不发送；点击遮罩或浮层外部必须保持浮层打开且不发送。`Enter` 确认，`Shift+Enter` 不确认。修复原因去除空白后为空时，确认按钮必须不可用，键盘确认必须显示可见错误且不得发送。附件气泡计入非空原因。
- 确认前必须重新读取运行时配置中的 `miniapp.debug`。该模板必须是含 `$path` 和 `$reason` 的非空字符串；两种占位符的全部出现位置均须替换。`$path` 仅替换为所选 `.html` 的绝对路径，`$reason` 替换为输入区的文字和附件气泡文本。配置无效、会话切换、Agent 不可用、会话繁忙或模型不可用时必须保留浮层并显示错误。
- 模板生成成功后，页面应通过既有 `sendCenterMessage` 普通发送链路，以 `miniapp_debug` 来源自动提交到打开浮层时绑定的当前会话；发送成功后关闭并清空调试草稿。不得新增独立调试 HTTP 接口、不得在浏览器侧执行 CLI 或读取/修改 HTML 内容。

### 编写代码
+ 复用既有迷你应用配对、绝对路径拼接、受控运行时配置读取、附件气泡、文件所有者收集、上传、会话发送、Toast、键盘快捷键和居中域浮层管理函数。
+ 新增浮层必须纳入既有 `data-overlay-base` 前景排序、显示状态、关闭分发与键盘前景判断；不可只依赖 CSS `z-index` 或孤立的键盘监听。
+ 修改前确认实际发布页面和配置路径；发布时静态页面与 `config/config.json` 必须同步到应用资源目录，并重新签名、严格校验应用。
+ 为模板校验与替换、空原因拦截、会话绑定、附件归属及 MD 单元格内瓢虫图标的长 Markdown 截断提供可维护的回归验证；不新增外部依赖。
