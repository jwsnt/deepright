# 20260620-2 用户手册

本次迭代补充了 `__TARGET__` 对 `__PROCESS__` 和 `__RETRY__` 的展示定位规则，但不会改变它们原有的作用域和计时逻辑。

## `__TARGET__` 定位规则

- 当 SSE 报文里的 `choices[0].metadata.__TARGET__` 为非空标记时，当前这条 `__PROCESS__` 或 `__RETRY__` 提示不会继续显示在 assistant 气泡外侧 footer，而是改为显示在当前等待响应的 assistant 气泡内侧左下
- 气泡内提示会与同一条 assistant 响应右下角的时间保持同一水平线，自身保持左对齐；展示样式与原来的 footer 临时提示保持一致
- 如果 `__TARGET__` 为空，则继续沿用原来的 assistant 气泡外侧 footer 展示逻辑

## 作用域与展示时长

- `__TARGET__` 只影响展示位置，不参与提示作用域匹配；无论是否携带这个标记，`__PROCESS__` 和 `__RETRY__` 都仍然只按当前 `ChatId` 隔离，`agentId` 不参与匹配
- `__PROCESS__` 仍然按原来的 `5` 秒计时；如果收到新的 `__PROCESS__` 报文，会立即覆盖旧文案并重新开始 `5` 秒计时
- `__RETRY__` 仍然优先取 `choices[0].metadata.delay` 作为展示时长，按毫秒处理；如果缺失、非法或小于等于 `0`，则默认展示 `30` 秒
- `__PROCESS__` 与 `__RETRY__` 仍共用同一个统一提示位，谁后到就覆盖谁；`__TARGET__` 不会改变它们互相覆盖的规则

## 正文与其他状态

- 纯 `__PROCESS__` / `__RETRY__` 报文在实时 SSE 和历史恢复时都不会进入居中对话框正文
- 展示内容仍直接取 `choices[0].delta.content`，并继续按现有前端规则归一化：去掉 `\r`、裁掉首尾空白、把连续换行折叠为空格，再把连续空白折叠为单个空格
- 如果归一化后为空，则会直接清空当前会话的这条统一临时提示
- `努力工作中` 的展示位置和显隐逻辑保持不变，仍只跟当前会话 busy 状态相关，不会被 `__PROCESS__` 或 `__RETRY__` 替换
