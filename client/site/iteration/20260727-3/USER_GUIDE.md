# Chrome 画面录屏使用手册

在虚拟文件系统点击“新增”，将类型切换为“录屏”，可填写 MP4 文件名或留空使用时间戳默认名。点击创建后，页面会先按最终名称检查当前 Agent 的 `videos/`；例如输入 `aaa` 会检查 `videos/aaa.mp4`。若同名文件已存在，会停留在创建浮层并提示冲突文件名；通过检查后才打开画面录制浮层，且不会立即产生文件。

按浮层内的三步提示操作：先在 Chrome 标签页打开目标页面，再选择标签页、窗口或整个屏幕。默认会录制完整共享画面；如需裁切，在状态行右侧开启“选择录制范围”，预览中才会出现可拖动的蓝色框。蓝色框允许任意宽高；如果宽或高为奇数，最终 MP4 会在右侧或底部自动补 1 像素，预览会显示补齐后的输出尺寸。用户取消授权或结束共享后，可以重新选择。

录制以 Chrome 提供的帧为单位裁切，保留捕获时间戳并请求最高 60 fps，不依赖页面在后台的 `requestAnimationFrame`。因此切到目标标签页后不会发生由录制页后台限速造成的丢帧；但源页面、Chrome、DRM 或本机编码器未实际交付的帧不能恢复。

停止后可先预览 WebM 结果，再点击“保存 MP4”。页面会把 WebM 暂存到当前 Agent 的 `tmp/`，交由本机 FFmpeg 转成 H.264/AAC MP4，最终保存到 `videos/`。同名文件或保存期间的并发冲突会自动在扩展名前追加时间戳，既不会覆盖旧文件，也不会丢弃这次录制；成功后 VFS 会刷新，最终绝对路径会尽力复制到系统剪贴板。临时 WebM 在成功、失败或关闭时清理。

点击创建录屏后、打开录制浮层前，页面会检查服务端的 `ffmpeg` 和 `ffprobe`。缺失依赖时会显示与视频剪辑浮层相同的安装确认提示；取消会保留创建浮层，安装会发送配置的安装请求。配置异常或转码失败时会显示原因，浏览器不会自行安装软件或生成伪装的 MP4。
