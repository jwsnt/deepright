## VoxCPM 配音队列

Integration 提供 `GET /api/voxcpm/check`，以及 `GET/POST /api/voxcpm/tasks`、取消、重新开始、失败或已取消任务删除和日志接口。`config/config.json.voxcpm.check` 控制成功依赖检查缓存，`install` 是缺失依赖时返回给页面的安装请求；系统不会执行安装。

任务只接受当前 Agent 工作区中的 UTF-8 文字文件；参考音色和 `control` 表达风格都可选。文本预览入口可直接提交当前预览文件的工作区相对路径，服务端仍读取并校验实际保存的文件内容。参考音色提供时必须可预览，任务使用 `voxcpm clone` 克隆其音色；未提供时使用 `voxcpm design` 自由生成声音。每条任务可保存受控场景：均衡克隆、质量优先、快速预览、清晰增强、温暖叙述或轻快表达，以及可选的 `control` 表达风格。表达风格会合并空白并限制在 240 个字符内；它只会作为单个 `--control` 值传入，填写后覆盖场景的内置风格，未填写时才使用内置风格。服务端将场景映射为固定的 CFG、推理步数、文字规范化和参考音频增强，拒绝其它任意参数。输出只能写入该 Agent 的 `audios/`。服务会探测 VoxCPM 的 CUDA 或 Apple MPS 环境并优先使用 GPU；GPU 执行发生任何错误时会自动使用 CPU 重试一次，CPU 重试不会再次重试，日志会记录参考音色选择、`design`/`clone` 模式、场景参数、实际表达风格、设备选择与回退结果。未检测到或无法验证 GPU 时直接使用 CPU。单任务使用请求名称，批量任务或冲突时追加时间戳；既有文件不会被覆盖。

队列跨 Agent 串行执行，并将任务、状态、进度、日志和输出绝对路径保存至共享 SQLite。取消会终止当前子进程；重新开始会分配新的安全输出路径；失败或已取消任务删除仅删除任务记录。
