### 需求介绍
+ Integration 必须继续将 `.canvas` 视为 Agent 工作区内的普通 UTF-8 文本文件，并通过受限的工作区读写接口支持创建、读取和更新；不得为画布暴露任意本机路径读写接口。
+ Site 的新建画布流程在用户首次点击“保存”前不得调用创建文件接口。首次或后续保存均通过现有受限写入语义落盘，因此取消未保存画布不会在工作区创建空文件。
+ Site 只会向服务端提交无后缀名称自动补充后得到的 `.canvas` 路径，或用户已填写的 `.canvas` 路径；其它文件后缀由页面在调用服务端前拒绝。
+ `.canvas` 文件内容是版本化 JSON，服务端无需理解节点、图片或连线的业务结构（包括节点可选背景色、`forward`、`reverse`、`both` 三种连线方向及备注），但必须原样保留其 UTF-8 内容；写入时仍需校验 Agent、相对路径、工作区边界和符号链接边界。
+ 同名覆盖由页面在写入前确认；用户确认后的保存沿用 `/api/edit` 对既有文件的覆盖语义。写入失败必须返回可展示的错误，且不得产生工作区外文件或半成功响应。
+ Site 在浏览器生成 PNG/PDF 后，通过既有受限 `/api/edit` 二进制写入语义保存到当前 Agent 工作区的 `canvas/` 子目录；目录不存在时创建，使用 `saveAsNew=true` 保留历史导出并返回最终绝对路径。服务端不负责图形渲染、不新增画布专用导出接口，也不处理 SVG。

### 编写代码
+ 保持 `/api/edit` 的二进制和 CLI 收口原则，确保相对 `.canvas` 路径可写、工作区外路径被拒绝、缺失目标可在首次保存时创建、既有目标可更新；PNG/PDF 的 Base64 内容仅可按同一受限语义写入工作区 `canvas/` 路径。不得新增外部依赖和画布专用本机文件接口。
+ 为 `.canvas` 首次写入和覆盖更新补充 Integration 回归测试，覆盖 JSON 原样保存、工作区边界拒绝及不经保存不创建文件的前端契约所依赖的“缺失文件可写”语义；同时覆盖 PNG/PDF 导出目录自动创建、二进制原样写入、时间戳另存和工作区边界。
+ 最小范围更新，不新增外部依赖。
