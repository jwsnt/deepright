# 20260503-17 使用手册

## 目标

本次迭代为 `proxy` 补齐了“任务完成后自动回推三方消息结果”的能力：

- 每分钟扫描最近 24 小时内已完成的非 `cron` 任务明细
- 通过任务明细里的 `meta_ref` / 执行 metadata 中的 `META_ID` 反查对应的 `connect add-request` 原始消息
- 如果该原始消息状态仍为“已启动”，则调用对应插件的 `send` 命令把任务结果回推给三方
- 回推成功后，将目标消息更新为“已回复”，并将更早且仍为“已启动”的同插件消息更新为“已完成”

## 执行流程

1. 定时任务后台每分钟扫描一次 `task_detail`
2. 只处理最近 24 小时内、`started=3`、`task_type != cron`、且 `replied_at` 为空的明细
3. 从该明细的 `meta_ref` 中取最后一条 request ID，作为本次回推对应的原始消息
4. 到 Connect 模块里查找这条原始消息，要求其状态仍为“已启动”
5. 读取该插件的 Connect 元数据，并调用：

```bash
plugin send --message '{}' --content '任务结果文本'
```

   在真正执行前，`proxy` 会先调用 `<callback> --help` 检查插件是否暴露 `send` 命令；如果插件程序不存在，或帮助信息里不包含 `send`，则视为该插件“不需要回复”，会在对应插件日志（如 `feishu.log`）里追加一条 skip 记录并跳过本次回推。

6. 插件回推成功后：
   - 当前原始消息状态更新为“已回复”
   - 更早且仍为“已启动”的同插件消息更新为“已完成”
   - 当前任务明细写入 `replied_at`，防止重复回推

## 字段关系

- `task_detail.task_type`：插件运行时主键，例如 `feishu`
- `task_detail.meta_ref`：本轮聚合时关联的 request ID 列表，使用英文逗号拼接
- `META_ID`：执行任务时写入 metadata 的最后一条 request ID
- `task_detail.result_content`：任务完成后的最终文本结果
- `task_detail.replied_at`：回推成功时间；非空表示该明细已经完成过自动回推

## 行为说明

- 仅处理非 `cron` 类型任务明细，不会影响普通周期任务
- 仅处理最近 24 小时内的已完成明细，避免无限追溯历史数据
- 如果 `result_content` 为空，则不会执行回推
- 如果目标原始消息已不是“已启动”状态，则不会重复发送
- 如果插件 `--help` 未暴露 `send`，或 callback 程序不存在，则记录插件日志并跳过，不视为失败
- 同一条已完成明细只会自动回推一次

## 状态说明

### connect_request.status

- `0`：待处理
- `1`：已启动
- `2`：已完成
- `3`：已回复

### task_detail.started

- `0`：待启动
- `1`：已启动
- `2`：无需启动
- `3`：已完成

## 验证

本次迭代已补充自动化测试，覆盖：

- 已完成任务明细按 `meta_ref` 找到目标原始消息
- 仅在原始消息状态为“已启动”时执行插件回推
- 回推内容使用 `task_detail.result_content`
- 回推成功后目标消息更新为“已回复”
- 更早且仍为“已启动”的同插件消息更新为“已完成”
- 同一条明细不会重复回推
