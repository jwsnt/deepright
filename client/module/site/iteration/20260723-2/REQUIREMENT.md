### 需求介绍
+ 备忘录查询的“元数据”结果表不再展示“状态”列。表头、单元格、状态徽标和悬停提示均须移除；元数据查询原有的状态筛选语义保持不变，仍可按其关联任务明细的状态筛选元数据。
+ 在“备忘录元数据预览”浮层的“内容”标题右侧新增无文字的任务列表小图标。该图标仅在元数据处于只读预览、未保存、未删除且未被其他确认流程锁定时可点击；其尺寸、热区、主题、hover/focus 样式及无障碍名称必须与现有预览小图标一致。
+ 点击该图标后，关闭当前元数据预览并直接打开“备忘录任务明细”查询浮层，自动查询当前元数据下的全部任务明细。
    + 此入口不得显示“元数据”Tab，也不得通过键盘、脚本或其他页面操作切换到元数据维度；标题显示“备忘录任务明细”。
    + 任务明细的执行时间范围、Agent、模型、状态和任务内容筛选均保留；所有筛选及结果必须始终限定在打开入口的元数据下。
    + 该受限列表复用现有任务明细表格、预览、历史明细查询、分页加载和错误提示能力，并保留任务明细自身的“状态”列。
+ 受限查询必须通过 `POST /api/cron/detail/list` 传入 `history=1` 与当前元数据的 `metaId`。前端还须按返回项的 `metaId` 做一次本地兜底过滤，避免异常响应混入其他元数据的任务。
+ 受限查询的缓存键必须包含 `metaId`，不得与通用“任务明细”查询缓存共用。关闭、按 `Esc` 或点击遮罩离开受限查询时，必须中止进行中的请求、使晚到响应失效，并恢复此前通用查询的条件、结果、滚动位置和 Tab；不得把受限结果遗留给通用查询。
+ 从受限列表打开任务明细预览后，关闭该预览再返回查询时，仍保持当前 `metaId` 限定与“仅任务明细”视图。此功能只读取现有查询接口，不创建或修改备忘录、任务明细、会话或持久化业务数据。

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 复用现有备忘录查询、任务明细预览、toast、AbortController、查询缓存和 overlay 域管理能力；不得新增后端接口、构建流程或运行时依赖。
    + 受限查询用页面运行期 `metaId` 上下文与请求序号管理。关闭、切换、预览跳转和重新进入时，必须中止旧请求并拒绝旧响应更新当前结果。
    + 任务列表图标不得破坏元数据预览已有 `500ms` 悬停关闭、编辑、保存、删除、运行确认、Esc 与新手引导逻辑；编辑态、保存态、删除态或全局锁定态不显示该入口。
    + 覆盖静态/自动化验证：元数据表无状态列、普通查询仍可切换两个 Tab、受限查询仅显示任务明细、请求携带 `metaId` 与 `history=1`、筛选结果不会跨元数据、关闭后通用查询状态恢复、预览往返后限定仍有效。
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
