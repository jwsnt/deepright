### 需求介绍
+ 在右侧边栏“正在执行的系统指令”标题栏新增一个展开/还原按钮
    + 新按钮放在系统指令标题栏的 action 区，和现有 `CMD` 按钮同域展示
    + 按钮视觉风格、尺寸、交互热区与知识库标题栏的展开按钮保持一致
    + 本次只复用图标和交互样式，不复用知识库按钮的“刷新”语义
    + 点击一次进入展开态，再次点击恢复原布局
+ 系统指令展开态的展示语义必须和知识库展开态一致
    + 展开后仅占满右侧边栏，不覆盖主页面，不进入浏览器原生全屏
    + 展开后右侧边栏上半部分仅保留系统指令区域，知识库区域被隐藏
    + 还原后恢复为当前既有的右侧边栏上下布局
    + 空态下也允许点击展开，展开后空态内容同样占满右侧边栏
+ 系统指令展开态与知识库展开态必须互斥
    + 同一时刻只允许一个面板处于展开态
    + 当系统指令进入展开态时，知识库若当前已展开，必须先恢复常态
    + 当知识库进入展开态时，系统指令若当前已展开，必须先恢复常态
+ 系统指令展开态需要绑定当前 chat 的右侧边栏运行时上下文
    + 切换 chat 后，系统指令展开态必须自动复原
    + 收起右侧边栏后，系统指令展开态必须自动复原
    + 新增“系统指令是否展开”的状态只能存放在当前页面运行时，不得写入 chat 持久化状态、`localStorage`、URL 参数或其他跨刷新状态
    + 页面刷新后默认恢复为未展开态
+ 系统指令展开态需要与现有日志流式更新稳定协作
    + 当系统指令面板处于展开态时，新的系统日志持续流入仍需保持展开态，不得自动还原
    + 展开/还原切换不得影响现有系统日志的实时渲染、追加顺序和滚动行为
    + 若系统指令内容区当前已有滚动位置，展开和还原前后都应尽量保持滚动位置稳定，不得无故跳回顶部
+ 交互语义需要明确且唯一
    + 系统指令标题栏的新按钮语义仅为“展开系统指令”与“还原系统指令布局”
    + 不得混入刷新、清空、关闭或切换到其他面板的语义
    + 展开态下再次点击该按钮，仅恢复为原布局

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，尽量复用现有知识库展开态、右侧边栏标题 action 区、右侧栏布局同步和 chat 切换链路
    + 系统指令展开态必须与知识库展开态显式分流，避免共用同一个状态位导致语义串线
    + “系统指令是否展开”只能保存在页面运行时状态，不得写入 chat 持久化字段、`saveChats()`、`localStorage` 或 URL
    + chat 切换、右侧边栏收起、知识库进入展开态等场景下，都必须显式回收系统指令展开态，避免残留脏状态
    + 日志流式追加期间，展开态切换不得中断现有 CLI 子面板渲染、恢复和滚动沉底逻辑
    + 新按钮的 DOM 落位、显隐和 aria 文案必须稳定，禁止在不同状态下漂移到标题栏之外
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
