### 需求介绍
+ 在居中对话框的 assistant SSE 响应气泡左上角增加“思考片段汇总”入口，使用现有灯泡样式的 `assistant-explosion-beacon` 作为触发器
    + 仅当该条 assistant 响应已经捕获到可展示的思考片段时才显示入口；普通响应、用户请求气泡、报错气泡、终态消息和右侧 CLI 子任务气泡不展示
    + 入口位于当前 assistant 气泡正文左上角，与正文内容共存，但不在气泡正文内展开思考内容
    + 入口展示当前已汇总的思考片段数量，数量文案沿用现有计数规则，最大显示 `9+`
+ 点击、悬浮或聚焦左上角入口后，展示独立的浮层汇总面板 `assistant-explosion-floating-popover`
    + 浮层是挂在 `document.body` 下的独立面板，不在当前消息气泡内做展开/收起切换
    + 浮层内容按捕获顺序展示思考片段列表，每条使用 `思考 1`、`思考 2` 这类标签，并继续复用现有 Markdown 渲染能力
    + 浮层位置跟随入口自适应，优先展示在入口附近；窗口 resize、页面滚动或当前入口内容变化时需要重新定位
    + 鼠标移入、焦点进入入口或浮层时保持展开；移出后按现有延时隐藏策略关闭；点击入口可手动开关；点击浮层外区域立即关闭
+ SSE 流式返回期间，思考片段汇总只负责维护左侧入口和浮层列表，不改动 assistant 正文区域的现有渲染方式
    + 正式回复正文继续按现有 SSE 节奏实时渲染，自动滚动、Markdown 展示、复制、耗时和状态标记保持不变
    + 新增思考片段时，只更新当前 assistant 消息对象上的 `_explodedSnapshots` 汇总数据，并同步刷新入口数量和浮层内容
+ 为减少“思考片段汇总”中的碎片数量，相同思考流需要在汇总层做合并
    + 汇总分组键不使用易变化的 `payload.id`，改为基于稳定字段 `biz + workflow + created` 生成 `snapshot:${biz}@${workflow}:${created}`
    + 同一分组内的后续片段继续并入同一条汇总记录；合并时优先复用完整内容，并处理首尾重叠片段，避免浮层中出现大量碎片化短句
    + 该合并范围仅限左侧“思考片段汇总”的 `_explodedSnapshots` 聚合，不改动其他消息恢复、数据库结构或 SSE 正文解析逻辑
+ 左上角入口和浮层需要与现有 assistant 气泡控件共存
    + 不遮挡现有复制、重试等交互热区
    + 深色/浅色模式下都需要保持可见性和足够反差
    + 保持现有页面的轻量接入方式，不新增新的消息类型、构建流程或运行时依赖
