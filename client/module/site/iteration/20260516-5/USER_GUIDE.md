# Site 迭代手册（20260516-5）

## 本次更新

- 设置面板里的蜂群配置区新增独立模型下拉，入口样式延续备忘录里的小地球图标风格
- 设置面板里的蜂群 `Thinking` 开关移动到蜂群开关右侧，不再和当前会话输入框里的 `Thinking` 状态联动
- 当设置中的模型配置发生新增、删除或修改时，蜂群模型下拉会立即刷新可选项，不需要先关闭再重开设置
- 如果删除了当前蜂群配置正在使用的模型，选择 Agent 右侧的小蜜蜂图标会立即变为红色闪烁；重新打开蜂群面板时，模型区域也会同步高亮提示该模型已不存在
- 左侧会话删除确认改为中间会话区水平垂直居中的背景模糊浮层；点击取消或空白区域会立即关闭

## 当前行为

1. 点击设置中的小蜜蜂图标后，会在原有蜂群浮层中看到 `蜂群开关`、`Thinking 开关`、`模型下拉` 和 `确认` 按钮同排展示
2. 蜂群 `Thinking` 只代表当前 Agent 的蜂群配置，不会再改动居中输入框当前会话的 `Thinking/Auto`
3. 蜂群模型未选择时，会提示 `请选择一个蜂群模型。`
4. 当蜂群处于开启状态时，模型和描述都为必填项；缺少任一项都会在蜂群面板内直接提示，且不会保存
5. 蜂群模型下拉的数据源始终取自设置面板当前可见的“模型与密钥”条目；新增或删除模型后，下拉会实时更新
6. 如果蜂群配置里记录的模型已经不在当前模型列表中，选择 Agent 右侧的小蜜蜂图标会立即切换为红色闪烁；模型标签和边框也会高亮为红色，并提示 `当前蜂群模型不存在，请重新选择可用模型。`
7. 点击蜂群 `确认` 后，会先暂存当前 `description`、`swarm`、`thinking`、`provider` 这 4 个字段，并在 `选择 Agent` 下方提示 `蜂群配置需要在保存后生效`
8. 只有继续点击设置面板底部的 `保存`，暂存的蜂群配置才会真正写回当前 Agent 工作区下的 `config.json`
9. 写回蜂群配置时会保留 `config.json` 中其他未被本次前端使用的字段，避免覆盖额外配置
10. 现在可以在同一次编辑里连续修改描述、模型和 `Thinking`，最后点击一次设置保存也会一起落盘，不会再互相覆盖
11. 当蜂群模型从 `deepseek` 切换到 `deepright` 这类新值时，写回 `config.json.provider` 会以本次最新选择为准，不会再被旧的 `provider` 覆盖回去

## 说明

- 当前会话输入框下方的 `Thinking` 仍然按会话维度单独保存，新建会话默认保持 `Auto`
- 蜂群模型下拉和其他设置浮层一样，遵守中间会话区的 overlay 分域与隐藏失活规则；关闭设置、切换 Agent 或点击面板外部时会立即收起
