### 需求介绍
+ 创建备忘录任务的表单状态重置时机需收口为“保存成功后”：
    + “保存成功”仅指创建请求已通过前端校验，且服务端已成功创建任务并返回成功结果；点击“保存”本身、请求尚未结束或仅完成本地校验，均不得重置任何表单输入。
    + 在确认弹窗点击保存后直至创建请求成功或失败返回期间，必须以全页面锁定层阻断左侧栏、中间会话区、右侧栏及所有浮层的交互；锁定层需明确展示“创建备忘录中”的等待状态，并阻止键盘焦点离开锁定层。保存成功或失败后才允许解除锁定。
    + 保存请求进行中，内容、开始时间、周期、模型及既有开关等全部用户输入必须保持不变；保存按钮需防止重复提交，且不得因列表刷新、浮层刷新或表单重新渲染而清空输入。
    + 前端校验不通过、服务端返回失败或网络异常时，创建弹窗保持打开，完整保留用户已填写的内容、时间和其他配置，并继续展示既有校验或失败提示，方便用户修正后再次保存。
    + 服务端成功返回后，必须关闭创建备忘录弹窗，并将内容、开始时间、周期、模型、SWARM、Thinking、校验和“复用当前会话”等全部创建表单配置强制恢复为初始化状态；开始时间必须写入保存成功时的当前小时和分钟，即使保存前选择的是未来时间也不得保留。
    + 开始时间的日常自动更新必须使用日历当前选择的日期与时间输入框的小时、分钟组成完整执行时刻比较：该时刻晚于当前时刻时，页面初始化或定时刷新均不得覆盖已有时间；该时刻等于或早于当前时刻、或输入值无效时，才写入当前小时和分钟。该保护规则不适用于保存成功后的强制重置。
    + 点击确认弹窗的取消时，只关闭确认弹窗，不重置任何已填写的时间、内容或配置；前端校验不通过、服务端返回失败或网络异常时同样保留当前草稿。

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，优先复用现有备忘录明细缓存、`rsMetaCenterPreview`、overlay 域管理、创建备忘录控件、既有前端校验、`scheduleRefreshCronViews()`、VFS Tips 与 cron 请求链路，避免实现第二套表单和浮层体系
    + 将当前悬停/编辑的明细 ID、关闭计时器、鼠标是否位于来源明细或浮层、编辑草稿和原始快照保存在页面运行时；不得写入 chat payload、`saveChats()`、`localStorage` 或 URL
    + 延迟关闭必须统一由可取消的计时器管理；所有切换、刷新、销毁和进入编辑态路径均要显式清理计时器，避免旧计时器误关闭新明细的浮层
    + 浮层从被动展示转为可接收鼠标和按钮事件时，需与现有 overlay 域状态管理显式兼容，确保浮层未激活时不拦截底层交互，激活时可稳定承接 `pointerenter` / `pointerleave` 和图标点击
    + 编辑表单的模型选项、开关联动、输入长度与必填校验必须调用或抽取自创建表单的单一实现；禁止复制后形成两套规则
    + 前端刷新仅用于同步展示，保存结果和“任务是否已启动”的最终判定必须以更新接口响应为准；不得用悬停时缓存的 `started` 代替服务端条件更新
    + 代理层按既有 cron API 的 JSON 返回结构、Agent 校验、数据库访问、错误响应和明细日志方式实现更新接口，并补充正常更新、已启动竞态拒绝、非法 Agent/明细、字段校验失败的自动化测试
    + 编辑图标、保存图标、取消图标的 DOM 落位、显隐、禁用态、焦点顺序和 aria 文案必须稳定，禁止在不同状态下漂移出浮层标题操作区
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
