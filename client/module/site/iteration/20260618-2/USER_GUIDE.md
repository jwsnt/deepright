# 20260618-2 用户手册

本次迭代把 `__PROCESS__` 状态提示从居中对话框正文里剥离，统一收敛到 assistant 气泡的临时提示位。

## `__PROCESS__` 临时提示

- 只有当 SSE 报文里的 `choices[0].metadata.__PROCESS__` 非空时，才会触发这类临时提示
- 展示内容直接取当前报文里的 `choices[0].delta.content`，并沿用现有前端文本归一化规则：去掉 `\r`、裁掉首尾空白、把连续换行折叠为空格，再把连续空白折叠为单个空格
- 如果归一化后的文本为空，则不会展示空提示，而是直接清空当前会话的 `__PROCESS__` 提示
- 纯 `__PROCESS__` 报文在实时 SSE 和 restore 历史恢复时都不会进入居中对话框正文

## 会话作用域与计时

- `__PROCESS__` 提示只按当前 `ChatId` 隔离；`agentId` 不参与作用域匹配
- 不同会话之间不会串提示；只有当前提示仍然属于同一个 `ChatId` 时，到时自动清空才会生效
- 每次收到新的 `__PROCESS__` 报文时，页面都会立即用最新文案覆盖旧提示，并重新开始一次 `5` 秒展示计时
- 如果这轮流式响应提前结束，提示仍会保留到本轮 `5` 秒计时结束，再自动清空

## 展示位置

- 默认情况下，`__PROCESS__` 会展示在当前会话最后一个 assistant 气泡底部的 footer 临时提示位
- 如果对应 SSE 报文里的 `choices[0].metadata.__TARGET__` 为非空标记，则会改为展示在当前等待响应的 assistant 气泡内侧左下
- `__TARGET__` 只影响展示位置，不参与提示作用域匹配
- `努力工作中` 的位置和显隐逻辑保持原样，仍只跟当前会话 busy 状态相关，不会被 `__PROCESS__` 提示替换
