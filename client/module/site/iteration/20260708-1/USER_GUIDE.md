# 20260708-1 用户手册

本次迭代补充了会话历史的本地存储压缩策略。此前页面会把聊天历史整包写入浏览器 `localStorage`，而 assistant 消息在部分场景下还会额外保存 `rawSse` 原始流记录；当历史积累过多时，页面容易触发本地存储配额上限，并弹出“本地存储已满，新的会话历史暂未保存”。

## 触发原因

- 页面仍然使用浏览器 `localStorage` 保存本地会话历史
- 会话正文之外，还会一起保存会话顺序、右侧 CLI 子面板历史、Thinking/Verify/HTML/SWARM 等会话级状态
- 已完成 assistant 消息中的 `rawSse` 与最终显示的 `content` 存在重复存储关系，容易放大体积

## 新的压缩顺序

- 当保存聊天历史时遇到本地配额压力，页面会先尝试移除已完成 assistant 消息中的 `rawSse`
- 如果空间仍然不足，会继续裁剪会话中的 `cliCommandHistory`
- 如果仍然不足，再继续裁剪非活跃会话、以及必要时的活跃会话中“最近保留窗口”之外的消息
- 压缩只作用于待落盘 payload，不会先修改当前页面正在使用的运行时内存对象

## 进行中会话的保护

- 正在请求中的会话会尽量保留 `rawSse`
- 这样可以继续兼容现有的恢复链路、任务 badge 恢复、底部 inline hint 恢复等逻辑
- 只有在更激进的兜底压缩阶段，才会对所有会话统一丢弃 `rawSse`

## 提示文案说明

- 如果页面通过压缩成功完成保存，会提示：`本地存储空间不足，已仅保存最近部分会话历史`
- 如果经过多轮压缩后仍然无法写入，才会提示：`本地存储已满，新的会话历史暂未保存`
- 第二类提示出现时，表示本次新增历史没有成功写入本地浏览器存储

## 范围边界

- 本次只修正现有 `localStorage` 存储链路，不把聊天正文迁移到 `IndexedDB`
- 不新增新的设置入口、清理按钮或用户开关
- 服务端模型密钥存储方式不变，仍由 `/api/token` 对应的服务端存储负责
