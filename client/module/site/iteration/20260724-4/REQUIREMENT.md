### 需求介绍
+ 居中会话输入框的 `@` 主菜单必须保持首帧即时显示；可用 Skill 和 SWARM `Agent` 入口的数据由 Integration 的 `at` 缓存接口提供。
+ 前端不得为 Skill 或 Agent 额外实现持久化缓存、定时轮询或过期逻辑；每次打开 `@` 仍可请求接口，由服务端统一依据 `config/config.json.at` 决定缓存有效性与刷新。
+ 同一轮 `@` 菜单打开期间，主菜单预取与用户立即点击 `技能` 或 `Agent` 必须复用进行中的请求，避免产生重复请求。
+ 当 `/api/skills` 或 `/api/swarm_agent` 因 `at` 配置错误或失效后的主动加载失败返回非成功响应时，前端不得展示旧数据；保留当前可用菜单入口并以现有错误处理方式避免未捕获 JSON 解析错误。
+ 在文件区禁用或恢复 Skill 目录时，继续调用既有 `/api/skill_state`；服务端成功响应后，后续同一会话的 `@ Skill` 菜单必须使用已即时更新并续期的会话缓存，不要求页面额外刷新或维护 Skill 列表缓存。
+ 任意 Agent 保存蜂群开关后，后续 `@ Agent` 菜单必须使用服务端已完整刷新并续期的所有缓存；页面无需等待定时刷新，也不得保留切换前的 Agent 列表。
+ 创建、删除或导入 Agent 成功后，后续 `@` 菜单必须使用服务端已完整刷新并续期的数据；页面无需等待 `at.refresh` 周期。
+ 复制 Agent 成功，或后端成功修改/删除会影响 Agent Skill 定义与蜂群可见性的文件后，页面无需增加额外刷新逻辑；后续 `@` 菜单必须直接使用服务端已完整刷新并续期的数据。普通 `@ 文件` 目录展示不依赖该缓存。
