### 需求介绍

在右侧栏“正在执行的系统指令”标题中提供构建迷你应用的入口，使用户可以向当前会话发送由运行配置生成的构建请求。

- 在“正在执行的系统指令”文字之后、现有命令与展开操作之前增加紧凑的“构建迷你应用”图标按钮；按钮须有可见的悬浮提示、`aria-label` 和键盘焦点样式，且不得挤压、遮挡或改变现有右侧栏操作按钮的布局。
- 点击入口后，在中间会话区域显示与既有 Git 安装浮层一致的居中浮层。浮层标题为“构建迷你应用”，说明为“输入 CLI 名称或 Git 地址，确认后会自动在当前会话中发起构建请求”。主输入框不显示“Git地址”标签，占位符为 `https://github.com/owner/repo 或 CLI名称`。
- 浮层须提供可选功能列表输入。初始不显示任何功能输入项；点击紧凑的 `+` 后新增一项，点击每项的 `−` 删除对应项，允许删除最后一项。输入项按用户界面顺序收集，空白项忽略；多个有效功能必须以全角顿号 `、` 拼接。功能输入与增删控件应紧凑排列，避免无谓增大浮层宽度或影响主输入框、取消和确认按钮的原有布局。
- 取消、点击浮层遮罩和按 `Esc` 都关闭浮层并保留尚未提交的输入；打开时聚焦主输入框。当前会话正在发送、预检、恢复或接收 SSE 时，入口和确认操作不得绕过既有会话忙碌校验；会话、Agent 或模型在打开后失效时，保留浮层并显示既有风格的错误提示。
- 确认时主输入值去除首尾空白后不能为空。页面必须重新通过既有 `/api/runtime_config` 读取当前运行配置的 `miniapp`，不得从浏览器工作目录、本地存储或硬编码常量读取模板。`miniapp.build` 必须为包含 `$name` 和 `$function` 的非空字符串；`miniapp.function` 必须为非空字符串。配置读取或校验失败时不得关闭浮层或发送消息，并显示原因。
- 构建文案中所有 `$name` 替换为主输入的有效值；功能列表存在有效项时，所有 `$function` 替换为以 `、` 拼接的结果；没有任何有效功能项时，所有 `$function` 替换为 `miniapp.function`。替换后的完整文案须先写入当前会话输入框，再完全复用普通居中会话发送链路立即发送，不执行 CLI、克隆 Git 仓库或直接构建应用。
- 发送必须沿用普通消息的会话、Agent、模型、令牌、输入长度、元数据和 SSE 状态校验。仅在成功触发发送后关闭浮层并清空本次草稿；发送未触发时保留可见错误提示和用户输入。既有“从Git安装”及其它 Skill 提炼、CMD、系统指令展示和右侧栏展开功能保持不变。
