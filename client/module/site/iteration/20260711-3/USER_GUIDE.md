# Site 迭代 20260711-3 使用手册

## 本次更新

- 页面继续使用浏览器 `localStorage` 保存本地会话历史，但新增了常驻的本地存储预算治理能力。
- 当当前站点 origin 下的 `localStorage` 总占用超过约 `2.5 MB` 时，页面会自动压缩本地聊天历史，目标压回约 `1.5 MB`。
- 每个会话持久化到本地的 `cliCommandHistory` 只保留最近 `30` 条；右侧 `CLI` 子面板可恢复/展示的本地 CLI 历史窗口也统一收口为最近 `30` 条。

## 自动治理规则

- 页面初始化完成后，会启动定时巡检；默认每 `30s` 检查一次本地存储预算。
- 页面从后台重新切回前台可见时，也会立即补做一次预算检查。
- 每次 `saveChats()` 正常完成后，页面还会顺手做一次静默预算检查，避免体积只增不减。
- 如果预算超限，页面会优先压缩 `deepright_chats`，而不是优先动 `theme`、侧边栏折叠状态或新手引导标记这类轻量 key。

## 压缩顺序

- 先统一规整 `cliCommandHistory`，确保每个 `chat` 只保留最近 `30` 条。
- 再优先移除已完成 assistant 消息中仅用于恢复的 `rawSse` 原始流记录。
- 如果空间仍然紧张，再继续裁剪非活跃会话的 CLI 历史和较旧消息窗口。
- 只有在仍未达到预算目标时，才会进一步压缩当前活跃会话中窗口之外的本地副本。

## 运行边界

- 当页面存在进行中的 SSE 或 restore 流式恢复时，自动治理会暂时让位，不会在中途压缩本地历史。
- 一旦自动压缩真正生效，压缩后的 payload 会同步回当前页面运行时状态，聊天主区、右侧 `CLI` 子面板和相关会话列表都会按新状态刷新。
- 自动治理默认静默运行；只有第一次真实发生“超过 `2.5 MB` 后自动压缩”时，页面才会给出一次轻量提示。

## 兼容性说明

- 这次改动仍然只治理现有 `localStorage` 存储链路，不把聊天正文迁移到 `IndexedDB`。
- 服务端模型密钥存储方式不变，仍由 `/api/token` 对应的服务端存储负责。
