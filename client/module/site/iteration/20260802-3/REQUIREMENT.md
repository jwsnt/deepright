### 需求介绍

- 在当前 Agent 工作区根层悬停 `videos` 目录时，显示与 `images` 目录“提取图片主体”相同尺寸、样式和显示时机的放大镜图标；标题及无障碍名称均为“视频提取主体”。该入口不得预填任何待创建任务。
- 点击入口后必须锁定依赖检查交互、防止重复打开，并严格按以下顺序请求同源接口：
  1. `GET /api/ffmpeg/check`。不可用时显示既有 FFmpeg 安装确认，取消或 `Esc` 只关闭确认；确认或 `Enter` 将服务端返回的安装请求发送至当前 Chat，浏览器不得自行安装。
  2. 仅在 FFmpeg 可用时，以当前页面已选择的 `agentId` 请求 `GET /api/rvm/check?agentId=<当前页面Agent>`；页面不得读取、推断或传递会话 UUID 作为 Agent 标识，也不得传递 VFS 工作目录。该检查仅判断这个 Agent 工作目录的固定 RVM 安装，不得使用其它 Agent 的结果或回退路径：必须存在 `$workspace/rvm/inference.py` 与 `$workspace/rvm/weights/rvm_mobilenetv3.pth`，并以可用 Python 成功执行 `inference.py --help`。不可用时显示标题“需要安装 Robust Video Matting”的同类确认，确认后将服务端已展开 `$workspace` 的 `rvm.install` 安装请求发送至当前 Chat；不得打开任务浮层。
- 两项依赖都可用时，打开居中域的“视频提取主体”任务浮层。浮层必须复用现有任务浮层的遮罩、层级、隐藏失活、焦点、关闭和键盘管理；`Esc` 关闭浮层但不取消已创建任务，`Enter` 提交当前待加入任务。
- 顶部文案固定为“添加更多视频任务”。“添加”支持多选，待加入列表最多 5 条，可逐条删除；文件选择器和浏览器侧筛选只允许 `mp4`、`m4v`、`webm`、`ogv`、`mov`、`mkv`、`avi`、`mpg`、`mpeg` 等视频，服务端拒绝时必须展示错误，不能将非视频加入待创建列表。
- 每条待加入视频都必须选择一个中文场景，控件布局与“提取图片主体”的任务选项保持一致。场景固定为“标准主体提取”（默认）、“精细边缘提取”和“快速主体提取”；浮层底部以图片主体同类主题色展示当前选择场景的中文作用说明，不直接展示技术参数。
- 列表沿用“提取图片主体”的状态筛选、每页 5 条、进度、日志、取消、重新开始、失败或已取消任务删除、单项复制和预览语义。已完成输出必须可勾选；勾选后在状态筛选右侧显示“复制”“清空”，复制以换行写入所选输出的绝对路径，清空仅取消勾选。
- 任务列表必须以“场景：<中文场景名>”显示每条任务的已保存场景；旧任务未保存场景时显示“标准主体提取”。创建任务提交每项视频的路径与场景，之后的执行、刷新、取消与重新开始均不得改写该选择。
- 任务输出文案为视频，完成预览可返回该任务浮层并保留待加入列表、筛选、分页、勾选和日志状态。关闭、刷新页面或重启应用均不得取消或丢失已创建任务。

### 编写代码
+ 所有前端依赖资源必须随站点页面一起可访问，并在发布链路中强校验资源存在性与正确MIME，禁止页面已引用但静态服务未实际发布的本地资源。
+ 修改前先确认服务实际读取的是哪一份运行文件；存在src/site与release/site 双份静态资源时，必须先确认运行目录，再修改并同步，不能只改源码文件。
+ 所有固定定位遮罩层、引导层、确认框、弹窗、日志面板、透明点击层必须统一管理层级、显示状态与 pointer-events，按左侧 Sidebar、居中会话区、右侧 Sidebar 分域隔离。
+ 所有浮层与遮罩默认遵守“交互域隔离 + 隐藏视图彻底失活”原则；隐藏态必须同时不可见、不参与层级竞争、不拦截点击、不接收焦点、不参与键盘导航。
+ 同一交互域任一时刻只能存在一个可交互的前景浮层；打开新浮层前必须先关闭当前浮层，禁止多个浮层重叠争抢点击和层级。
+ 浮层一定挂在它要压住的那一层内部；如果目标在弹窗、抽屉、设置面板等容器中，引导层应直接渲染到对应容器内部，不要依赖外层 z-index 强压。
+ 浮层定位、遮罩高亮与说明卡片位置必须收口到统一的公共函数或 portal 机制，统一坐标系，禁止在业务代码中各自手算 left/top。
+ 设计弹层结构时先确定挂载层级与坐标系，并避免把可能溢出的浮层放入overflow:hidden容器，防止裁切、错位和点击区域异常。
+ 布局逻辑与CSS限制必须一致；若CSS已动态计算 width、height、maxWidth，CSS 不得再写死更小的上限覆盖运行结果。
+ 选择器必须唯一且稳定，优先使用带作用域的 ID 或明确容器前缀，禁止直接依赖.settings-panel这类可能重复命中的通用类名。
+ 引导、确认、弹层等步骤切换不能只依赖理想时序；用户点击、浮层关闭、侧栏展开、动画结束、异步渲染等顺序变化时，流程仍必须可恢复。
+ 所有引导步骤应能根据当前 DOM 状态重新同步和兜底恢复，不能只依赖内存中的状态机，避免因为中途时序变化导致步骤丢失或跳错。
+ 排查浮层问题时，优先顺序固定为：先确认运行文件，再确认挂载层级，再检查层级与 pointer-events，再检查CSS尺寸限制，最后确认选择器唯一与状态恢复能力。
+ 优先复用成熟、轻量、可控的开源方案；在满足需求前提下保持代码简洁、依赖最少、包体积尽可能小。
+ 能用开源包的就用开源包
+ 代码简洁，包体积越小越好
