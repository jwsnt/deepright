### 需求介绍
+ 右侧 Sidebar 的备忘录任务明细列表，在鼠标悬停任一明细时展示的“备忘录配置预览”居中浮层，需要调整悬停关闭语义：
    + 当前悬停明细的鼠标离开后，浮层不得立即关闭；应启动固定 `500ms` 的关闭延迟。
    + 在这 `500ms` 内，鼠标重新进入同一条备忘录明细或进入该明细对应的浮层本体时，必须取消关闭计时，并继续展示当前浮层。
    + 鼠标位于浮层本体内时，浮层必须保持打开且可正常点击；只有鼠标同时不在当前明细和浮层本体内，并且关闭延迟届满后，才允许关闭。
    + 若鼠标从一条明细直接切换悬停到另一条备忘录明细，不等待旧明细的关闭延迟：立即以新明细数据替换浮层内容，并将浮层归属切换到新明细。
    + 浮层归属必须以稳定的明细 `detailId` 标识，禁止只依赖 DOM 引用；列表刷新、切换日期、切换 Agent、右侧栏收起、浮层对应明细不存在时，必须取消未完成计时并立即回收浮层，避免显示过期数据。
    + 编辑态不得因普通悬停切换而静默丢失未保存输入；编辑期间浮层固定归属当前明细，即使鼠标离开明细和浮层范围也不得自动关闭，只有保存成功或点击取消后才恢复普通悬停切换和 `500ms` 自动关闭语义。编辑态浮层必须升级为全页交互锁：浮层卡片自身的输入、保存、取消与 Esc 可用，卡片外背景全部不可点击。
+ 删除浮层标题下方的说明文案“当前悬停元数据的配置与内容会同步显示在这里。”：
    + 仅删除该文案及其占用的垂直空间；保留 `MEMO METADATA`、标题、配置区和内容区的现有视觉体系。
+ 备忘录明细浮层需支持“未启动明细”的原位编辑：
    + “尚未启动”严格定义为任务明细 `started === 0`（当前展示为“待执行”）。`started` 为 `1`、`2`、`3` 的明细均不显示编辑入口，也不能通过接口修改。
    + 当且仅当当前浮层展示的明细满足上述未启动条件时，在标题行红框所示的右侧操作位显示无文字的编辑小图标；图标尺寸、热区、颜色、hover/focus 效果和浅深色主题适配需与既有小图标体系保持一致，并提供稳定的 `aria-label` / `title`。
    + 点击编辑图标进入编辑态后，原编辑图标原位替换为“保存”和“取消”两个小图标；不得新增第二组操作入口、不得改变标题和配置区的整体对齐。
    + 编辑态中，除“周期”和“状态”外，明细配置与内容均使用创建备忘录时相同的控件、选项来源、交互联动和视觉样式编辑：
        + 执行时间使用创建时相同的时间输入与格式；保存后只更新当前 `task_detail.exec_time`，不改动周期元数据或其他未来/历史明细。
        + 模型、Thinking、SWARM、校验及内容复用创建备忘录的模型选择、开关、输入和联动规则；例如校验仍遵守 Thinking 相关的现有可用性规则。
        + 周期继续读取关联元数据的 `cycle`，状态继续读取当前明细的 `started`，两者在编辑态固定为只读展示，不能伪装成可操作控件。
        + Agent 是当前任务明细的归属身份，而不是创建表单中的可选配置；为避免把已有任务迁移到其他 Agent，该字段继续只读展示。复用会话等未在本浮层展示的既有明细字段必须原样保留，除非创建表单已有对应编辑控件且明确展示在此编辑态中。
    + 进入编辑态前，页面必须保存当前明细的完整原始快照；取消时用该快照恢复所有编辑控件、清除校验错误并切回只读预览。取消只重置本地编辑草稿，不向服务端提交请求。
    + 点击保存时复用创建备忘录的必填校验及错误呈现，至少包含内容 `trim` 后非空、内容长度限制、已选择可用模型、时间格式/范围、模型注册可用性和现有开关联动校验。前端校验失败时不发起保存请求，保持浮层和编辑态。
    + 保存请求进行中，保存/取消图标须防重复点击；请求结束后恢复可操作状态。保存成功后，以服务端返回的最新明细更新浮层的只读快照和当前列表缓存，并刷新受影响的备忘录视图；无论修改后的执行时间是否仍属于当前日历日期，当前浮层都不得因此被关闭。
    + 点击保存或取消均不得关闭浮层。成功保存后切回同一明细的只读预览；取消后恢复原始只读预览；保存失败时保留用户输入和编辑态，并展示失败原因。编辑态按下 `Esc` 必须等同点击取消图标：还原原始快照、退出编辑态并保持浮层打开，且不得触发其他浮层的 `Esc` 关闭逻辑。
+ 明细更新需要新增受服务端保护的接口，而不是由前端依据初次悬停时的状态直接修改本地列表：
    + 新增 `POST /api/cron/detail/update?agentId=xxx`，请求体至少包含 `detailId`、`execTime`、`content`、`model`、`thinking`、`verify`、`router_disable`；不得接受或修改 `cycle`、`started`、`agentId`、`metaId`、任务类型、执行结果等不可编辑字段。
    + 服务端必须复用创建任务的字段校验、模型注册校验、时间校验和布尔字段规范化；不得信任页面传入的明细状态或 Agent 归属。
    + 更新必须以单条原子条件更新或等效事务完成，条件至少包含明细 ID、Agent ID 和 `started = 0`。禁止“先查询未启动、后无条件 UPDATE”的两步实现，避免用户打开编辑后任务恰好启动仍被覆盖。
    + 若条件更新未命中，服务端需重新识别原因：任务已启动或状态不再为 `0` 时返回明确失败结果（建议文案：`保存失败：任务已启动，无法修改`）；任务不存在或不属于该 Agent 时返回相应失败结果。前端收到任何失败结果均不得关闭浮层或退出编辑态。
    + 成功更新后需要记录明细更新日志，日志包含更新后的可编辑字段、原有 `metaId`、Agent、执行状态和发生时间，保持现有 `cron_detail_log` 的审计语义。
    + 本次更新的作用范围仅为当前 `task_detail`：不得回写 `task_meta`，不得重排或重建其他周期明细，也不得影响已经启动、已跳过或已完成的明细。
+ 兼容与验收边界：
    + 浮层的打开、延迟关闭、编辑、保存、取消和提示不得中断正在进行的 SSE、聊天滚动、右侧 CLI 子面板、日历选择、备忘录列表刷新或现有删除/查看会话操作。
    + 现有新手引导若锁定备忘录明细交互，继续优先于本次悬停和编辑行为；引导中的模拟明细不得展示真实编辑入口或发送更新请求。
    + 同时覆盖以下验收场景：离开明细后 `0.5` 秒关闭；在倒计时内回到明细或进入浮层不关闭；切换另一条明细立即换内容；待执行明细可编辑并保存；编辑态离开浮层不关闭；已启动后再保存失败且保留编辑态；取消完整还原；周期/状态不可编辑；保存或取消后浮层仍保持打开。

### 编写代码
+ 以现有site页面技术栈编写以上代码，要求：
    + 在../../index.html中按现有HTML/CSS/JavaScript组织方式实现
    + 不引入新的构建流程和额外运行时依赖
    + 代码简洁，优先复用现有备忘录明细缓存、`rsMetaCenterPreview`、overlay 域管理、创建备忘录控件、既有前端校验、`scheduleRefreshCronViews()`、VFS Tips 与 cron 请求链路，避免实现第二套表单和浮层体系
    + 将当前悬停/编辑的明细 ID、关闭计时器、鼠标是否位于来源明细或浮层、编辑草稿和原始快照保存在页面运行时；不得写入 chat payload、`saveChats()`、`localStorage` 或 URL
    + 延迟关闭必须统一由可取消的计时器管理；所有切换、刷新、销毁和进入编辑态路径均要显式清理计时器，避免旧计时器误关闭新明细的浮层
    + 浮层从被动展示转为可接收鼠标和按钮事件时，需与现有 overlay 域状态管理显式兼容，确保浮层未激活时不拦截底层交互，激活时可稳定承接 `pointerenter` / `pointerleave` 和图标点击
    + 编辑表单的模型选项、开关联动、输入长度与必填校验必须调用或抽取自创建表单的单一实现；禁止复制后形成两套规则
    + 前端刷新仅用于同步展示，保存结果和“任务是否已启动”的最终判定必须以更新接口响应为准；不得用悬停时缓存的 `started` 代替服务端条件更新
    + 代理层按既有 cron API 的 JSON 返回结构、Agent 校验、数据库访问、错误响应和明细日志方式实现更新接口，并补充正常更新、已启动竞态拒绝、非法 Agent/明细、字段校验失败的自动化测试
    + 编辑图标、保存图标、取消图标的 DOM 落位、显隐、禁用态、焦点顺序和 aria 文案必须稳定，禁止在不同状态下漂移出浮层标题操作区
    + 能用现有开源包和浏览器能力的就不要重复造轮子
+ 最小范围更新
