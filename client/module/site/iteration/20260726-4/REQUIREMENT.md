### 需求介绍
+ 左侧虚拟文件系统的“新增”类型增加“音频”。用户输入名称、选择音频并点击“创建”后，不得先创建空文件；页面应进入居中的录音浮层，并在获得用户麦克风授权后开始录制准备。
+ 音频文件名只允许没有后缀，或以不区分大小写的 `.wav` 结尾。无后缀时页面自动补 `.wav`；任何其它后缀必须在进入录音前提示并阻止继续。保存路径固定为 Agent 工作区相对 `audios/<文件名>`，不得受当前虚拟目录影响；`audios` 不存在时由服务端安全创建。
+ 录音浮层标题为“录制”，需包含“开始”“结束”“重置”三个同一行的独立操作按钮、从 `00:00` 开始实时累加的录制时长、录音状态提示，以及文案仅为“取消”和“保存”的两个底部按钮；`Esc` 和 `Enter` 快捷键仍按既定行为生效，但不在按钮中提示。暖色主题下整个浮层、按钮、状态和控件使用暖色空间；冷色主题下对应全部使用冷色空间，亮/暗主题均应保持对比度和可读性。音频裁剪的“保存为新音频”按钮在冷色主题必须使用纯冷色背景，不得混入暖色渐变。
+ 点击开始后才采集麦克风；点击结束后停止采集并保留本次结果。未结束录制时仅展示状态与时长框；结束状态须隐藏该状态框，并在其原位置展示浏览器内试听控件，使下方控件上移。点击“重置”会丢弃当前未保存录音、隐藏播放器并回到尚未开始状态，不产生工作区文件。
+ `Esc` 在正在录制时必须先显示二次确认；仅在用户确认放弃后停止采集、释放麦克风并关闭浮层。未录制或已结束状态下，`Esc` 直接按取消关闭。`Enter` 在录制中应先结束录制再保存，在结束状态下直接保存；开始前没有有效录音时不得保存。
+ 录音须输出无损 PCM WAV，不得把 `MediaRecorder` 生成的有损 WebM/Opus 伪装为 WAV。页面应使用浏览器实际 AudioContext 采样率、尽可能保留输入声道，并以至少 16-bit PCM 写入带正确 RIFF/WAVE、`fmt ` 和 `data` 区块的 WAV；采集约束应关闭回声消除、降噪与自动增益，以避免主动降低录音保真度。浏览器不支持所需录音能力、麦克风授权失败、录音为空或编码失败时应保留浮层并展示可理解的错误。
+ 保存时页面将 Base64 编码后的 WAV 发送至同源 `POST /api/agent/audio?agentId=<agentId>&path=<relativePath>`。保存期间应防止重复提交；成功后关闭录音浮层、刷新当前虚拟文件列表、将服务端返回的绝对 `savedAs` 路径复制到系统剪贴板并提示成功。保存失败时保留可试听、可重置的录音和文件名，以便重试；页面不得读取本机绝对路径或使用 `file://`。
+ 录音浮层为阻断交互的居中浮层，应与现有浮层栈、右侧 URL 预览隐藏逻辑、焦点管理和全局键盘确认/取消逻辑兼容；关闭时必须停止计时器、停止媒体轨道并释放 AudioContext 等浏览器资源。
