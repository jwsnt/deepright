# 迭代 20260718-3：备忘录 STOP

## 使用方式

1. 在右侧备忘录创建区的周期位置，或备忘录列表底部左侧，查看并操作 `STOP` 小图标；它表示当前 Agent 的定时任务运行状态，不属于正在填写的备忘录。
2. 图标为中性颜色时表示关闭：当前 Agent 的本地备忘录任务会按原流程执行并创建会话。
3. 点击图标开启 `STOP`。图标会变为红色并持续闪动；当前 Agent 的本地备忘录任务在到期后暂不执行。
4. 再次点击即可关闭 `STOP`。此前未执行的待执行任务会在后续扫描中继续执行，无需重新创建备忘录。
5. 每次成功开启或关闭后，左侧虚拟文件系统都会显示 Tips。刷新、切换 Agent、重新回到前台及低频自动同步会读取服务端状态，但不会重复提示。
6. 创建区和备忘录列表使用同一份服务端状态：从任一位置切换后，另一处会立即同步颜色、闪动、提示文字与禁用状态。

## 周期显示规则

- `STOP` 图标与周期文字使用同一位置。
- 首次打开或重置后，周期文字为空，会显示 `STOP` 图标。
- 选择任意周期后（包括“仅一次”），周期文字会覆盖该位置，`STOP` 图标暂时隐藏。
- 图标隐藏不代表 `STOP` 状态被修改；周期文字清空后，图标会按原状态再次显示。
- 周期文字与 STOP 使用固定宽度槽位淡入淡出切换，不会挤动时间、重置或保存等后续控件。
- 备忘录列表底部左侧的 `STOP` 不与周期文字重叠，因此列表状态下会始终显示；右侧的返回按钮保持在底部右侧。

## 执行时间

- “仅一次”任务如果选择了过去的日期或时间，保存时会自动改为当前本地分钟并继续创建，不会显示“执行时间需要晚于当前时间”。确认框会展示改正后的执行时间。
- 工作日、自然日、每小时、每 15 分钟、每 30 分钟等周期任务仍要求执行时间晚于当前时间；过去时间会保留原有错误提示且不会提交。

## 开启后的结果

- 本地备忘录仍会保存元数据，并在到期时生成任务明细，周期任务后续也会继续生成明细。
- 开启期间，当前 Agent 到期的本地备忘录任务会保持“待执行”；不会创建会话，也不会调用模型或上游服务。
- STOP 不修改任务元数据、任务明细、任务状态或既有 `chat_id`。关闭后，STOP 期间积压的待执行任务会被补偿扫描。
- STOP 影响当前 Agent 已有和之后创建的本地备忘录任务，不需要逐条修改备忘录。
- 飞书、邮件和连接类任务不受该开关影响，仍按原流程处理。

## 多浏览器同步与节能

- 页面打开、切换 Agent 或从后台回到前台时会立即同步当前 Agent 的 STOP 状态。
- 前台常规模式每 15 秒同步一次；开启“节能”后改为每 30 秒一次。页面在后台、没有选择 Agent 或已有同步请求时不会重复轮询。
- 多个浏览器同时操作同一 Agent 时，以服务端最后一次成功保存的状态为准；下一轮同步后，各页面会显示同一状态。
