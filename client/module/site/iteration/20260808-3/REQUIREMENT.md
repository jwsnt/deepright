### 需求介绍
+ 用户在会话列表确认删除会话时，必须立刻终止该会话尚未结束的请求，并同步移除该会话全部待执行消息，避免删除后仍有前端不可见的普通会话请求或待发送消息继续执行。
+ 覆盖正在预发送、已建立 SSE 连接、恢复轮询和正在自动出队的请求；删除与 SSE 完成、恢复、待发送队列自动出队或插入消息同步同时发生时，以删除为准，晚到的异步结果不得恢复会话、创建队列或发起新的请求。
+ 覆盖浏览器内存中的待发送队列，以及服务端 `message_insert` 中该会话尚未终态的插入消息；服务端插入消息需按现有接口查询后物理删除。
+ 删除操作不等待服务端响应：会话立即从列表和本地持久化数据中移除，当前 SSE 读取立即中止，预发送计时器和相关轮询立即停止。
+ 删除后立即首次调用 `POST /api/cancel?chat=<chatId>` 取消服务端当前请求；若未确认取消成功，最多再尝试两次，每次间隔 `15` 秒，即总计最多 `3` 次。任一次确认成功即停止重试。
+ 三次取消均未成功时，本次取消视为失败，不再在后台持续重试；页面需要明确提示“会话已删除，但取消请求失败，后端可能仍在处理”。待发送/插入消息清理失败时也需要明确提示。

### 编写代码
+ 复用现有 `AbortController`、`/api/cancel`、会话恢复轮询、待发送队列和 `message_insert` 接口，不新增后端接口或第二套请求状态。
+ 为删除中的会话建立仅限当前页面生命周期的阻断标记；所有会导致发送、恢复、重新建队或渲染流式结果的异步入口都必须先检查该标记。
+ 取消重试仅用于确认当前 SSE 请求取消；不得将失败状态写成可在刷新后继续重试的会话状态。
+ 代码简洁，避免重复的取消、队列清理和错误提示逻辑。
