### 需求介绍
+ CLI 子面板在聊天 SSE 正常存活期间仅消费聊天 SSE 中 `biz=cli` 且 `workflow=sub` 的实时回显；不得为 CLI 子面板启动、维持或在 SSE 正常完成后追加 `/api/restore` 轮询。
+ 切换到仍有正常 SSE 的会话时，只能从该会话已保存在页面内存中的实时状态重绘 CLI 子面板；切换会话本身不得触发 CLI 恢复请求。
+ 在页面刷新、重新打开会话或其他需要通过 `/api/restore` 重建会话的场景，聊天 SSE 的非 `cli/sub` A 数据必须填充居中对话；`cli/sub` 不得进入居中 SSE 或思考片段。CLI 子面板只可依据恢复响应中的 `cli/get` 与 `cli/pub` 记录重建，避免同一任务重复显示。
+ 恢复 A 记录的展示路由必须与实时 SSE 一致，只是数据来源改为 `/api/restore`：逐个 SSE 数据包判断，`biz=cli && workflow=sub` 只归 CLI 子面板链路，`workflow=__sub` 等其它包继续归居中对话/思考片段链路；两类内容不得混入同一渲染状态，也不得同时展示。
+ 恢复时，`cli/get` 的任务标识为 `chatId + tid`。前端必须从任务原始内容读取 `subOps.echo`：只有其值严格为 `false` 时，该任务及其对应 `cli/pub` 不显示在 CLI 子面板；字段缺失、为空或为 `true` 时正常显示。
+ `echo=false` 仅控制恢复态 CLI 子面板的展示。它不得取消任务执行、阻止 `cli/pub` 回传或修改服务端日志；前端仍须按任务标识记录并跨恢复批次保留该任务的展示决定，处理对应 `cli/pub` 但不渲染气泡。
+ 每条 `cli/pub` 必须仅按相同的 `chatId + tid` 更新对应 `cli/get` 的面板项。不得以“最近一条执行中命令”作为回退匹配，也不得跨会话补充输出。找不到同键 `cli/get` 的 `cli/pub` 不得显示到任何其他命令。
+ 手动 CMD 面板历史不属于 `cli/get` / `cli/pub` 恢复链路，不受 `subOps.echo` 过滤影响。

### 编写代码
+ SSE 与恢复态的 CLI 数据源必须明确分流；不得以命令文本、时间窗口或“最近未完成项”等启发式规则去重或关联。
+ 任务回显状态与 `cli/pub` 的关联必须使用 `chatId + tid`，并保持重复 restore 时幂等。
+ 代码应保持简洁，并复用既有 SSE 解析、CLI 气泡渲染与恢复游标能力；不得新增外部依赖。
