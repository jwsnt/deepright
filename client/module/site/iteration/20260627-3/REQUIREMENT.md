### 需求介绍
+ 居中对话框中的 `http/https` URL 在点击 `预览` 后，不再使用原文件编辑器浮层，而是切换右侧 Sidebar 为独立 iframe 预览区
    + 右侧 iframe 预览区需要整体替换原右侧内容区，iframe 展示高度吃满右侧可用区域，不能因为切换动画或父容器布局导致底部被抬高、留白或整体错位
    + 预览区左上角的切换按钮需要悬浮在居中对话框与右侧 Sidebar 的交界处，与居中会话框左上角 `复制会话` 按钮保持同一水平线；按钮始终完整可见，不能被右侧栏裁切或遮挡
    + 切换按钮点击后，需要恢复为原右侧布局；打开 iframe 与切回原布局时，都要保留毛玻璃模糊的淡入淡出效果，但不能影响整体布局高度和滚动定位
    + 当 iframe 对应站点为大型页面、在线文档或网络文档，导致实际内容仍在加载而页面先出现白屏时，右侧预览区需要展示覆盖在 iframe 上方的毛玻璃 Loading 态；该 Loading 只允许覆盖展示层，不能额外占位、抬高布局或压缩 iframe 可用高度
    + iframe 的毛玻璃效果需要覆盖三类状态：打开时淡入、关闭时淡出、加载等待时的 Loading 毛玻璃；三类效果都要与右侧现有布局解耦，不能造成边栏高度、底部空间或滚动位置抖动
+ 右侧 iframe 预览状态需要与当前 `Agent + Chat` 绑定
    + 当前会话打开过的 iframe 预览 URL、开关状态和展示信息需要写入该会话自身状态中
    + 切换到其他会话后，需要按目标会话自己的预览状态判断是否展示 iframe，不能把上一个会话的预览状态串过去
    + 如果当前会话没有打开 URL 预览，则右侧栏保持原布局
    + 当 SSE 流式响应过程中识别到 `http/https` URL，且该 URL 通过右侧 iframe 的可加载条件检查后，需要自动打开当前会话绑定的右侧 iframe 预览
    + 如果同一轮 SSE 响应过程中依次识别出多个 URL，则最终应以“最后一个通过加载条件检查的 URL”为准展示右侧 iframe；未通过检查的 URL 不能覆盖已通过的展示结果
+ 对于右侧 iframe 预览失败场景，需要自动回退并给出原因提示
    + 当目标站点无法访问、返回 `404/5xx`、明确通过 `X-Frame-Options` 或 `Content-Security-Policy frame-ancestors` 禁止 iframe 嵌入时，需要自动关闭右侧 iframe，并切换回原右侧布局
    + 如果前端实际加载阶段超时、加载错误或最终没有成功进入可展示状态，也需要自动关闭 iframe 并回退原布局
    + 上述失败原因都需要复用左侧虚拟文件系统 Tips 位置进行提示，文案需要区分“站点不可访问”和“站点禁止 iframe 预览”等不同原因，避免只显示浏览器原生报错页
+ 右侧 iframe 预览的实现需要继续遵守现有 site 前端收口方式
    + 在 `../../index.html` 内按现有 HTML / CSS / JavaScript 组织实现，不引入新的构建流程或前端依赖
    + 可以补充同源探测接口或最小必要的后端辅助逻辑，但最终行为必须对 `site` 前端透明，且不能破坏现有 `integration / proxy` 路由结构
    + 预览失败时的自动回退、按钮展示、会话切换恢复和淡入淡出动画都需要与现有右侧栏、VFS Tips、对话切换和主题系统兼容
    + 右侧 iframe 的打开/关闭过渡与加载中 Loading 毛玻璃效果，都必须兼容当前 `节能开关 / low-power-rendering` 机制；节能模式下允许保留同语义视觉反馈，但必须自动降级为更轻量的 blur、阴影和动画时长，避免沿用高开销连续动画
