### 任务元数据
+ 任务元数据由以下元素组成：
    + ID：自增
    + 使用周期：int，0=仅一次、1=、工作日、2=自然日、3=每小时、4=每15分钟、5=每30分钟
    + 原始时间：string，yyyy-MM-dd hh:mm格式表示的时间
    + 绑定的AgentId：string
    + 选择的模型：string
    + 是否深度思考：boolean
    + Cron表达式：string
    + 任务的内容：string
    + response_schema: string，可为空（""）
        + > 新增自 iteration/20260518-1/REQUIREMENT.md
    + router_disable: boolean
        + 由任务元数据周期性创建的任务明细继承任务元数据的 router_disable
        + 一次性任务明细在创建时可选的指定 router_disable
        + router_disable 不可为空，默认为 true（关闭）
        + > 新增自 iteration/20260524-1/REQUIREMENT.md
+ 禁止存储模型的Token（密钥），需要执行时由使用方动态传递
    + > 引用自 iteration/20260502-4/REQUIREMENT.md
###### Cron表达式
+ 如果请求中直接指定了Cron表达式则直接使用，否则需要从使用周期和原始时间计算出表达式
    + 仅一次：指定时间的表达式
    + 自然日：在每天的指定时间重复执行，包括指定时间本身
    + 工作日：在每周1到5的指定时间重复执行，包括指定时间本身
### 任务明细
+ 在提交任务元数据及每分钟执行一次的周期创建检查（Job）需要将后5天需要创建任务元数据拆解为任务明细
    + 如果直接指定的表达式，则提交时不需要立即创建，在每分钟执行一次的周期中创建
+ 任务明细由以下元素组成：
    + ID：自增
    + META_ID：任务元数据ID
    + 执行时间：时间戳
    + 绑定的AgentId：string
    + CHAT_ID：string，可以为空
        + > 引用自 iteration/20260502-1/REQUIREMENT.md
    + 选择的模型：string
    + 是否深度思考：boolean
    + 任务的内容：string
    + 任务明细状态（是否已启动）：int，0未启动、1已启动、2无需启动、3已完成
    + 类型（type）：string，默认为cron
        + cron：备忘录任务（由cron创建的周期任务或一次性任务）
        + connect：connect模块创建的任务，值为具体模块名（如飞书）
        + > 引用自 iteration/20260502-6/REQUIREMENT.md
    + response_schema: string，可为空（""）
        + 由任务元数据周期性创建的任务明细继承任务元数据的 response_schema；一次性任务明细在创建时可选的指定 response_schema
        +     + > 引用自 iteration/20260502-4/REQUIREMENT.md
+ 索引：
    + 索引1：AgentID + 执行时间 + 任务明细状态
    + 索引2：执行时间 + 任务明细状态
    + 索引3：AgentID + CHAT_ID + 执行时间 + 类型
        + > 引用自 iteration/20260502-6/REQUIREMENT.md
+ 案例
    元数据是 2026年4月27日 12点10分 仅执行一次，则对应的Cron表达式为0 10 12 27 4 ? 2026，提交时在明细表中生成对应2026年4月27日12点10分的任务明细
    元数据是 2026年4月27日 12点10分 自然日，则对应的Cron表达式为0 10 12 * * ?，提交时创建任务，同时在每分钟执行的周期创建检查（Job）为后5天创建任务明细
    元数据时 2026年4月27日 12点10分 工作日，则对应的Cron表达式为10 12 * * 1-5，创建规则同上
+ 周期创建检查（Job）在创建时需要先检查对应任务元数据在指定时间的任务是否已经创建（META_ID+执行时间），如果已经存在则不要重复创建
+ 周期创建检查（Job）将任务元数据拆分为任务明细时需要继承 router_disable
    + > 新增自 iteration/20260524-1/REQUIREMENT.md

### 链路整理
+ 收到任务元数据
+ 立即创建首个任务明细
+ 周期性创建后5天任务明细，如果已存在则跳过

### 定时器启动
+ 启动应用时即启动定时器，每分钟执行一次，将后5天非一次性的任务元数据拆分为任务明细
+ 如果已经存在则不要重复创建
+ 记录最后执行时间
+ > 引用自 iteration/20260428-1/REQUIREMENT.md

### CLI命令
+ 通过CLI创建任务元数据需要提供以下数据：
    + 使用周期：int，0=仅一次、1=工作日、2=自然日、3=每小时、4=每15分钟、5=每30分钟
    + 原始时间：string，yyyy-MM-dd hh:mm格式表示的时间
    + 绑定的AgentId：string
    + 会话ID（CHAT_ID）：string
    + 选择的模型：string
    + 是否深度思考：boolean
    + Cron表达式：string
    + 任务的内容：string
+ 创建时需要检查数据：指定Agent必须存在，指定模型是否在Proxy已注册（填写Token），及其他参数必须符合格式和要求
+ 模型Token由调用时动态传递，不存入数据库
+ CLI案例：
    ```
    ./integration cron create --content "每15分钟检查一次上游接口健康" --model "OpenAI" --thinking true --rawTime "2026-05-03 10:00" --cycle 4 --chatId "chat-001"
    ```
+ > 引用自 iteration/20260502-3/REQUIREMENT.md

### 编写代码
+ 以Golang编写以上代码，要求：
    + 新建高频周期任务（每小时/每15分钟/每30分钟）时，需要和工作日/自然日一样在创建后立即生成后5天内的所有任务明细，不能仅依赖每分钟的定时器延迟创建
    + 每分钟的定时器仍需周期检查所有非一次性任务（包括高频周期），为后续5天补充创建新的任务明细，确保持续运行不遗漏
    + 使用文件名为data的sqlite存储，并使用连接池，避免每次都新建连接
    + 代码简洁，包体积越小越好
    + 能用开源包的就用开源包

### 验证测试
``` 测试1，提交任务元数据：
+ 指定周期：仅一次，0
+ 原始时间：2026年4月30日 12点10分，2026-04-30 12:10
+ AgentId：A
+ 模型：OpenAI
+ 深度思考：true
+ 任务的内容：查看天气
```
+ 对应Cron：0 10 12 30 4 ? 2026
+ 立即为2026年4月30日 12点10分创建一个任务

``` 测试2，提交任务元数据：
+ 指定周期：工作日，1
+ 原始时间：2026年4月30日 12点10分，2026-04-30 12:10
+ AgentId：A
+ 模型：OpenAI
+ 深度思考：true
+ 任务的内容：查看天气
```
+ 对应Cron：0 10 12 30 4 1-5
+ 立即为含2026年4月30日在内的后5天 每天12点10分创建一个任务明细
+ 在2026年4月30日 12点11分发现任务已经创建，跳过
+ 在5天后 12点10分发现任务再创建后5天的任务明细

``` 测试3，提交任务元数据：
+ 指定周期：每个自然日，2
+ 原始时间：2026年4月30日 12点10分，2026-04-30 12:10
+ AgentId：A
+ 模型：OpenAI
+ 深度思考：true
+ 任务的内容：查看天气
```
+ 对应Cron：0 10 12 30 4 ?
+ 立即为含2026年4月30日在内的后5天 每天12点10分创建3个任务明细（去掉2天周末）
+ 在2026年4月30日 12点11分发现任务已经创建，跳过
+ 在5天后 12点10分发现任务再创建后4天的任务明细（去掉1天周末）

``` 测试4，提交任务元数据：
+ 指定Cron表达式：10 12 * * 1-5
+ AgentId：A
+ 模型：OpenAI
+ 深度思考：true
+ 任务的内容：查看天气
```
+ 对应Cron：10 12 * * 1-5，表示为：工作日的 12点10分
+ 立即为含当天在内的后5天 每天12点10分创建不超过5个任务明细（去掉周末）
+ 在1分钟后发现任务已经创建，跳过
+ 在5天后发现任务再创建后5天的任务明细（去掉周末）
