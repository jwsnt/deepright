### 需求介绍
+ Windows WSL 安装流程中的 apt 安装必须具备超时与 fallback 能力，避免单个软件包安装卡死而中断后续安装。
+ 默认超时时间为 10 分钟；超时粒度为单个软件包、单个安装源的一次尝试。
+ `apt-get update` 同样必须受 10 分钟超时保护；超时后记录失败并继续后续软件包安装。
+ 基础软件包必须逐个安装，包含：`git`、`python3`、`python3-pip`、`curl`、`build-essential`、`bubblewrap`、`xdg-utils`。
    + 每个软件包当前仅使用 Ubuntu apt 源。
    + 某次安装返回非 0 或超过 10 分钟时，视为该软件包在该源失败；记录红色日志后继续下一个软件包，不得阻塞整个安装流程。
+ `nodejs` 必须按以下顺序逐源尝试安装：
    1. NodeSource 的 Node.js 20.x 安装源。
    2. Ubuntu apt 源安装 `nodejs` 与 `npm`。
    + 每个源的单次尝试均最多 10 分钟；前一源超时或失败后，必须立即尝试下一源。
    + 两个源均失败或超时后，记录红色日志并继续后续安装流程。
+ 技术实现要求：
    + 在 WSL 内为每条 apt/NodeSource 安装命令增加 10 分钟超时控制；超时后必须结束该命令及其仍在运行的子进程，避免遗留 apt、dpkg 或安装脚本继续占用锁。
    + 将安装结果区分为成功、命令失败、超时三类；日志必须包含软件包、安装源、超时阈值和“将尝试 fallback”或“所有源均失败”的结果。
    + 存在 fallback 的首次失败或超时，须写入安装日志和控制台黄色日志后继续尝试 fallback；无 fallback 或全部源失败时，须同时写入安装日志和控制台红色日志，且不得调用终止安装脚本的逻辑。
    + 软件包安装结束后仍执行现有工具校验；缺失工具只作为可见的安装结果，不影响后续应用文件复制、启动脚本生成及 Integration 启动。
