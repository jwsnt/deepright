### 需求介绍
+ Integration 启动时必须从运行时主应用 `config/config.json` 读取 `temp` 配置；配置值不得在源码、构建脚本或发布产物中固化。一次启动中配置读取一次，修改配置后重启 Integration 生效。
+ `temp` 必须是对象，且 `clear`、`pack`、`scan` 都必须是正整数，单位为小时：
```json
{
  "temp": {
    "clear": 168,
    "pack": 168,
    "scan": 2
  }
}
```
+ 配置不能读取或字段非法时，必须记录明确日志且不执行本轮临时文件整理；不得以源码默认值替代配置值。
+ 临时文件整理必须在独立 goroutine 中运行：Integration 启动后立即执行一次，之后每隔 `temp.scan` 小时执行；任何扫描、移动、删除或配置错误都不得阻塞 HTTP 服务启动、请求处理或定时任务。
+ 每轮扫描所有有效 Agent 工作目录的 `tmp/`。`tmp/bak/` 是归档目录，缺失时仅在确有需要归档时创建，且不得再次作为归档源扫描。
+ 对 `tmp/` 下的一级文件或目录逐项处理。一级目录必须仅在其递归子树中的任一文件均已超过 `temp.pack` 小时未修改时整体归档；只要任一文件仍在期限内，整个一级目录不得移动。空目录按目录自身修改时间判断。根目录的一级文件按自身修改时间判断。
+ 归档目标为 `tmp/bak/<原相对路径>`，必须保留原有目录结构。目标不存在时可直接移动；目标目录存在时递归合并。目标中存在同名文件、或同名目标类型不一致时，必须保留目标、跳过源项并保留源项等待后续扫描；不得覆盖或重命名任何文件。
+ 对 `tmp/bak/` 下的一级文件或目录逐项清理。只有一级目录递归子树中所有文件均已超过 `temp.clear` 小时未修改时，才删除整个目录；一级文件按自身修改时间删除；空目录按目录自身修改时间删除。
+ `pack` 归档、归档冲突跳过、`clear` 删除及每个 Agent 的处理错误都必须写入 Integration 日志，日志至少包含操作类型、Agent ID、源路径或目标路径及原因。

### 编写代码
+ 以 Go 实现配置校验、扫描、递归合并和异步调度；复用现有 Integration 配置路径、Agent 根目录和生命周期 context，不新增依赖。
+ 为配置解析、按 `pack` 归档、递归合并时的同名跳过、按 `clear` 整体删除、`bak` 排除和 context 取消补充自动化测试。
