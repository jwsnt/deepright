### 需求介绍
+ 右侧工作区首次加载或切换 Agent 时，页面不得因为扫描所有 Agent 的 `skills` 目录而长时间停留在“正在加载工作区”。
+ 工作区路径解析、文件列表加载与请求转发的技能元数据必须解耦；优化工作区加载不得降低普通会话、备忘录任务或 Connect 任务的技能提交正确性。

### 工作区快速加载
+ `GET /api/workspace?agentId=...` 只负责校验目标 Agent 并返回其工作区绝对路径：
    + 必须只接受 Agent 根目录的直接子目录；拒绝空值、路径分隔符、`.`、`..`、符号链接逃逸及不存在的 Agent。
    + 不得调用 `getAgentOutput`、`getAgentOutputForChat`、`agentcore.GetOutputForApp` 或任何会遍历/解析 `skills` 的元数据聚合逻辑。
    + 保持既有响应语义：成功返回 `text/plain` 工作区路径；无效 Agent 返回非 2xx。
+ 前端已保存当前 Agent 时，应先直接请求 `/api/workspace`，不得为常规工作区加载额外等待 `/api/agentId`。
+ 仅当没有已保存 Agent，或直接请求因 Agent 名大小写/历史名称不匹配失败时，才请求 `/api/agentId` 选择或修正 Agent 后重试一次。
+ 已解析过的工作区路径可在当前页面生命周期内按 Agent 缓存；切换回已访问 Agent 时不得重复请求 Agent 列表或工作区路径。
+ 页面仍须保留递增请求序号和过期响应丢弃逻辑，避免快速切换 Agent 时旧响应覆盖当前工作区。

### 技能元数据与自动任务
+ 普通 `/v1/chat/completions` 转发、备忘录定时任务、Connect 触发任务仍须在实际构造上游请求时通过既有 Agent 元数据链路获取技能；不得依赖浏览器是否打开过工作区。
+ `agents[].skills` 继续在转发与离线任务执行当刻从当前磁盘状态刷新，确保新增、删除或修改技能后的下一次请求带上最新技能。
+ 不得将工作区快速路径返回的目录或页面缓存作为转发技能元数据的来源；两者只共享 Agent 身份，不共享技能快照。

### 验证
+ 覆盖工作区解析测试：合法直接子目录成功、Agent 不存在失败、空值/路径穿越/符号链接逃逸失败。
+ 覆盖页面请求策略：已有 Agent 直接请求工作区；仅在直接请求失败或没有当前 Agent 时回退查询 Agent 列表；缓存命中时不重复请求。
+ 覆盖普通转发和离线备忘录执行：不打开页面仍能在执行时获得并提交当前 Agent 的技能元数据。
