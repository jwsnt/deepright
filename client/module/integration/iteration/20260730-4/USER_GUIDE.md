# 定时备忘录 SSE 读取超时与失败状态使用手册

在主应用随包发布的静态配置 `config/config.json` 中，使用 `http.timeout.read` 配置定时备忘录的 SSE 正文读取空闲超时，单位为秒：

```json
"http": {
  "heartbeat": 3,
  "debug": false,
  "timeout": {
    "read": 120
  }
}
```

该值必须是可表示为 `time.Duration` 的正整数秒。配置缺失、不是整数、为零、为负数或超过可表示范围时，Integration 会在日志中记录 `http.timeout.read` 的配置错误，并回退为 `120` 秒；不会因这一个可选配置项而拒绝启动。

这是 SSE 的读取空闲超时，不是请求总时长：响应体每收到任意字节都会重新开始计时。只要服务端持续输出，定时备忘录可以持续运行；连续无数据达到配置值时，Integration 会关闭该 SSE 响应并把本次任务收束为失败。

以下情况都会将 `task_detail.started` 更新为 `4`（失败）：请求创建失败、转发请求失败、读取空闲超时、其它读取错误、上游非 2xx、上游业务异常，或响应结束却没有 `data: [DONE]`。已经收到的原始 SSE 数据会保留在聊天日志中，随后追加现有的 `abnormal` 日志“连接已中断，请重试”，因此会话恢复可以显示明确的结束状态。

状态 `4` 是终态，不会再参与 `started = 0` 的定时扫描，也不会自动重试，避免失败任务持续占用后续执行队列。备忘录时间线、详情和查询中会显示“失败”；如需重试，可由用户明确发起一次新的运行任务。已有状态 `2`（无需启动）和 `3`（已完成）不变。

本项不改变 `/restore` 的接口、参数、返回结构或前端恢复协议。它只向既有聊天日志写入 `abnormal` 终态，由现有恢复流程继续消费；普通对话、心跳和其它 HTTP 客户端也不会使用此读取超时。
