### 需求介绍
+ Integration 新增同源 `POST /api/agent/audio?agentId=<agentId>&path=<relativePath>`，仅用于保存 Site 新建流程录制的 WAV。请求体为 JSON，`content` 是 WAV 二进制数据的标准 Base64 编码；成功响应继续返回统一的 `status`、`agentId`、相对 `path` 和工作区内 `savedAs` 路径。
+ 接口只接受当前 Agent 工作区相对 `audios/<文件名>.wav` 目标路径；`audios` 不存在时安全创建。必须拒绝缺失 Agent 或路径、`audios` 以外的目录、绝对路径、`~`、`.` / `..` 路径逃逸、目录目标、跨 Agent 目标以及符号链接导致的工作区外写入；不得暴露任意本机路径写入能力。
+ 目标文件必须以不区分大小写的 `.wav` 结尾。服务端不得替用户接受或转换 `.mp3`、`.webm`、无后缀等其它名称；前端负责无后缀补齐，服务端负责最终校验。
+ 服务端必须将 Base64 严格解码，并校验最小 WAV 容器结构：RIFF 标识、WAVE 标识、`fmt ` 区块和非空 `data` 区块均需存在且长度不得越界。无效、截断或非 WAV 内容必须拒绝，不得创建文件。
+ 录音保存仅在最终提交时落盘，接口不得预先创建空文件。若同名目标已经存在，必须返回可展示的冲突错误，不覆盖、删除或改名既有文件。写入应先落到同一受限工作区内的临时文件，完成后再原子创建最终新文件；写入失败不得留下最终文件或工作区外临时文件。
+ 接口不做编解码、重采样、降噪、格式转换或媒体分析，不引入 FFmpeg 与外部依赖；它只在通过安全与格式校验后原样持久化浏览器生成的高保真 PCM WAV。
