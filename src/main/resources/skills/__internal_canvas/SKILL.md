### 参考资料与文件范围
+ 开始前先阅读`#workspace/app/CANVAS.md`，并以其当前格式、约束和兼容规则为准
+ 需要通过Integration读取或写入画布时，再阅读`#workspace/app/API.md`，只使用其中明确记录的接口
+ `.canvas`是当前Agent工作区内的UTF-8 JSON文件，优先使用用户指定的相对路径，未指定时使用简短、语义清晰的`.canvas`文件名。不要擅自覆盖、移动或删除无关文件
+ 新建或保存时显式使用`.canvas`后缀，画布可位于工作区的任意受限相对路径，`canvas/`仅用于编辑器导出的PNG/PDF，不是`.canvas`文档或图片的固定目录
+ 修改已有画布前，先读取并理解现有JSON，保留用户未要求修改的节点、连线、标题和视口

### 制作流程
+ 1. 明确画布主题、读者、核心对象、对象间关系与阅读顺序。对象或关系不明确时，先向用户澄清，不把猜测写成事实
+ 2. 选择布局：流程和时间线通常从左到右，层级和拆解通常从上到下，为节点预留空间，避免重叠
+ 3. 为每个需要讨论、移动、关联或复用的概念创建独立节点，为每条有业务含义的关系创建独立连线，并`note` 写动词、条件或机制
+ 4. 生成完整、可编辑的`.canvas` JSON。不要以 HTML、Markdown、图片文件目录或页面交互代替画布内容
+ 5. 保存前校验格式和引用，写入或读取时使用受限的工作区接口，不启动额外服务，也不假设未记录的接口

### JSON格式要求
+ 顶层始终写入`version: 2`、`title`、`viewport`、`nodes`和`edges`，`viewport`包含有限数字的`x`、`y`与范围为`0.2–3`的`scale`
+ 每个节点必须有唯一且非空的`id`、合法 `type`、有限的`x`/`y`、`width`和`height`，宽度范围为`100–900`，高度范围为`42–900`
+ 使用`card`承载核心概念，使用`text`标记分区标题、图例或注释，正式业务画布通常不输出`guide`，`card`、`guide`和`text`使用`content`，可选`color`只能是`#RRGGBB`
+ 图片节点只能使用`type: "image"`和以`data:image/`开头的Base64 Data URL `src`，不要写入本机路径、相对路径、HTTP URL、`file://` URL、`content`或`color`
+ 每条边必须有唯一`id`，其`from`和`to`必须引用两个不同且存在的节点，`arrow`只能为`forward`、`reverse`或`both`，并始终写入`note`（没有备注时使用空字符串）
+ 不输出格式不支持的属性，例如字体、边框、旋转、分组、泳道容器、节点层级、连线颜色/线型/锚点、Markdown/HTML、外部图片、音视频或脚本逻辑

### API与数据处理
+ 使用`POST /api/edit`（或对应`integration api edit`）保存UTF-8 JSON，使用`GET /api/raw`（或对应 CLI）读取原文后解码为 UTF-8 JSON
+ 只向当前Agent工作区写入经校验的相对路径，不使用任意本机路径读写能力
+ 不在画布内容、文件路径或请求中写入Token、Cookie、密码或其他凭据
+ 仅当图片确实有助于理解时嵌入图片，并控制Base64 体积，图片随`.canvas`JSON 保存，不创建独立图片资源引用

### 验证与完成标准
+ 保存前验证JSON可解析，顶层五个字段齐全，`version`为`2`
+ 验证节点和边的ID唯一、边端点有效且非自环、箭头和颜色值合法、尺寸与缩放在允许范围内，图片仅使用合法Data URL
+ 验证关键节点不重叠，连线方向与`note`能表达用户所需的关系，且没有语义重复的边
+ 完成后反馈`.canvas`文件路径、画布表达的主题与主要关系，以及尚未验证或受运行环境限制的部分（如有）
