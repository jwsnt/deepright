---
name: __internal_creator
description: 当用户明确要求创建、沉淀、提取、整理或完善技能（Skill）时，创建或更新对应目录下的SKILL.md，补齐frontmatter、使用说明、约束、示例和可选脚本引用
---

### 适用场景
+ 用户明确要求创建一个新技能
+ 用户希望把一段可复用流程沉淀为技能
+ 用户要求补全、重写、整理或优化已有SKILL.md
+ 用户提供了一组操作步骤，希望整理成后续可复用的技能说明

### 不适用场景
+ 普通文案润色，但不需要形成技能
+ 一次性脚本、页面、配置生成，但不需要复用为技能
+ 与技能目录、SKILL.md结构无关的临时说明整理

### 输出要求
+ 在目标技能目录中创建或更新`SKILL.md`
+ frontmatter至少包含：
    + `name`：技能唯一标识，使用小写字母和连字符
    + `description`：完整描述技能做什么、什么时候使用
+ 正文应优先包含：
    + 技能用途
    + 使用场景
    + 执行步骤或约束
    + 真实示例
+ `Script`、资源路径、附加文件为可选项，仅在确实需要时添加

### 编写原则
+ 描述要清楚说明“做什么”与“什么时候用”，避免过短或过泛
+ 内容优先写可执行约束，而不是空泛介绍
+ 示例优先使用真实用户请求，不要只写占位词
+ 如果仓库内已有相近技能，优先保持同样的结构和语言风格
+ 如果是更新已有技能，保留原有有效内容，仅补全缺失部分并消除冲突

### 制作步骤
+ 确认技能名称、用途、触发场景和预期产物
+ 如已有同名技能，先基于原内容补充或重构，不要盲目重写
+ 先写frontmatter，再补正文结构
+ 若技能依赖固定命令、脚本、目录或资源路径，写明调用方式
+ 若某部分只是可选能力，明确标注为可选，而不是写成必填

### 基本模板
```md
---
name: my-skill-name
description: 当用户需要[解决的问题]或希望[完成的任务]时，使用该技能执行[关键动作]，并产出[结果]
---

### 适用场景
+ 场景1
+ 场景2

### 输出要求
+ 输出物1
+ 输出物2

### 执行步骤
+ 步骤1
+ 步骤2
+ 步骤3

### 示例
+ 用户说：帮我把这个流程整理成一个可复用技能
+ 用户说：为这个功能创建一个新的Skill说明文件

### 约束
+ 约束1
+ 约束2

### Script
+ 可选脚本或资源路径1
+ 可选脚本或资源路径2
```
