#init
### 更新准则
+ 逐次读取git：`#git` 在`#lastUpdate`至`#limitUpdate`内每个COMMIT。单次小于5个COMMIT，仅取摘要
+ 每页WIKI记录上下文摘要、关联Commit。实体词间交叉引用，高频关联实体词抽象公共概念作为新实体词聚合
+ 参考www.wikipedia.org的交叉引用与层级组织方式，以Markdown为载体编写高频实体词WIKI
+ 忽略绝对路径、临时文件路径和URL，核心页面/组件的相对文件名可作为实体词标识保留
+ 数据价值判定（按优先级应用）：
    + P0：必须保留：用户特异性的行为红线、交互偏好、主观审美量化、决策历史（含放弃路线）、心智感悟，无论格式为何
    + P1：判定剔除：匹配以下模式且非用户特异性的内容直接丢弃：
        + 纯平台知识、纯操作步骤、寒暄表态、重复已知信息
        + 以"XX是..."或"遇到XX要"开头的通识/指令句
    + P2：敏感过滤：密钥、Token、密码等凭证一律忽略
+ 忽略应属于USER.md/SOUL.md的知识：
    + SOUL.md：AI核心人格与通用行为准则（如：不阿谀奉承）
    + USER.md：用户身份背景与宏观偏好（时区、项目方向）
    + 知识库：具体技术项目、特定美学风格的量化参数、技术决策历史（含减法）、用户心智模型与人生感悟
+ 规则冲突时优先级：核心铁律（个性化资产）> 行为红线 > 价值过滤器 > 工具使用规范
### 最少读写
+ 禁止全量读取知识库，先从`index.html`或文件名推测是否相关再读取更新，都不相关则新建
### 工具使用
+ 使用工具`[cli]`更新
### 输出规范
+ 每次知识提交后输出：变更文件列表 + 每文件净增/删/改的实体词数量 + 未更新项及阻断原因（单行）
